# 业务监测 MQ 消息监测接入

## Context

业务监测页面已具备完整 XXL-JOB 链路（配置 CRUD → Collector 拼 SQL → MCP 数据库目标只读查询 → dashboard/详情/定时告警），MQ 模块目前是骨架：后端 4 处抛"MQ 监测…下一步接入"，前端 MQ 标签页为空占位。

MQ 消息真实来源是各子应用库的 `message_sender_log` / `message_receiver_log`（RabbitMQ，已在 db-prod 核验约 28 个 schema 分布）。已确认决策：
1. **自动发现全部库**：监测配置不填库名，运行时按业务线+环境解析 MCP 数据库目标后查 `information_schema` 发现所有含 `message_sender_log` 的 schema（守卫已放行该查询，schema 名做 `[A-Za-z0-9_]+` 校验）。
2. **口径**：发送失败 `status=3`；发送积压 `status IN (1,2)` 且 `create_time` 早于 `now - N 分钟`（复用 `mq_lag_threshold`，默认 30）；接收失败 `status=0` 或 `deal_business_success=0`。
3. **复用现有空字段，无 DDL**：`mq_topic`→关注交换机(exchange，逗号分隔)、`mq_consumer_group`→关注队列(queue，逗号分隔)、`mq_lag_threshold`→积压阈值分钟。`OpsMonitorSchemaInitializer` 无需改动。
4. **本期含定时告警**（镜像 `XxlJobFailureMonitorJob`）。

状态语义（来自业务公共组件 lease-mq/thctay-mq 枚举，已核验）：sender status 1=未发送 2=发送中 3=失败 4=成功；receiver status 0=签收失败 1=签收成功。

## 后端实施（workhub-server）

**workhub-model 新增**（`model/ops/`，record 风格对齐现有）：
- `MqDatabaseStatsResponse`：databaseName + sender 总/成功/失败/积压 + receiver 总/成功/失败 + latestActivityAt
- `MqDashboardResponse`：监测元信息 + status/message/checkedAt + 库数量与汇总计数 + `databaseStats` 列表 + 失败/积压消息计数与分页 + `messages` 列表
- `MqMessageResponse`：databaseName、logType(SENDER/RECEIVER)、logId、messageId、exchange、routingKey、queue、status、failureType/failureTypeName（SEND_FAILED/SEND_STUCK/RECEIVE_ACK_FAILED/RECEIVE_BUSINESS_FAILED）、retryCount、autoRetry、dealBusinessSuccess、occurredAt、errorMsg(截断500)
- `MqMessagePageResponse`：分页明细 + `MqQueryEvidence`（同形 `XxlJobQueryEvidence`，Definition 换为 discoveredSchemas）

**workhub-service**：
- 新增 `MqMonitorCollector`（镜像 `XxlJobMonitorCollector`，复用 `XxlJobDatabaseQueryClient`）：
  - `discoverDatabases`：`SELECT table_schema FROM information_schema.tables WHERE table_name = 'message_sender_log'`
  - 统计：单条 UNION ALL 聚合 SQL（每库 sender/receiver 计数，窗口默认 7 天；状态判定用 `SUM(CASE WHEN…)`，别名避开危险关键字，日期字面量拼接同 xxljob 模式）
  - 明细：统计 + 分页两条语句一批（`runVerifiedBatch`），镜像 `collectLogs` 的回执完整性与统计/明细一致性校验 + 证据哈希；`LIMIT/OFFSET` 显式写入（≤200，同 `normalizePageSize`）
  - exchange/queue 过滤沿用 `escapeSqlLikeLiteral` + 字符白名单校验模式
- 修改 `OpsMonitorService`：`toEntity` 支持 MQ（monitorKey 默认 `bl:env:MQ`；校验 mqLagThreshold≥1；MQ 不要求 xxlJobDatabaseName）；`check` 与详情按 monitorType 分发到 MQ collector；移除 4 处"下一步接入"；新增 `mqDashboard` / `mqDetail` / `mqMessages`
- 新增 `MqFailureAlertService`（镜像 `XxlJobFailureAlertService`）：dedupeKey `MQ:{monitorId}:{db}:{logType}:{logId}`，通知类型 `MQ_MESSAGE_FAILED`，收件人 `findBusinessLineMembers`

**workhub-job**：新增 `MqFailureMonitorJob`，`@Scheduled(cron = "${workhub.ops.mq.failure-monitor.cron:0 */10 * * * *}")`

**workhub-controller**：`OpsMonitorController` 新增 `GET /api/ops/monitors/mq/dashboard`、`GET /api/ops/monitors/{id}/mq/detail`、`GET /api/ops/monitors/{id}/mq/messages`，权限沿用 `ops:monitor:*`
