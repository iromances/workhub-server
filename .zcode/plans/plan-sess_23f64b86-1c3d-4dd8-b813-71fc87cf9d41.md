# 提测 AI 审核与 Jenkins 构建改为可选项

## Context

REQ-a71851db 落地的提测链路目前强制三步：AI 审核必须完成（FAIL 还需人工强制确认）→ 创建禅道测试单 → 触发所选测试环境 Jenkins 构建，全部成功才推进测试中。禅道/Jenkins 真实联调尚未配置，强制链路导致当前根本无法走通提测。本次将 **AI 审核**与 **Jenkins 构建**改为可选项（禅道测试单创建保持必选），弹窗内两个开关**默认关闭**（默认直接提测：只建禅道测试单并推进测试中），人工可勾选开启。按 SDD 流程作为该需求的补充规格实施。

## 后端 workhub-server

1. **`workhub-model/.../intake/IntakeSubmitTestConfirmRequest.java`**
   - 移除 `environmentCode` 的 `@NotBlank`；新增 `Boolean skipAiReview`（null 视为 false）与 `Boolean triggerJenkins`（null 视为 true，兼容存量调用），更新类注释说明新契约。

2. **`workhub-service/.../intake/IntakeSubmitTestReviewService.java`** — `confirmAndSubmit` 调整判定顺序：
   - `triggerJenkins` 为 true 时才要求并校验 `environmentCode`（大写归一）；false 时忽略环境与 Job 名。
   - `skipAiReview=false`：维持现行为（审核须完成、FAILED 须 `forceConfirm` 并记录确认人）。
   - `skipAiReview=true`：跳过审核前置校验（含 RUNNING/PENDING 中）；实体不存在时插入 `review_status=SKIPPED`、reviewMessage="人工跳过 AI 提测审核" 的记录用于保存禅道回执；实体已存在则不动审核字段、不要求 forceConfirm。
   - 禅道创建、`advanceStage(SUBMIT_TESTING)` 不变；Jenkins 触发仅在 `triggerJenkins=true` 时执行。
   - 新增常量 `STATUS_SKIPPED = "SKIPPED"`。

3. **竞态修复（本次变更直接引入的路径）**：允许 skip 时在审核 RUNNING 中确认提测，而 `executeReview` 现用全列 `updateByIntakeId` 回写，会用加载时的旧实体把禅道/Jenkins 回执冲掉。在 `workhub-dao/.../IntakeSubmitTestReviewMapper.java` 新增只更新审核结果列（review_status/review_message/findings_json/conclusion/summary/updated_by/updated_at）的 `updateReviewOutcomeByIntakeId`，`executeReview` 的 RUNNING 置位与最终回写都改用它；回执行列以确认事务的全量更新为准。

4. **迁移 SQL**：新增 `workhub-bootstrap/src/main/resources/db/schema/mysql/V20261110_*__intake_submit_test_review_skipped_status.sql`，仅把 `pm_intake_submit_test_review.review_status` 列注释更新为含 SKIPPED（列本身 VARCHAR(32) 无约束，不改已有迁移避免 checksum 漂移）。

5. **测试 `workhub-service/src/test/java/cn/aslight/workhub/service/intake/IntakeSddFlowTest.java`** 新增用例：
   - skip=true 且无审核记录、triggerJenkins=false：不校验环境 → mock 禅道成功 → 实体以 SKIPPED 插入、Jenkins 客户端零调用、advanceStage 被调用。
   - triggerJenkins=true（缺省）无 environmentCode：报"请选择测试环境"。
   - skip=true 时实体 RUNNING：直接放行（不抛"审核尚未完成"）。
   - skip=false 维持原校验（既有用例覆盖，跑通回归）。

## 前端 workhub-web

6. **`src/views/intake/IntakeListView.vue`** 提测弹窗（SUBMIT_TESTING 模板块 ~3716-3754）：
   - 新增 `submitTestAiReviewEnabled`、`submitTestJenkinsEnabled` 两个状态，**默认 false**；弹窗打开时不再自动触发 AI 审核、不轮询（勾选开启后按现逻辑 fetch/start/poll）。
   - AI 开关关闭：隐藏 AI 审核区（alert/缺陷表/强制提测勾选/重审按钮）并停止轮询；开启：恢复现行为。
   - Jenkins 开关关闭：隐藏"测试环境""Jenkins Job"表单项；开启：环境必选（提交前校验）。
   - `submitStageAction` 提交分支：payload 按开关传 `skipAiReview`/`triggerJenkins`，Jenkins 关闭时不传 environmentCode/jenkinsJobName；成功提示按实际动作生成（如"提测完成：禅道测试单已创建"）。
   - `resolveSubmitTestReviewStatusLabel/AlertType` 增加 `SKIPPED` → "已跳过"/info；回执卡（~4528）已对 jenkins 字段做 v-if，无需改。
7. **`src/types/work-item.ts`**：`reviewStatus` 类型加 `'SKIPPED'`。**`src/api/intake.ts`**：`confirmSubmitTest` 请求类型改为 `environmentCode?: string` 并新增两个可选布尔字段。
