# 系统集成可视化管理

## Context

现有禅道/Jenkins/GitLab 集成已实现但配置散在 `sys_config_item`（`zentao.base`、`gitlab.global`、`agent.jenkins`/`policy`、`intake.submitTest`），无可视化入口。本需求新增「系统集成」菜单：列表页（系统名、集成方式、认证方式、操作：详情/编辑/测试连接），详情展示并编辑该系统的接入能力清单。已确认三个决策：**①注册台账表**（新建两张表，迁移预置禅道/Jenkins/GitLab 及能力目录，页面可新增系统）；**②仅元数据+配置状态**（连接配置不在此编辑，显示配置状态并跳转现有系统配置页）；**③列表页加测试连接**（Jenkins 复用探针，禅道/GitLab 新增只读探针）。不改现有客户端调用逻辑、不迁移 sys_config、不动 Agent 策略。

## 1. 数据库迁移（1 个 Flyway 文件）

`workhub-bootstrap/src/main/resources/db/schema/mysql/V20261106_HHMMSS__add_integration_catalog.sql`：

**`sys_integration_system`**：id、system_code（唯一）、system_name、integration_method（REST_API / REST_AND_LOCAL_GIT）、auth_type（ACCOUNT_PASSWORD / BASIC_API_TOKEN / PAT）、config_groups（CSV，关联 sys_config 组名）、enabled、sort_order、remark、created/updated_at、created/updated_by。

**`sys_integration_capability`**：id、system_id（FK）、capability_code（系统内唯一）、capability_name、capability_type（READ / WRITE）、impl_status（ACTIVE / PLANNED）、description、enabled、sort_order、remark、时间戳。

**预置数据**（幂等 NOT EXISTS）：
- 禅道 ZENTAO（REST_API / ACCOUNT_PASSWORD，groups=zentao.base,zentao.mapping）：换Token、匹配版本（查build）、创建测试单（均 ACTIVE）、创建任务（PLANNED）
- Jenkins JENKINS（REST_API / BASIC_API_TOKEN，groups=agent.jenkins,intake.submitTest）：只读探针、触发构建（WRITE）、队列/构建状态、构建回执、丢失响应查找（均 ACTIVE）
- GitLab GITLAB（REST_AND_LOCAL_GIT / PAT，groups=gitlab.global,gitlab.,agent.gitlab）：列组仓库、仓库同步（fetch/clone）、创建候选分支（WRITE）、创建 Draft MR（WRITE）、查/合并 MR（ACTIVE）

**菜单权限**：`sys_permission` 插入 MENU `system:integration:view`（parent=system:view，route=/system/integrations，sort 56）+ BUTTON `system:integration:create`、`system:integration:update`，并按 V16 模式授予超管角色。

## 2. 后端（workhub-server）

- **model**：`IntegrationSystemEntity`、`IntegrationCapabilityEntity`（workhub-model）
- **dao**：Mapper 接口+XML（workhub-dao，照 SysConfigItem mapper 模式）
- **service**：
  - `IntegrationCatalogService`：列表/详情/新增/编辑（能力清单随系统整体替换，事务内删插）/启停；编辑校验 system_code 不可改（内置探针按 code 分派）
  - `IntegrationProbeService`（测试连接，按 system_code 分派）：
    - ZENTAO → `ZentaoClient` 抽出并新增 `probe()`：POST /api.php/v1/tokens 换 Token，成功返回账号，凭据缺失/失败明确报错
    - JENKINS → 读 `agent.jenkins`/`policy` JSON 第一个 enabled 实例 → 复用 `AgentJenkinsClient.probe`（Job segments 用 ["validate"]，照 AgentJenkinsPolicy.java:29 写法）；无实例明确提示未配置
    - GITLAB → 读 `gitlab.global` → GET /api/v4/user 轻量探针
    - 其他 system_code → 明确返回「该系统暂不支持测试连接」；响应只含 ok/message/耗时，不回传凭据
  - 配置状态：详情响应按 config_groups 统计各组键数、enabled、SECRET 是否已配置（复用 `SysConfigService.findPlainValue` 类能力，不回传值）
- **controller**：`IntegrationController`（`/api/system/integrations`，`@PreAuthorize` 照 AiConfigController 模式）：GET 列表、GET /{id}、POST、PUT /{id}、POST /{id}/probe（权限并入 update，照 ai-providers test-connection 先例）
- **测试**：目录 CRUD/权限/校验、三系统探针（凭据缺失、失败、无实例分支）单测，照现有 workhub-service 测试模式

## 3. 前端（workhub-web）

- `src/constants/menu.ts` 系统管理组追加「系统集成」项；`src/router/index.ts` 加路由（meta 照 system/ai-config 写法）
- `src/api/integration.ts`（照 system-config.ts 的 http 封装）
- `src/views/system/IntegrationView.vue`（element-plus，单文件）：
  - 列表：系统名/集成方式/认证方式/启用/操作（详情、编辑、测试连接——测试连接展示结果弹消息）
  - 详情弹窗：能力表格（编码/名称/类型/实现状态/描述/启用，支持行编辑与增删；PLANNED 打标签）+ 配置状态区（组名/键数/SECRET 状态 +「去系统配置」链接）
  - 编辑/新增弹窗：系统元数据表单（枚举下拉）
  - 按钮权限用 `authStore.hasAnyPermission`（照 SystemConfigView.vue:32 写法）
- `SystemConfigView.vue` 小改：onMounted 读 `route.query.configGroup` 预填筛选，支持从详情跳转定位
- 类型定义新建 `src/types/integration.ts`
