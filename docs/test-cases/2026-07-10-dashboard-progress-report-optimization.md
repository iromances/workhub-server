## 2. 测试范围

- 本次需求核心场景：报告标题调整为“项目进度”；副标题只展示生成时间；本周上线需求展示“研发需求”或“数据提取/运维”类型标签；未上线需求按是否已经提测切换日期信息；点击生成时重新获取最新工作台数据；报告以高清 PNG 生成并下载。
- 本次需求边界场景：本周上线或未上线列表为空；日期字段缺失；报告包含单条或多条需求；标题、业务线等文本较长；浏览器设备像素比不同。
- 本次需求异常场景：刷新工作台数据失败；浏览器不支持 Canvas 2D 上下文；PNG Blob 生成失败；用户连续点击生成按钮。
- 不纳入自动化测试的范围及原因：前端仓库当前没有测试运行器，Canvas 绘制、点击下载和异常提示通过 TypeScript 生产构建与真实浏览器检查验证；不同显示器、聊天工具二次压缩后的肉眼清晰度以及不同操作系统中文字体渲染效果不适合用稳定的单元测试断言；生产环境真实业务数据不在本地单元测试中读取。

## 3. 测试环境

- 后端环境：本地 Java 25、Maven 3.9，使用 JUnit 5 和 Mockito；执行前确认当前分支包含本需求代码。
- 前端环境：同级 `workhub-web`，Node.js 22、npm 10；执行现有 `npm run build`，并补充真实浏览器检查，不为本次小范围优化新增测试框架依赖。
- 数据库环境：自动化测试使用 Mapper mock，不连接真实数据库。
- 外部依赖：自动化测试不访问外部服务；前端真实下载检查依赖本地浏览器。
- 测试数据准备方式：后端构造研发需求、数据提取/运维需求及提测前后日期记录；前端用固定报告数据验证完整 Canvas 布局，并在本地工作台页面验证入口和按钮。

## 6. 未覆盖风险

- 未覆盖场景：实际下载文件落盘后的文件名和打开验证；刷新失败、连续点击；聊天工具或文档系统对 PNG 的二次压缩效果；不同操作系统和中文字体下的像素级一致性；超过 1600 万逻辑像素、无法容纳为单张报告的极端数据量；部署新后端后的完整真实数据联调；前端全应用既有严格类型错误。
- 未覆盖原因：这些场景依赖外部软件、真实字体环境、浏览器实现或生产数据，单元测试中的 DOM 和 Canvas mock 无法可靠还原。
- 可能影响：下载后的图片在部分传播渠道仍可能变模糊；超长报告会自动降低像素倍率，极端数据量会提示无法生成单张截图；个别字体环境下换行和截断位置可能不同。
- 后续补充计划：部署或重启包含本次后端改动的本地服务后，在人工浏览器下载一份真实报告，确认文件名、打开效果、最新数据和失败/连点行为；如后续引入浏览器自动化框架，再补充真实 Canvas 下载和尺寸断言。
