# 消费分期独立仓库、独立环境与渐进精简自动化测试用例

## 1. 需求信息

- 需求名称：消费分期独立仓库、独立环境、独立数据库及渐进精简。
- 研发方案文件：`docs/研发设计/迭代/2026-08-03-consumer-installment-independent-evolution.md`。
- 测试用例文件：`docs/test-cases/2026-08-03-consumer-installment-independent-evolution.md`。
- 业务线：消费分期，`BL000004`。
- 涉及系统：消费分期新仓库、新部署环境、新数据库及必要公共测试资源。
- 涉及模块：网关、鉴权、申请、附件、状态机、通知、数据库迁移、任务治理、运营后台、监控和审计。
- 当前状态：方案阶段，所有用例均为待执行。

## 2. 测试范围

- 核心场景：新仓库构建、空库初始化、新旧环境隔离、新合作方鉴权、申请受理、附件、查询、通知、运营管理和任务白名单。
- 边界场景：重复请求、并发请求、重复附件、状态乱序、请求超时、通知重试、任务重复触发和服务重启。
- 异常场景：伪造合作方身份、签名错误、重放攻击、数据库迁移失败、队列积压、未知状态、敏感日志和新旧系统串流。
- 回归范围：首期保留的老模块构建、启动、健康检查和仍被白名单流程调用的能力。
- 不执行范围：老系统历史交易迁移、新老数据库双写、未批准的真实支付或资金写入。

## 3. 测试环境

- 目标环境：开发、测试、预发布和生产灰度环境，执行前分别确认。
- 目标分支：测试环境使用当前发布分支；生产环境使用 `master`。
- 数据库：各环境独立新库，数据库验证只使用 WorkHub 受控只读能力。
- 测试数据：构造新合作方、项目、产品、申请、附件和通知数据，不复制生产交易数据。
- 外部依赖：只允许连接已批准的测试资源。
- 安全限制：未确认写入安全策略前，不执行短信、签约、支付、扣款、放款、退款等高风险正向请求。
