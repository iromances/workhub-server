## 2. 系统定位

WorkHub 是公司内部研发协作与受控运维平台的工作台，提供研发管理、平台管理、业务线运维上下文、监测及外部集成配置能力。具体业务线的业务系统在各自代码仓库中维护，支付域在 WorkHub 内负责接入配置。

项目职责来源于[根目录项目定位](../../AGENTS.md#2-项目定位与职责)。前端仓库为同级 `workhub-web`，本次未核对前端实现。

## 3. 技术与模块结构

后端采用 Maven 多模块结构，Java 25、Spring Boot 4.0.5、MyBatis Spring Boot Starter 4.0.0。启动模块声明 MySQL 驱动、Druid 和 Flyway 依赖。版本依据为[根构建配置](../../pom.xml)和[启动模块构建配置](../../workhub-bootstrap/pom.xml)。

下表记录当前模块分工及 Maven 声明的直接内部依赖；模块链接指向各自构建配置。

| 模块 | 职责 | 直接内部依赖 |
| --- | --- | --- |
| [workhub-model](../../workhub-model/pom.xml) | 数据模型、请求与响应结构 | 无 |
| [workhub-support](../../workhub-support/pom.xml) | 公共支撑能力 | 无 |
| [workhub-dao](../../workhub-dao/pom.xml) | MyBatis 数据访问 | model |
| [workhub-service](../../workhub-service/pom.xml) | 业务服务与集成逻辑 | model、dao、support、mcp-server |
| [workhub-controller](../../workhub-controller/pom.xml) | HTTP 接口层 | model、service |
| [workhub-job](../../workhub-job/pom.xml) | 定时任务 | model、dao、service、support |
| [workhub-mcp-server](../../workhub-mcp-server/pom.xml) | MCP 能力实现 | 无 |
| [workhub-bootstrap](../../workhub-bootstrap/pom.xml) | 应用启动、配置与模块装配 | controller、job、support |

## 6. Codex 接入配置模型能力

2026-09-23 根据 [Codex 模型能力动态加载需求](需求/REQ-9209b10e-c3f9-41ac-b2fe-79f9b2cdd442-Codex模型能力动态加载/design.md)核验本地实现及自动化测试；尚未验证真实账号目录和已登录页面联调，未发布或重启应用。

接入配置 CLI 通道通过 `POST /api/manage/system/ai-provider/codex-models` 查询。后端以当前表单命令、工作目录运行 Codex app-server，通过 stdio 完成初始化并调用 model/list，聚合可见模型及各自推理强度；仅查询目录，不创建任务。接口须有 AI 配置新增、编辑或管理权限。后端本机与运行用户的 Codex 登录、配置决定目录内容；手动刷新只能绕过 WorkHub 的 60 秒缓存，不能承诺强制刷新 Codex 云端目录。单次协议查询限制 10 秒，成功和失败均回收进程。

前端打开含启用 CLI 通道的接入弹框时加载模型，强度随用户选择的模型联动。查询失败、旧模型缺失时保留历史值并提示；新建及改变环境、模型或强度后须加载有效目录再保存。模型和强度使用 Codex 原值保存并传给 CLI，历史全大写强度仅在旧值匹配及执行边界兼容；不将 ULTRA 映射为 xhigh。API 通道及场景编辑器继续沿用现有选项机制，字典和历史数据不迁移。
