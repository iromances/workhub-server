## 2. 根因摘要

- 已证实：
  - 新 nacos（28848，库 `lease_nacos_huawei_254`）共享配置 `COMMON_GROUP/common.yaml`（11-06 修改）xxl 段指向新中心 `218:28080` 且配置 accessToken、`executor.port: -1`。

  - 2.5.0 admin 对 `/api/*`（注册与回调）统一校验 accessToken（`xxl-job-2.5.0/xxl-job-admin/.../JobApiController.java`）。
- 待执行器侧证据确认（缺口）：旧 core 2.2.0 回调被新 admin 拒绝的具体原因（token 不匹配或报文不兼容），需查看执行器应用日志或 `/mnt/xxljob` 回调重试日志；MCP 未配置 lease-saps/ol-saps 生产服务器目标，ELK 查询报"活动时间超出查询区间"无法取证。

## 3. 补跑原则（先读再动）

1. **禁止全量重跑**：代扣等资金类任务窗口内已实际执行（第 1.2 条证据），盲目重跑有重复扣款/重复计费风险。
2. **核对优先**：每类任务先执行第 5 节核对 SQL，判定“已执行 / 漏执行 / 部分执行”。
3. **定向补跑**：仅对核对确认缺口的手动触发；统一在新 admin（218:28080）任务页“执行一次”带原参数，或走各服务自带手工 Controller（源码存在 xxlJobController/测试 Controller 入口）。
4. **客户触达类**（短信/微信/电话）补发避开 21:00–09:00；历史通知是否补发由业务确认，默认不补。
5. 补跑操作人与时间记录到本文档第 7 节；每次补跑后执行对应验证 SQL。
