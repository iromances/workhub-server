## 已确认问题

### P1 CRM 调度参数丢失可能扩大处理范围

目标提交 a79a599b7cbdfadecea554ecb4c3988ce5dee7f8，基线 89e9678c449babc67d595dd90153d297d7c12060。

[ProductChangeExecuteJob.java 第 45 行](http://10.10.116.21:10000/xxt-plateform/thctay-crm/-/blob/a79a599b7cbdfadecea554ecb4c3988ce5dee7f8/crm-controller/src/main/java/com/thchengtay/crm/controller/xxljob/ProductChangeExecuteJob.java#L45) 保留 execute(String param)。父依赖升至官方 core 2.5.0 后，MethodJobHandler 以空参数数组反射调用旧入口，不再传入调度参数。若配置了申请单号数组，业务方法仍收到 null，第 54 行的申请单 in 条件不生效，随后会调用 service.completed 处理所有符合基础状态条件的产品转换申请。车辆修复任务的指定游标也有同类影响。

修复方向：无参调度入口通过 XxlJobHelper.getJobParam() 取参数，将有参业务方法与调度入口分开；保留手工调用语义。未声称测试或生产已发生越范围处理。

### P2 CRM 失败返回值被执行器忽略

[PushPersonVehicleOrderBatchJob.java 第 33 行](http://10.10.116.21:10000/xxt-plateform/thctay-crm/-/blob/a79a599b7cbdfadecea554ecb4c3988ce5dee7f8/crm-business/src/main/java/com/thchengtay/crm/business/job/PushPersonVehicleOrderBatchJob.java#L33) 捕获 InterruptedException 后返回 ReturnT(500, ...)。core 2.5.0 不读取方法返回值，正常返回时上下文仍为默认 200；依赖失败状态的重试及告警无法按原语义触发。服务实现确有 CountDownLatch.await() 的中断路径。

修复方向：在调度入口中显式 handleFail 或抛出异常；正确保留中断状态，避免把失败分支当正常完成。

### P2 CRM 手工执行接口不兼容无参任务

[xxlJobController.java 第 43 行](http://10.10.116.21:10000/xxt-plateform/thctay-crm/-/blob/a79a599b7cbdfadecea554ecb4c3988ce5dee7f8/crm-controller/src/main/java/com/thchengtay/crm/controller/debug/xxlJobController.java#L43) 固定调用 method.invoke(bean, paramStr)。公共 MQ d44d555c25 的 messageSenderRetrySchedule 已改为无参 process()，并在 CRM 的 com.thchengtay 组件扫描范围内。请求该任务时，无论 data 为 null 或对象，均抛 wrong number of arguments，业务服务不会执行。

修复方向：手工调用接口统一适配任务参数、上下文和结果；无参入口不得固定传入一个参数，迁移为 void 后也不能仅凭反射返回值判断任务成功。
