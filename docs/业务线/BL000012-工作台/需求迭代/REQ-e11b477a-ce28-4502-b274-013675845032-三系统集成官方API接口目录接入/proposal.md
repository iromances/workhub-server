## 1. Why：背景与问题

- 当前问题及证据：
  - 系统集成台账（REQ-49bc7dcd 建立、REQ-0051c0a8 扩展）的接入能力是平台视角的自建条目（如 `exchange-token`、`submit-build`），不含官方 API 的接口要素（接口名称、HTTP 方法、请求路径）；用户与 AI 无从得知三个系统官方提供了哪些接口、WorkHub 实际接入了哪些。
  - 禅道 REST API、Jenkins Remote Access API、GitLab REST API v4 的官方接口清单只存在于各自文档站点，未结构化进入 WorkHub。
- 受影响用户/角色：平台管理员（查阅官方接口全集与平台接入面）、研发/测试与数字员工（通过目录了解可请求的官方接口要素）。
- 不解决的后果：接口要素需每次翻官方文档；平台接入面与官方全集的差异不可见。

## 2. What：目标与范围

### 本期目标

1. 按官方对接文档，将禅道、Jenkins、GitLab 三个集成系统的官方 API 接口目录（资源组 + 接口条目：接口名称、HTTP 方法、请求路径、说明）结构化导入 WorkHub，并在系统集成详情页展示。
2. 接口条目标注平台接入状态（平台代码已调用的接口可识别），与既有"接入能力"目录并列呈现。

### 本期交付范围

1. 数据模型与迁移：新增接口条目存储与三系统种子数据迁移（来源、抓取时间与文档口径在迁移/目录中可追溯）。
2. 抓取生成脚本：从官方文档解析生成种子 SQL 的脚本，产出物入库（需求目录），保证目录可再生成、可核对。
3. 后端查询接口：按集成系统分页查询官方接口目录（资源组/方法过滤）。
4. 前端展示：系统集成详情弹框新增"官方接口目录"只读区（分页表格、过滤），展示接口名称、方法、路径、说明与平台接入标记。
5. 文档：`docs/mcp-server.md` 无涉及（本期不动 MCP）；迭代日志与需求文档更新。

### 明确不做

1. 不将官方接口批量开放为 MCP 可调用工具——平台实际调用仍按既有链路（提测、数字员工审批发布等），本期仅目录与要素展示。
2. 不重构既有"接入能力"目录（capability 语义保留平台视角）；接口目录为并列新增的只读数据，页面不提供手工编辑。
3. 不代理转发官方接口请求（不做 API 网关）。
4. 不覆盖 GITLAB 之外的系统与未列出的集成系统。

### 约束与依赖

- 依赖的代码和文档：`sys_integration_system/capability` 模型与服务、`IntegrationController`、前端 `IntegrationView.vue`；官方文档事实来源（已核实可达性，见 Design §1）。
- 业务/合规约束：接口目录为官方公开文档的结构化快照（无凭据、无敏感信息）；数据量以抓取时点文档为准并标注来源与日期。
- 既有系统/接口/数据约束：不修改既有 capability 表语义与页面区块；新表与新接口独立。
- 外部依赖与前置条件：抓取期间官方站点可达（已实测：docs.gitlab.com、jenkins.io、zentao.net 可达；禅道 REST API 文档入口需在实施首任务定位权威源，候选见 Design §1）。
