## 1. Why：背景与问题

- 当前问题及证据：接入配置列表"CLI通道"列的默认模型按 ZCode 要求的 `providerId/modelId` 原始标识渲染（例 `ec0bca54-…/glm-5.3`），用户无法辨认（2026-11-24 截图确认）。同页"API通道"列默认模型显示字典编码而非名称（AiConfigView.vue:1139）；"使用场景"表模型列对 CLI 绑定行同样回退原始标识（AiConfigView.vue:1069，字典 `optionText` 找不到即原样返回）。而编辑弹窗与场景弹窗已通过目录接口拿到 `displayName` 下拉展示，列表却未复用。
- 受影响用户/角色：查看与维护 AI 接入配置的管理员（`system:ai-config:view` 及以上）。
- 不解决的后果：列表页继续展示不可读的长 UUID 标识，核对默认模型配置须逐个打开编辑弹窗。

## 2. What：目标与范围

### 本期目标

1. 接入配置列表：CLI 通道默认模型显示目录友好名称，原始标识保留在悬浮提示中；API 通道默认模型显示字典名称。
2. 使用场景列表：模型列对 CLI 绑定行显示目录友好名称。
3. 名称不可得时（目录未返回、无调用权限、CLI 失败）回退显示原始标识，页面不报错、不阻塞。

### 本期交付范围

1. `workhub-web/src/views/system/AiConfigView.vue`：新增 CLI 模型名称的会话内获取与映射、三处展示替换。

### 明确不做

1. 不改后端接口、权限与数据库，不持久化显示名称。
2. 不改编辑/场景弹窗既有目录加载、校验行为。
3. 不为只读用户申请目录接口权限（回退原始标识即为最终表现）。

### 约束与依赖

- 依赖的代码和文档：既有 `fetchZCodeModels`/`fetchCodexModels` 目录接口（60 秒 TTL 缓存 + 并发去重，CodexModelCatalogService）、`createCodexCatalogLoader`、字典 `aiModel`。
- 业务/合规约束：CLI 目录接口要求 `system:ai-config:create/update/manage` 权限；`view` 用户仅能回退原始标识。
- 既有系统/接口/数据约束：ZCode 默认模型必须存 `providerId/modelId` 原始标识（AiCliType 校验），展示层不得改存储格式。
- 外部依赖与前置条件：CLI 名称解析冷启动会拉起 CLI 进程，量级与编辑弹窗打开一次相同。
