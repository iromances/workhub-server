## 1. Why

巡检已稳定产出分级报告，但问题只停留在文本：看不到代码位置与根因，修复靠人从报告到代码的二次定位；修复-审核-发版全链路人工。把"问题→定位→修复→审核→上线"产品化为平台闭环。

## 2. What（分两期）

### 一期：结构化问题 + 三 Tab 展示 + 巡检深查

1. 巡检产出结构化问题：CLI 结果扩展 `problems[]`（域=系统预警/业务监测/账务监测；标题、级别、证据引用、五要素：代码位置/触发步骤/根因/影响与验证/修复方向）；文本报告保留。
2. 巡检当轮深查（决策③）：平台按业务线 GitLab 组**浅 clone 涉及仓库**进 CLI 工作区（决策①同源机制），AI 对**新出现的 P0/P1**逐个读代码定位（复发问题沿用上次分析，控制时长）；P2 不做代码定位。
3. 新表 `pm_agent_issue`（问题即工单，含状态机与去重键）；平台解析入库、去重合并。
4. 前端：运行详情"结果与产物"下三个 Tab 按域展示问题卡片（级别/五要素/证据），支持单选多选。

### 二期：勾选修复 + 工单审核 + 两段式发版

5. "去修复"：平台独立 clone 涉及仓库→建分支 `fix/{工单号}`→CLI 修复任务（选中问题五要素+修复方向为输入）→提交推送→建草稿 MR→工单转"待人工审核"。
6. 工单中心页：列表/详情（diff 摘要、MR 链接、分析五要素）；审核通过→合并 MR→触发 Jenkins 部署 TEST→"测试中"；人工确认 TEST 通过→发 PROD（复用既有 Jenkins 绑定与发布守卫）→"已修复"；拒绝→回开放+意见。状态变化发站内信。
7. 状态机：OPEN→ANALYZED→FIXING→PENDING_REVIEW→TESTING→FIXED（/REJECTED→OPEN）。

### 明确不做

不自动合并未经审核的代码；PROD 永远人工点击；不做工单与禅道缺陷双向同步（后续可接）。

## 3. Done（关键验收）

| 编号 | 验收 |
| --- | --- |
| AC-01 | 巡检报告含结构化 problems；三 Tab 按域展示，P0/P1 含五要素（新问题），复发问题不重复分析 |
| AC-02 | 勾选（单/多）问题→去修复→独立 clone+分支+代码提交+草稿 MR，工单转待审核 |
| AC-03 | 审核通过→合并+Jenkins 部署 TEST；人工确认→发 PROD→已修复；全程状态可追溯、站内信通知 |
| AC-04 | 全量测试与构建通过；安全边界（不动本机开发目录、PROD 人工门禁）不回退 |
