## 1. 背景
用户提供《智能柜退款修复分支审查报告-20261030.md》作为报告结构参考。仅借用结构，不执行附件中的修复建议，也不把其历史结论当作当前巡检事实。
当前数字员工结果契约只有 type/summary/deliveries/problems；报告全文常进入 summary，前端从文本摘取摘要。实际失败轮次 e471163f-30c4-4bf2-8b6f-f2823c5f7761 已保存约 15335 字符的答复，其中唯一 JSON 块可以解析，但前置说明文字触发额外模型整理，整理接口返回 -32603。
已有 pm_agent_issue 是跨轮次问题工单，不能替代不可变的单轮报告快照。
本需求新增固定报告契约与存储，关联但不覆盖 REQ-10c04b69 的旧报告阅读优化、REQ-5fbc863d 的原文保存与恢复历史。

## 2. 目标与范围
1. AI 按版本化 JSON Schema 一次返回结构化结果。后端校验、分表保存，前端及导出按固定章节渲染；不以再次调用模型排版作为正常路径。
2. 模板覆盖巡检、代码审查和一般数字员工结果；内容未核验必须标明，不因数组为空或执行完成就宣称业务正常。
3. “本地”按 WorkHub 自有运行库解释，不新建桌面数据库；拟新增五张表，复用现有事件保存脱敏原文、现有工单跟踪修复。
4. 保留旧报告只读展示；历史失败原文可走现有恢复入口，本轮提供确定性解析能力，不自动批量重跑或回填。
5. 不增加人为正文长度限制；摘要职责与详细证据分离，不靠截断达到简洁。无安装依赖、第三方消息、自动修复/部署。

| 编号 | 条件 | 核对方式 |
| --- | --- | --- |
| AC-01 | 巡检、审查、一般任务均按约定结构返回，结论、范围、检查、发现、证据、行动分别可读 | 三类脱敏夹具及契约测试 |
| AC-02 | 合法 JSON 或唯一合法 JSON 围栏直接校验通过；缺字段、非法引用、多候选歧义、截断结果不误成功 | 解析与完整 schema 测试 |
| AC-03 | 五表保存原子、幂等，历史报告不随工单状态变化；权限和删除生命周期一致 | 数据库事务及接口测试 |
| AC-04 | 页面/导出使用同一结构，旧报告仍可读；摘要不复制整篇明细 | 前端测试、构建、浏览器验证 |
| AC-05 | 原文先保存，格式失败可单独恢复，不执行业务工具；失败不伪装完成 | 协议与恢复测试 |
| AC-06 | 现有问题去重/通知/验收继续有效；通用审查发现不自动变成运维修复工单 | 集成回归 |
