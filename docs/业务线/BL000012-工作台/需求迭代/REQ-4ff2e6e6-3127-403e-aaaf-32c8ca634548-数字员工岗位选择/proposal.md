## 1. Why：背景与问题

- 当前问题及证据：数字员工仅有名称与职责，缺少"岗位"画像；职责 AI 起草（REQ-3e8d95c2）只能靠用户文字描述定位身份，初稿风格与岗位不贴合。
- 受影响用户/角色：创建/配置数字员工的用户（agent:manage）。
- 不解决的后果：岗位信息无处沉淀，起草助手无法按岗位画像生成初稿，数字员工列表也无法按岗位理解分工。

## 2. What：目标与范围

### 本期目标

1. Agent 配置新增**岗位**必填下拉：选项来自字典 `agentPosition`（种子=IT 岗位划分 + 全栈开发 + 公司常见岗位），支持输入模糊匹配。
2. 岗位联动职责 AI 起草：起草请求携带岗位，初稿贴合岗位画像。
3. 岗位随 Agent 保存、回显，`GET /api/agents/options` 一并下发岗位清单。

### 本期交付范围

1. workhub-server：`AgentConfiguration.position` 字段与保存校验；`AgentOptionsResponse.positions`；起草场景新增 `positionName` 变量并升版模板；字典与模板迁移。
2. workhub-web：Agent 配置对话框岗位必填下拉（filterable）、提交校验、起草联动。

### 明确不做

1. 不做岗位管理页面（字典经 SQL/运维维护，后续有需要另立需求）。
2. 不改运行时执行提示词（agent.*.step 模板不注入岗位；岗位只影响画像与起草）。
3. 不在数字员工列表页展示岗位标签。

### 约束与依赖

- 依赖的代码和文档：`dict` 字典表与 `DictService`；REQ-3e8d95c2 起草链路；`AgentConfiguration` JSON 存储（无 DDL 变更）。
- 既有系统约束：存量 Agent 的 configuration_json 无 position 字段，读取不受影响，编辑保存时须补选（必填）。
