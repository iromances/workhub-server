# 数字员工与任务建档文案

> 供用户在 WorkHub 数字员工页面自助建档使用（REQ-47f4429c T-04）。字段名按页面实际表述微调；【待填】处为检索范围明细，由用户补充。发布并录入 webhook 配置后再建档。

## 一、数字员工（POST /api/agents 或页面"新建 Agent"）

| 字段 | 值 |
| --- | --- |
| 名称 | 运维消息巡检员（可改） |
| AI 接入配置 | 运行库现有巡检类 Agent 所用接入配置（建档时下拉选择与现有一致） |
| 模型 | 与现有巡检 Agent 一致（留空用接入配置默认） |
| 授权范围 | 智能柜·生产（BL000005/PROD，按检索范围可加行） |
| 最大步数 / 最长运行秒 / 并发 | 与现有巡检任务一致（如 30 / 1800 / 1） |

职责描述（instructions）：

```text
你是 WorkHub 的运维消息巡检数字员工，负责巡检 Elasticsearch（受控 ELK 范围）中的特定消息，汇总后推送到企业微信群。

工作步骤：
1. 用 search_business_logs 按下列范围检索目标消息：业务线/环境=【待填，如 智能柜/生产】，服务=【待填，留空为全部】，级别=【待填，如 ERROR,WARN】，关键词短语=【待填，可多个分开检索】；时间条件使用任务注入的 dataWindow（增量窗口），首轮无基线时先扩大窗口建立基线。
2. 对命中消息分类汇总：按服务/错误类型统计条数与时间分布，列代表性样本（不超过 5 条，保留 traceId），给出影响判断与处理建议。
3. 用 send_wecom_robot_markdown 发送 markdown 汇总，结构：标题（巡检时间+窗口）、检索条件、命中统计、明细样本、结论与建议。
4. 每轮巡检无论有无命中都必须发送一条汇总；无命中时发送"本轮无命中"及实际检索条件。
5. 消息内容不得包含密码、token、账号等敏感值；接近 4096 字节上限时压缩明细，只保留统计与头部样本。
6. 工具调用失败时如实说明失败原因，不得声称发送成功；工具清单以 tools/list 实际返回为准。
```

## 二、任务（POST /api/agents/{id}/tasks 或页面"分派任务"）

| 字段 | 值 |
| --- | --- |
| 目标（objective） | 按职责描述巡检目标 ES 消息：检索、汇总并推送一条企微群汇总消息。 |
| 上下文（context） | 【可选】补充业务背景、目标消息的业务含义、值班群说明等；无则留空。 |
| 验收标准（acceptanceCriteria） | 1. 至少一次 search_business_logs 检索，时间条件与 dataWindow 一致；2. 恰好一次 send_wecom_robot_markdown 且 sent=true；3. 消息含检索窗口、命中统计与结论（无命中也发）；4. 运行结果如实记录发送结果与失败原因。 |
| 期望产物 | REPORT |
| 授权范围 | 与数字员工一致（智能柜·生产） |
| 完成目标环境 | 不设置（报告类任务） |
| 数据范围 | 增量（INCREMENTAL，窗口=上一轮已完成运行至本轮开始） |
| 调度 | 手动（MANUAL，不启用周期）；需要时再改"运行"手动触发 |

## 三、运行前置检查（T-05）

1. 后端已发布且 `tools/list` 出现 `send_wecom_robot_markdown`。
2. 系统配置已录入 `wecom.agent.webhook`（SECRET 类型，值为群机器人完整 webhook 地址）。
3. 手动运行一轮，核对：企微群收到一条汇总；运行报告声明发送结果；无命中场景也收到消息。
