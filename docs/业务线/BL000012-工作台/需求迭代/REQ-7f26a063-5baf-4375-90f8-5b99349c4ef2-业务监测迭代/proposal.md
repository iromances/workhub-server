## 1. Why：背景与问题

- 当前问题及证据：
  1. 核对批次详情弹框（`AccountingMonitorView.vue`「核对批次详情」）的监测维度表没有查看 SQL 的独立列；唯一入口是点击维度名称（REQ-372e4ce1），弹框内还要逐条展开执行记录才能看到渲染后 SQL。一致性批次一个规则组会产生 1 条边界 + N 批汇总 + 样本，同一模板重复多行（运行库批次 4：67 行结果、321 条审计）。
  2. 配置详情里的规则目录只读（`AccountingRuleCatalog.vue`）。一致性规则组及检查项来自代码内静态目录 `integrity-rules.json`（叉车 13 组、智能柜 16 组、125 条检查项），执行时该业务线全部规则组全量执行（`AccountingIntegrityCheckExecutor#execute` 直接读 `AccountingIntegrityCatalog.families`），无法按配置启停规则组或检查项、无法调整告警级别、无法新增规则组。
  3. SQL 模板只能在「系统管理 → Function Call」按编码查找维护，与业务监测配置分离；运行库 87 个 `AI_*` 模板目前均未被修改过。
- 受影响用户/角色：业务监测使用与排查人员（`ops:accounting:view` 及以上）；规则组与检查项管理需 `ops:accounting:manage`；SQL 模板编辑与试运行沿用 Function Call 既有权限。
- 不解决的后果：核对口径调整要改代码发版或到另一页面按编码找模板；不关注或已知缺口的规则组每次全量核对都要跑；从批次结果定位实际 SQL 路径太深。

## 2. What：目标与范围

### 本期目标

1. 核对批次详情中每个监测维度可一键查看实际执行的 SQL。
2. 配置详情内可管理该配置的监测场景（规则组及其检查项）与 SQL；修改后下次核对按最新生效，历史批次保持当次执行快照。

### 本期交付范围

1. workhub-web 批次详情：结果表新增「实际 SQL」列；维度 SQL 弹框改为按 SQL 模板分组直接展示渲染后 SQL（执行次数、成败数、首末批参数），并可展开到逐条执行记录。
2. workhub-web 配置详情新增「监测场景」tab：
   - 一致性配置（`ACCOUNTING_INTEGRITY`）：规则组列表，支持启用/停用规则组、启停检查项与修改告警级别、查看/编辑三段 SQL（边界/汇总/样本）、保存后试运行、新增/编辑/删除自定义规则组。
   - 流程配置（批量代扣等五类）：列出三个固定维度及其 SQL 编码或固定值，支持查看/编辑对应 SQL 模板；维度集合固定不可增删。
3. workhub-server：规则组与检查项按配置持久化（两张新表），代码内置目录改为只补缺的种子；提供管理与执行接口；执行器按配置的生效规则执行；提交核对前校验存在生效规则；一致性模板保存时做契约校验；新增维度 SQL 概览接口；数字员工平台指南与数据指南口径同步。
4. 数据库迁移：新增 `ops_account_monitor_family`、`ops_account_monitor_check` 两表，并替换数据指南中的已知片段。

### 明确不做

1. 内置规则组的检查项集合不可增删，只能启停和改告警级别（用户 2026-11-27 选择「调整检查项」时该选项的约定）；自定义规则组的检查项可增删改。
2. 不改调度与通知口径：一致性场景仍仅手动或数字员工明确执行，告警开关保持关闭；保存修改不自动触发核对。
3. 不改历史批次的运行、结果与审计数据；停用或删除的规则组在历史批次中的结果行保留。
4. 不新增权限点，不新增 SQL 模板的修改历史与回滚。
5. 不做规则组排序管理，不提供已删除自定义规则组的恢复，不支持在保存前试运行未保存的模板。

### 约束与依赖

- 依赖的代码和文档：REQ-d227e09d（一致性规则目录、执行器、Function Call 审计链路）、REQ-b42cfc0f（配置详情弹窗）、REQ-372e4ce1（维度到规则组的映射、`sql-evidence` 的 `family` 过滤）、REQ-9f3c2a84 / REQ-b4d7e6f2（Function Call 登记与执行审计）；[Function Call 数据库访问规范](../../../../研发规范/FunctionCall数据库访问规范.md)。
- 业务/合规约束：业务库访问继续全部经 `func_call_sql` 模板与 MCP 只读网关（`SqlPolicyGuard`：只读、单条、强制 LIMIT），不直连、不修改业务数据。
- 范围变更说明：REQ-d227e09d v2 定稿的「静态规则目录按业务线绑定，来源表不接受自由输入」在本期由用户明确选择放开（新增自定义规则组），安全边界由模板契约校验与只读网关保持，见 Design §6。
- 既有系统/接口/数据约束：内置规则组编码、SQL 编码（`AI_<规则组编码大写>_<BOUNDS|SUMMARY|SAMPLE>`）、结果行 `rule_code` 均不变；`GET /configs/{id}/rules` 响应只增字段，向后兼容。
- 外部依赖与前置条件：迁移在应用重启时由 Flyway 执行到运行库（本机实例连接共享运行库）。实施阶段只做 H2 回归；真实迁移与重启由用户决定时机。
