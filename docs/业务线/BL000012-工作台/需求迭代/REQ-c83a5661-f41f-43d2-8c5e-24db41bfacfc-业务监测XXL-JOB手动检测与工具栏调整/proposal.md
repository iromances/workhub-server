## 1. Why：背景与问题

业务监测页面（`workhub-web/src/views/ops/OpsMonitorView.vue`）XXL-JOB 页签的“上次状态”来自 `ops_monitor` 表落库快照，仅由后台每 10 分钟定时扫描回写。后端早已提供单条实时检测接口 `POST /api/ops/monitors/{id}/check`（权限 `ops:monitor:check`），前端也封装了 `checkOpsMonitor(id)`（`src/api/ops.ts:52`），但页面没有任何按钮调用它，用户无法在页面手动刷新状态。

同时工具栏存在冗余：

1. 页头说明文案“维护本地 XXL-JOB 监测配置，首页不采集远端调度库统计。”无保留价值，用户要求删除。
2. 页头“刷新配置”按钮与筛选区“查询”按钮调用同一函数 `loadDashboard`，功能完全重复，用户要求删除“刷新配置”、保留“查询”。
3. “新增 XXL-JOB 监测”按钮在页头右侧，距离筛选区远，用户要求移到“查询”按钮右侧。
4. 列表“业务线”列编码在上、中文名在下，主次颠倒，用户要求中文名在上。
5. “监测名称”“监测 Key”两列信息价值低（Key 过长挤占宽度），用户要求删除这两列。
6. “上次采集时间”列直接显示 ISO 原文（含 `T`，如 `2026-11-12T09:30:00`），用户要求格式化为 `YYYY-MM-DD HH:mm:ss`。

## 2. What：目标与范围

### 本期目标

1. 行级手动检测：操作列新增“检测”按钮，点击实时检测该条监测并就地更新“上次状态/上次消息/上次采集时间”。
2. 批量手动检测：筛选区新增“全部检测”按钮，对当前列表逐条顺序检测，显示进度，完成后汇总提示；单条失败不中断。
3. 工具栏调整：删除页头说明文案；删除“刷新配置”按钮；“新增 XXL-JOB 监测”移到筛选区“查询”按钮右侧，与“全部检测”并列。
4. 列表列调整：“业务线”列中文名在上、编码在下（小字）；删除“监测名称”“监测 Key”两列；“上次采集时间”格式化为 `YYYY-MM-DD HH:mm:ss`。

### 本期交付范围

1. workhub-web：`OpsMonitorView.vue` 模板（页头、筛选区、操作列）、脚本（检测逻辑与状态）、相关样式清理。
2. 后端 workhub-server：不改动（复用既有 check 接口与权限）。

### 明确不做

1. 不新增/修改任何后端接口、权限点与数据库结构；不新增批量检测后端接口（前端循环调用单条接口）。
2. 不改动监测配置的新增/编辑/删除、筛选、详情抽屉与日志加载逻辑。
3. 不改动 MQ 页签占位与定时扫描任务（默认每 10 分钟）。
4. 不改 `api/ops.ts` 既有函数签名（仅新增 import 引用）。
5. 不改详情弹窗摘要与执行日志表（触发/处理时间显示维持现状）。

### 约束与依赖

- 权限：检测按钮受 `ops:monitor:check` 或 `ops:monitor:manage` 控制（与后端 `@PreAuthorize` 一致）；新增按钮维持 `ops:monitor:create`/`ops:monitor:manage`。
- check 接口对 MQ 类型监测返回错误（“MQ 监测采集下一步接入”）；本页列表仅含 XXL-JOB 监测，脚本仍做类型守卫。
- 外部依赖与前置条件：无。
