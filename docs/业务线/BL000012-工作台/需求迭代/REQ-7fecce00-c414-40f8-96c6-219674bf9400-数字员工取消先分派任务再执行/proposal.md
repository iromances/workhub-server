## 1. Why：背景与问题

- 当前问题及证据：数字员工页面是「员工 → 详情（任务列表）→ 分派任务 → 运行记录（任务成果）」四步。要执行必须先在「分派任务」抽屉建一条任务（`AgentTaskDialog.vue`），再从任务列表进入「任务成果」点「开始新一轮」（`AgentWorkbenchView.vue` L99–L133、L277–L291）。执行模型自 2026-11-10 起已改为职责驱动，2026-11-16 任务目标改为可选（默认按员工职责执行），2026-11-22 周期巡检统一改手动，“先分派再执行”成为多余步骤。
- 受影响用户/角色：使用数字员工的所有用户（`agent:task:view`、`agent:task:operate`）。
- 不解决的后果：每次执行都要先建任务；同一员工多次执行会在任务列表堆积多条任务，历史运行按任务分散，看不到“这个员工做过什么”。

## 2. What：目标与范围

### 本期目标

1. 数字员工直接执行：员工列表的「任务成果」直接打开该员工的任务成果弹框，在弹框里「开始新一轮」；页面删除任务列表、「分派任务」、任务编辑/删除入口和独立的「调整周期」抽屉。
2. 历史运行按员工展示：任务成果里的「历史运行」直接列出该员工名下全部运行（常设巡检、需求自动开发、问题修复），侧栏的展示方式不变。
3. 执行配置可调：原任务级配置收进弹框里的「执行设置」，语义不变（只影响后续新运行）。

### 本期交付范围

1. workhub-server
   - `GET /api/agents/{id}/duty-task`、`GET /api/agents/{id}/runs` 两个接口。
   - 职责执行任务的补建与存量认领、按员工列运行、保留请求标识与删除保护。
   - 相关提示文案与单元测试。
2. workhub-web
   - `AgentWorkbenchView.vue`、`AgentTaskDialog.vue`、`AgentRunPanel.vue`、`AgentConfigDialog.vue`、`AgentRunAcceptancePanel.vue`。
   - `src/api/agent.ts`、`src/types/agent.ts`、`docs/frontend-architecture.md`。
3. 文档：`现状.md`、`迭代日志.md`。

### 明确不做

1. 不删除、不合并任务表和任务接口。`pm_agent_task` 仍是运行的挂载点，需求自动开发（`IntakeAiDevelopmentService`）和问题修复（`AgentFixService`）继续按原流程创建并驱动任务，`/api/agent-tasks` 既有接口保留。
2. 不迁移历史运行，不改写任何运行或任务的规格快照；没有数据库结构变更，也没有数据迁移脚本。
3. 不为存量非常设任务保留“选中后再执行”的入口。它们的运行留在历史里可查看，失败、取消或待资源的运行可重试；需要按其配置重跑时调整「执行设置」。受影响的存量任务是智能柜“业务监测 v4 一次性验收”任务（1 轮）。
4. 不改执行链路（提示词、预警通知、业务监测、产物验收、对账）和权限码。「开始新一轮」保持无二次确认，与现状一致。

### 约束与依赖

- 依赖的代码和文档：REQ-4252cd6c（任务目标可选）、REQ-6d1b5cb0（周期改手动）、REQ-75416059 与 REQ-a473b3fe（任务成果全屏、手动刷新）。
- 既有系统/接口/数据约束：运行链路只读运行自身的配置与规格快照；`pm_agent_run.task_id` 非空且参与触发唯一键，运行必须有任务作为容器。
- 外部依赖与前置条件：后端先于前端发布（前端依赖两个新接口）。
