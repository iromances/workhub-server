## 1. Why：背景与问题

- 业务线编辑弹窗中的环境下拉框由前端硬编码（`ProjectListView.vue` 固定 dev/test/prod 三项），既选不了 FAT、UAT，也无法按业务线差异调整；访问地址/网关配置行的环境编码只能从这三项里选。
- 环境编码口径混乱：业务线访问配置与 MCP/运维各页面分别硬编码（dev/test/prod、dev/test/staging/prod、PROD/UAT/SIT/TEST 三套并存），后端各写入点大小写不一（业务线访问配置存小写，支付存大写，MCP/运维原样存储），前端按精确匹配显示标签时互相认不出。
- 不解决的后果：新环境（如 FAT、UAT）无法在业务线上使用；跨模块环境口径继续漂移，MCP 上下文、日志检索按环境匹配时容易踩空。

## 2. What：目标与范围

### 本期目标

1. 业务线增加“支持环境”配置（如 DEV、FAT、TEST、UAT、PROD），业务线编辑弹窗可维护；下方访问地址与网关配置行的环境下拉框取自该业务线的支持环境。
2. 全系统环境编码统一为大写存储与校验：所有 `environment_code` 写入点归一化为大写，存量数据迁移为大写。
3. MCP 资源页环境下拉框按所选业务线的支持环境动态取值，保存时校验环境必须属于该业务线的支持环境。

### 本期交付范围

1. workhub-server：`pm_business_line` 新增 `supported_environments` 列；业务线保存/响应模型与校验；MCP 资源、运维监测、告警范围/事件/人工接入、通知、对账监测等环境编码写入点统一大写；存量数据大写迁移与业务线支持环境回填 SQL。
2. workhub-web：业务线编辑弹窗支持环境编辑器与访问配置环境下拉联动；MCP 资源页环境下拉按业务线动态取值；运维监测页环境选项改为大写口径。

### 明确不做

1. 支付域 `pay_merchant_account.environment`（已是 PROD/UAT/SIT/TEST 大写，属支付域自有口径）不动。
2. 运维监测页、支付配置页的环境下拉不做按业务线动态取值（运维页仅改为大写口径；动态化后续跟进）。
3. 不做多环境名称映射管理（标签映射在前端常量维护）。

### 约束与依赖

- 依赖的代码和文档：WorkHub 后端仓库指引、代码风格规范；前端 workhub-web 仓库指引。
- 既有系统/数据约束：`mcp_resource_config`、`pm_business_line_access_config`、`ops_monitor_config`、`ops_system_alert_subsystem`、`ops_system_alert_event`、`ops_system_alert_scope`、`sys_notification`、`ops_account_monitor_config` 均有 `environment_code` 列；ELK 告警事件的环境编码继承自告警范围行。
- 外部依赖与前置条件：无新增外部依赖；迁移 SQL 随 Flyway 启动执行。
