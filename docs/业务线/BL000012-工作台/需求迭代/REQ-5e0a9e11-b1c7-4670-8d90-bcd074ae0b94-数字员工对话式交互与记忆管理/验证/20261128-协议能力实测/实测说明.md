## 假设逐项结论

### 1. ZCode 跨进程 `session/resume` 续接 —— 成立

- `session/resume` 参数取第一种形态 `{sessionId}` 即成功（无需 workspace 参数）。resume 的 result 直接返回全量 `messages` 历史。
- 两阶段实测：阶段1 新进程 create+send 让模型记住哨兵句 `T00_SECRET_7f3a` 后进程退出；阶段2 新进程 resume+send 追问，模型原样答出 `T00_SECRET_7f3a`（`recalled: true`）。
- `turn.completed` payload 含 `response`、`usage`（含 `cacheReadTokens` 8896——上下文缓存跨进程生效）、`toolCallCount`、`historyRoundCount`、`duration`、`resultType`。
- 未观察到 `session.resumed` 事件（该事件在本流程中不发出）；续接判定以 resume result 与功能为准，不依赖该事件。
- 会话持久化由 `ZCODE_SESSION_DB_PATH` 指向的 session.db 承载：跨进程续接要求两阶段共用同一存储目录。

### 2. ZCode 原生记忆落盘与隔离 —— 成立，路径规则修正

- **记忆根路径实测为 `{ZCODE_STORAGE_DIR}/cli/memories/projects/{名}-{哈希16}/memory/`**（例：`storage/cli/memories/projects/work-8767fae4f4544734/memory/`），随**存储目录**而非 `ZCODE_DATA_BASE_DIR` 派生。设计原按 `ZCODE_DATA_BASE_DIR` 推导，已修正。
- 条目格式与设计一致：YAML frontmatter（`name`、`description`、`metadata.type`）+ 正文；`MEMORY.md` 为每条一行的索引（样例见 `证据/记忆条目样例.md`、`证据/记忆索引样例.md`）。
- 跨会话验证：阶段1 会话要求记住暗号（模型真实调用 Read/Write 工具写入记忆文件），阶段2 **全新会话**（不 resume、同工作目录同存储）正确回忆出 `T00_MEM_9c2e`。
- **前置条件（重要）**：记忆写入依赖模型真实调用文件工具。`session/create` 若传空 `toolAllowlist: []` 会禁用全部工具，模型只能在回复文本里"假装"写记忆（实测出现伪造的 `ToolUse: writer_insert … memory saved` 文本且无文件落盘）。WorkHub 生产路径 `prepareAgent`（nativeTools）不传 `toolAllowlist`，不受影响；对话执行接入（T-04）不得引入空 allowlist。
- 模型行为记录：glm-5.3/low 未真实调用工具且输出偶发乱码前缀（" spikedThought"等）；一次无记忆时模型编造了暗号。对话链路须保留"结论必须对应实际工具输出"的提示词约束，版本号/暗号类信息以文件内容为准。

### 3. 流式事件负载 —— 成立，事件名修正

- 文本流式为 `session/event` 的 `type: "model.streaming"`，payload `{assistantMessageId, delta, done, kind}`（实测 `kind: "reasoning_delta"`，文本增量按同构字段）。SSE 的 `delta` 事件直接映射此负载。
- `message.upserted` 在本版本 app-server 会话流程中未出现；WorkHub 现有代码依赖的 `turn.started`/`turn.completed`/`turn.failed`/`tool.updated`/`session.updated` 均实测在位。

### 4. Codex `--json` 线程标识与 `exec resume` —— 推迟（用户 2026-11-28 指示）

- `codex exec` 在非信任目录需 `--skip-git-repo-check`（WorkHub 生产命令 `CodexAgentCliProtocol` 已携带）。
- 首轮真实运行遇 Codex 后端 `codex_api::endpoint::responses: error=timeout`，进程进入重连（1/5、2/5…）。用户确认本机 Codex 暂不能用，实测停止、进程已清理；待可用时补测线程标识与 `exec resume`，结论回填本节。

### 5. Codex 原生记忆 —— 结论修正

- `~/.codex` 下存在 `memories_1.sqlite`：Codex 0.80.0 有记忆基础设施，但为 **SQLite 库而非 Markdown 目录**，且无 WorkHub 可管理的文件接口（二进制内无 memories 路径字符串、无 markdown 记忆目录）。
- 对设计的影响：`平台记忆目录 + Codex 经 memory_save/memory_delete 工具读写` 的结论不变；"Codex 完全没有记忆"的表述修正为"Codex 的原生记忆为私有 SQLite 格式，不经平台目录，不纳入本期"。

## 环境异常记录（2026-11-28 当天）

- `glm-5.4` + 默认推理档经 anthropic 路由（`/v1/messages`）**持续 503**（两轮探针共 60+ 次重试全部失败，`server_error`，退避约 50 秒）；未认证探针返回 401，服务本体在线。`glm-5.3/low`、`glm-5.3/high` 可用。
- 影响：若生产 `ai_provider_config` 的 ZCode 通道默认模型为 glm-5.4，数字员工运行会同样受阻；需跟踪 AI server 恢复情况或临时降级默认模型。
- Codex 后端同日 endpoint 超时。

## 对设计的修正（已回写 design.md）

1. 记忆根路径：ZCode 原生记忆随 `ZCODE_STORAGE_DIR` 落在工位 `storage/cli/memories/projects/{slug}/memory/`；平台记忆权威目录即该目录（每员工固定 work 目录 → 唯一 slug），`memory_save`/`memory_delete` 与记忆子菜单读写同一位置。原 `zcode-data/`（`ZCODE_DATA_BASE_DIR`）方案删除。
2. 工位布局简化：会话库与原生记忆同源于 `storage/`，一个环境变量管两件事。
3. 对话执行接入（T-04）新增约束：不得向 `session/create` 传空 `toolAllowlist`。
4. SSE `delta` 事件映射 `model.streaming` 的 `delta` 字段。
