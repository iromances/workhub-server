## 3. 任务明细

### T-00：CLI 协议能力实测

- 描述与目标：用真实 CLI 验证 Design §1 的五项假设，决定后续任务按设计实施还是调整。
- 输入：Design §1 的 CLI 事实与假设；本机 ZCode CLI 0.18.0、Codex CLI 0.80.0。
- 输出：`验证/20261128-协议能力实测/实测说明.md`，含命令、事件负载样例、落盘目录和逐项结论；Design §1 的假设改为已核实事实。
- 前置依赖：无。
- 允许修改范围：本需求目录下的验证记录与 Design §1。
- 明确不修改范围：任何源码、配置、真实 `~/.zcode` 与 `~/.codex`。
- 项目补充任务字段：实测会产生真实模型调用（经公司 AI server），执行前由用户确认。

实测内容：
1. ZCode：`session/create` → `session/send` → 进程退出 → 新进程 `session/resume`，第二轮能引用第一轮的事实。
2. ZCode：会话中要求记住一件事，同一工作目录的新会话能引用，换工作目录后不可见；定位落盘目录并与 Design §3 的推导规则比对。
3. ZCode：记录 `message.upserted`、`tool.updated`、`turn.completed`、`usage.delta` 的实际负载。
4. Codex：`codex exec --json` 取线程标识，`codex exec resume` 续接；确认 MCP 与沙箱参数在 resume 下生效。
5. Codex：确认 0.80.0 没有原生记忆。

验收条件：

- [ ] 五项假设各有“成立、不成立或部分成立”的结论和证据。
- [ ] 记忆隔离成立：同一工作目录共享，不同工作目录互不可见。
- [ ] 不成立的假设已写回 Design §1 并给出替代方案。

计划验证方式（尚未执行）：一次性临时目录加隔离的数据目录（做法同 `ZCodeCliClient.prepareBuilder`，复制认证状态），不触碰真实用户配置。

状态及真实结果：进行中（2026-11-28）。ZCode 三项假设已实测成立（跨进程 resume 续接、原生记忆落盘与跨会话可见、流式事件负载），含两处设计修正：记忆根路径随 `ZCODE_STORAGE_DIR` 派生（`storage/cli/memories/…`）、`session/create` 不得传空 `toolAllowlist`。Codex 实测按用户 2026-11-28 指示推迟（本机 Codex 暂不可用，后端 endpoint 超时；`--skip-git-repo-check` 必需已确认），恢复后补测。当日环境异常：glm-5.4+默认推理经 anthropic 路由持续 503，glm-5.3 可用。过程、证据与结论见 [验证/20261128-协议能力实测/实测说明.md](../验证/20261128-协议能力实测/实测说明.md)。
