## 3. 任务明细

### T-01：执行策略、新场景与进程管理

- 目标/输入：依据 Design §3.4 将新实施场景与旧 `allowLocalTools` 模式分开，读取现有 CLI/网关/场景配置。
- 输出/允许范围：service 的 ai/intake CLI 相关类、明确的执行策略与取消句柄、相应测试；必要 model 配置类型。
- 不修改：既有分析场景能力、全局 Codex 配置、MCP 契约、主机账户或软件安装。
- 建议研发任务标题：新增受限 Agent 实施场景。

验收：

- [ ] 新场景仅 CLI；命令保留 workspace-write 沙箱、无命令网络，不含绕过沙箱参数；缺目录、配置或隔离支持时拒绝。
- [ ] 环境白名单、外部工具禁用、输出上限可验证；不删除外层限制以放宽权限。
- [ ] 超时/取消清理进程树；迟到输出不覆盖终态；既有场景回归通过。

计划验证（未执行）：扩展 CodexCliClient / DefaultAiGatewayClient / AiUseCaseDefinitions 相关隔离测试；只使用现有工具与依赖缓存，不调用真实模型、不联网下载。

### T-02：数据模型、数据库约束与迁移

- 目标/输入：承接 Design §3.2，先读适用数据库规范并核对现有 schema/迁移序号。
- 输出/允许范围：model/dao、新增 Flyway SQL、工作项 execution_mode、计划/执行/租约/报告修订表与索引、权限定义。
- 不修改：业务线数据库、已应用迁移、既有角色授权或真实数据；不启动应用来代替隔离验证。
- 建议研发任务标题：持久化 Agent 执行计划与任务。

验收：

- [ ] 存量工作项默认 HUMAN；活动工作项和 attempt 有数据库唯一约束；事务失败无半确认/半入队。
- [ ] 计划批准快照不可覆写；状态更新带版本与持有者条件；报告修订追加保存。
- [ ] 新迁移在已授权隔离数据库验证新增/升级与失败场景；没有该数据库则明确记为未验证，不连接开发/业务库替代。

计划验证（未执行）：mapper/服务测试、迁移结构检查；真实 MySQL 迁移测试待可用隔离环境。回滚保留新增表/列和证据，删除需另行确认。

### T-03：仓库定位、隔离工作区与预检

- 目标/输入：Design §3.1/3.4，WorkHub 实际业务线映射与批准计划；GitLab 仓库发现只复用已核实能力。
- 输出/允许范围：agent 域工作区服务、只读仓库元信息查询复用、预检结果模型与测试。
- 不修改：用户 IDEA 工作区、业务线分支、运行账户/配置、MCP 资源白名单。
- 建议研发任务标题：准备 Agent 专用执行工作区。

验收：

- [ ] projectId 与业务线归属核验，按批准 SHA 创建专用克隆；不存在的分支/SHA 阻断，不回退。
- [ ] 越界路径、软链接、带凭据 remote、危险仓库配置被拒绝；专用目录与交付目录分离。
- [ ] 预检覆盖写边界、命令网络、敏感文件读取、已安装工具和离线缓存；缺项可见且保持功能关闭。

计划验证（未执行）：临时目录下本地 Git 沙盒测试；执行主机探针待环境授权；无需真实 GitLab 凭据。

### T-04：独立验证和幂等交付

- 目标/输入：Design §3.5，批准的验收命令、T-01 受限执行与 T-03 工作区。
- 输出/允许范围：AgentVerifier、GitlabDeliveryService、可注入 GitLab 客户端、提交/分支/MR 结果模型及测试。
- 不修改：GitLab 默认/受保护分支，不自动合并或部署，不生成含密钥脚本。
- 建议研发任务标题：验证 Agent 产出并交付分支与 MR。

验收：

- [ ] 模型报告成功但命令失败/未执行时禁止交付；每条证据关联命令 ID、退出码、日志摘要与结果内容。
- [ ] 有限修复最多 2 轮，全部受总时限约束；验证后内容变化需重新验证。
- [ ] 固定仓库、执行分支、目标分支、resultSha；默认/受保护分支推送与 force 被拒绝；凭据不进入工作区/日志/模型环境。
- [ ] 推送成功响应丢失、MR 创建超时可核对后续传；远端同名分支不同 SHA 不覆盖；重试不生成重复 MR。

计划验证（未执行）：本地 Git 测试、HTTP 桩测试，不推送真实远端。真实接口冒烟归 T-09 授权范围。

- 目标/输入：Design §2、§3.1、§3.6，原阶段动作事务与 T-01–04。
- 输出/允许范围：agent 计划/生命周期/引擎、阶段动作事务接入及请求扩展、状态回写与测试。
- 不修改：既有需求和工作项状态定义、自动合并逻辑、其他业务线代码。
- 建议研发任务标题：打通规格确认后的自主实施。

验收：

- [ ] HUMAN 旧流程兼容；AGENT 必须展示并确认完整快照；确认、状态推进与 QUEUED 同事务；afterCommit 丢失仍可领取。

- [ ] 取消与 DELIVERING 条件更新互斥；进程未回收不终结；重启不会误杀其他持有者任务。
- [ ] 旧租约、迟到回调、提交后崩溃和远端结果不确定均有真实状态与恢复路径；无未经确认的无限重试。
