# 巡检历史读取与缺陷线索验证

日期：2026-11-04；状态：源码及本地隔离验证完成，未部署。规格为已批准 v4，另纳入用户明确回复“包括已登记缺陷和运行时发现的问题”。

## 实际改动

1. 修正 `monitor.business.detail` 的来源契约：读取 `xxlJobLogs` 的逐次执行日志；原先读取 `xxlJobDetail` 的任务汇总，无法满足问题登记所需 `/data/logs/{index}`。支持固定日期范围及每页大小，查询错误标为 `QUERY_FAILED`，不作为空的成功结果。
2. 新增 `monitor.accounting.runs`，按业务线/环境及可选配置读取历史运行，使用 `beforeRunId` 续页；最新成功不再遮住此前失败。历史失败与最新汇总的同一运行使用相同来源身份，避免同一事实被重复登记。
3. 账务规则明细改为有界的 ID 续页，返回 `nextAfterResultId / hasMore / runFinished`；状态清单支持配置过滤与分页，系统预警可以固定 `from/to` 时间范围。空的后续页或指定配置未找到不会冒充整条业务线没有监测配置。
4. 新增 `workhub.bugs.list/detail`，从缺陷所属项目关联真实业务线，叠加当前 Agent、任务及 `work-item:view` 权限。列表包含全部状态并支持状态筛选；详情重新限定业务线和缺陷类型。工作项没有结构化环境，输出 `environmentState=UNRESOLVED`，不自动归到 TEST/PROD，也不改动原工作项。
5. 工具目录增至35项，Agent/任务最多可选64项。两种执行适配的任务提示加入分页、历史数据和缺陷定位语义。前端工具目录原本动态读取后端，本轮无前端源码改动。

## 验证

相关22个测试类共 **262项通过，失败0、错误0、跳过0**。补充历史范围来源标记和工具容量后，再完成41项读取相关测试及 controller/job 依赖编译复查。命令、各类结果和用例名称见 [测试汇总](测试汇总.txt)，源码版本见 [摘要](源码摘要.sha256)。

- 从仓库实际 DDL 提取所需表定义，在 H2 MySQL 模式验证生产 Mapper；包含不同环境/业务线的运行和规则，验证续页不因新增更高 ID 移位、配置过滤不能跨环境、参数不能改变 SQL 范围、金额精度和实际字段映射。
- 使用真实 XXL-JOB 日志响应 DTO 经工具返回，再交给 `AutonomyEvidence` 提取问题身份，覆盖原契约接不上的问题；不再只用自造的近似 JSON 证明接口相通。
- 已登记缺陷核对实际项目业务线与“缺陷”类型；其他类型和其他业务线的 ID 无法取详情。真实权限服务验证来源权限撤销、当前范围撤销、越界和非法参数；敏感描述在进入模型前脱敏。
- 全部回归使用既有依赖、临时 Git、H2 与本机模拟服务；保留实际已安装 ZCode 的本机模拟模型验证。未访问真实 AI、GitLab 或用户 Jenkins。

## 剩余边界

- 上述 ID 是有界查询的续页位置，尚不是跨运行持久化的消费游标；迟到提交、来源删除/保留期、扫描确认与事务推进还需实现，不能据此声明已完成持续补漏。
- 历史账务范围按当前监测配置关联，源运行表没有独立环境快照，回执明确该依据且 `historicalEnvironmentVerified=false`；若配置曾变更环境，需结合原始日志复核。
- 缺陷工作项目前作为可追溯调查线索，保存在工具轨迹；与具体环境证据及自主问题单的完整关联仍需补齐。没有据工作项状态宣称修复、测试或发布成功。
- 本轮没有新增或执行数据库迁移，没有改变采集配置、主机路径白名单或角色权限。Jenkins 按用户要求暂缓，禁止生产构建测试的边界继续生效。完整产物验收、业务效果复查及真实环境联调尚未完成。
