# 日志查询与活动证据验证

日期：2026-11-04。业务线：BL000012-工作台。开发分支 codex/agent-workbench-autonomy，工作树 workhub-agent-autonomy/workhub-server。继续执行用户确认的“Agent 判定业务效果、WorkHub 核对证据约束”。

## 已实现

- 实时日志查询固定实际 ELK 配置摘要、监测范围、服务和筛选条件。匹配日志与每个指定服务的全级别活动查询共用同一 PIT，按最新 PIT ID 继续读取及释放；活动查询保留相同索引、环境、日期区间，去除日志级别、短语和请求标识过滤。
- 拒绝超时、失败/缺失分片、提前终止、非法计数、无效日志标识/时间、缺少或重复游标、重复记录。部分结果不伪装成功；消息/堆栈截断同时反映在返回状态，预警采集的共享读取也执行相应协议校验。
- 指定服务模式下没有启用服务时，查询前拒绝，不能退化成读取全部服务。范围重新加载后核对当前业务线/环境；没有明确预期服务或超过单次活动证明上限时，查询结果可分析，但不能推断全部服务健康。
- 新凭据随既有不可变 Observation 保存，无新迁移；不包含认证、PIT原文或敏感检索词原文。筛选条件/实际目标变化会重起观察，数据时间取全部目标服务中最旧的活动，不能以单个活跃服务掩盖其他服务停滞。
- 复查核验各服务真实活动和获批新鲜度、查询完整性及相邻区间覆盖。查询区间存在空档时重起观察；重复旧活动不增加样本。符合约束后仍由 Agent 按获批条件判断，平台不计算业务语义通过规则。
- 已有采样 JSON 缺少新增区间字段时保持可读；旧无凭据、截断日志保留原约束，不回填为已验证。发布门禁与原业务/账务来源一同回归。

## 协议依据与边界

按 Elasticsearch 官方 [Search API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-search) 检查 timed_out 和分片完成状态；按 [PIT 文档](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/point-in-time-api.html) 禁止部分快照、复用并更新 PIT ID。指定服务使用 [Filters aggregation](https://www.elastic.co/docs/reference/aggregations/search-aggregations-bucket-filters-aggregation) 分别收集活动，避免以全局最新日志代替各服务状态。真实ELK版本与这些协议的兼容性仍需在真实接入时验证。

此凭据证明查询快照中已进入ELK的数据范围、完整性与活动时间，不证明业务端到ELK全链路无丢失。获批方案需要其他监测证据时，Agent仍须补足。系统预警落库的持久采集区间、截断后的补漏游标、复查页面、问题关闭/复发与通用任务验收继续实施；当前系统预警来源仍不能据最近同步成功签发复查通过。
