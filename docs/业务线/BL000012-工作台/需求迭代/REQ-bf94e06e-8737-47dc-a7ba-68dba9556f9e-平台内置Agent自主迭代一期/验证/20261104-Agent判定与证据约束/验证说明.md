# Agent 判定与平台证据约束验证

日期：2026-11-04。业务线：BL000012-工作台。开发位置：独立工作树 workhub-agent-autonomy/workhub-server，分支 codex/agent-workbench-autonomy。本轮按用户“Agent 判定，WorkHub 核对证据约束”的确认实施；Jenkins 继续暂缓。

## 已实现

- 新增 verification.start / record / finish / status / wait。Agent 提交业务判断、理由和历史数据处置状态，平台固定人工审核摘要、准确候选版本、全部实际部署回执及获批复查标准。
- 采样引用当前运行的真实 Observation；验证原运行/Agent、来源工具、业务线/环境、内容摘要、数据时间和完整性。Agent 判断与平台约束分别保存；空查询、未执行、部分执行、截断和过期数据不能签发通过凭据。
- 同一实际数据重复查询不增加样本，来源/规则/目标变更或采样间断重启连续观察段；多来源使用共同覆盖窗口。历史采样不可变且仍保留，不能用等待墙钟时间替代新数据。
- 合格最终结果生成数据库关联的 VERIFICATION 凭据；生产发布材料必须核对该记录及原测试部署的准确版本和全部仓库覆盖，不能只信任 artifact 的 provenance/passed 字段。
- 等待时间持久化，只唤醒明确等待且没有未知句柄/占有者的原运行；撤权、停用、取消、预算耗尽均不自动恢复。等待不重置步数或执行时间预算。
- 业务写入与工具回执同事务，重复/并发调用幂等；API 可恢复已提交回执，CLI 仍须真实停止证明。人工未知执行核对也识别该回执，不能覆盖已提交结果。
- 新增只读 GET /api/agent-release-plans/{id}/verification，检查当前账号、候选清单、原任务范围和监测来源权限。长理由保留完整审计原文，工具/状态视图明确返回摘要及截断标记，避免结果整体丢失。

## 真实来源限制

目前能满足完整时间与执行范围核验的来源是带固定执行凭据的新账务运行。历史账务运行无凭据时不能通过；执行失败、跳过及部分执行不能冒充已完整评估。

业务监测的 updated_at 会在每次采集时更新，不能当成固定配置版本；当前摘要缺少执行时范围证明，返回 EXECUTION_SCOPE_UNVERIFIED。业务失败日志、系统预警和日志检索缺少查询区间内的采集健康证明，返回 COLLECTION_COVERAGE_UNPROVEN；空结果不能自动通过。以上是明确待补齐的实际来源能力，不能据本轮本地成功样本宣称全部业务场景闭环。
