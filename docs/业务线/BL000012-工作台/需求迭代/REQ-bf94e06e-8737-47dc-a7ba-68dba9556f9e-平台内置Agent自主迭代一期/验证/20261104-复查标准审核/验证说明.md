## 实现及限制

- release.prepare 的 API/CLI 共用工具契约要求 verificationPlan，包含各目标范围的监测工具/对象、通过条件、观察窗口、采样间隔、新鲜度、最少有效样本和证据要求，及整组历史数据/失败处理。没有默认时长；仅接受受支持的监测工具，范围必须恰好覆盖本组目标。字段、时间关系、唯一标识及总体24 KiB限制由后端核对。
- 请求幂等摘要使用固定字段顺序且包含标准；schemaVersion=2 整组快照冻结标准及原问题/方案引用，人工审核的 snapshotHash 包含全部材料。改变标准必须新请求、新计划、新审核；已有真实测试、候选版本、权限与环境门禁保留。
- 旧请求可形成缺标准草案，schemaVersion=1 可读、可驳回，但不可新批准。已批准旧计划的未发步骤被阻止；已发请求仍按原句柄核对，未知状态保留占位。标准不是成功产物，不据此宣称业务验证通过。
- 页面逐项显示标准，批准提示明确同时审核标准；缺标准禁用批准。按当前用户、权限、候选和激活状态隔离响应，失败清空材料。未对冻结材料提供编辑入口。
- 监测对象和通过条件仍是经人审核的标准文本，本阶段没有执行这些文本、自动复查、生成 VERIFICATION 成功产物或关闭问题。后续需把真实观察与批准标准绑定后独立验收。Jenkins仍暂缓。
