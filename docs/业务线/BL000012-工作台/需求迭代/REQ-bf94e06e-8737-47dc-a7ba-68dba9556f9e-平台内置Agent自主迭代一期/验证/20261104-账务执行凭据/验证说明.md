# 账务执行凭据与异常判断验证（2026-11-04）

本轮在 `codex/agent-workbench-autonomy` 独立后端工作区实施。用户确认“业务效果复查的监测项、通过条件、观察时长由 Agent 提出，随发布方案审核”，已写入 Design；本轮先修复复查来源证据的两个缺口，不将来源凭据视为修复通过。

## 已实现

- 实际查询前固定配置、业务线/环境、数据窗口、记录时区、规则定义和 SQL 摘要。数据库查询会话固定同一目录/目标，原文 SQL、口令不写入执行凭据。凭据落库失败时不查询；仅实际新执行保存记录，旧运行不回填。
- 历史列表、详情、持久巡检按已保存的范围读取；后续配置变更或删除不会把有凭据的历史改成另一个环境。旧记录仍明确环境未核实，混合列表逐条标记；证据损坏报错，不能退回旧记录路径。当前配置的最新运行不借用旧环境记录。
- MCP 响应缺失、格式不完整或字节截断时失败。聚合必须有一行完整数据，异常数必须是非负且不溢出的整数、金额必须有效；不将空记录或缺字段默认成零异常。部分规则跳过时整批为 PARTIAL。
- Agent 读取和问题来源提取使用执行记录的 Asia/Shanghai 时区，不按宿主时区解释本地时间。拥有凭据仍必须通过当前任务/Agent 范围与来源权限检查。
