# 巡检回执恢复验证

2026-11-04；REQ-bf94e06e-8737-47dc-a7ba-68dba9556f9e，沿用已批准v4及 [Design](../../design.md)。本轮继续实施T-01/T-04，核验本地 `codex/development-20261102` 工作区，未部署。

## 变更与验证

原断点：`inspection.next/ack` 的业务事务和持久调用结果已经提交，但执行器在写运行 `TOOL_RESULT` 前中断。此前恢复只看运行事件，会将这类调用一直留在结果未知状态。

现在恢复以原运行、调用键和匹配的工具意图读取已提交巡检结果，补入对应API或原生CLI的标准工具回执，并记录 `TOOL_RECEIPT_RECOVERED` 来源。正常执行与恢复复用成功回执格式，避免把裸业务结果当作执行端协议。恢复事务使用 `READ_COMMITTED`，等待原事务释放锁后可读取最新提交。

- API重新领取后直接消费已保存的工具结果，再进行下一轮规划；不重跑扫描或重复写分析。
- CLI的工具已完成和进程树已停止分别核实。即使已恢复工具结果，没有停止证明仍保持 `WAITING_RESOURCE` 和所有权；证据齐全后才释放。正常CLI最终结果的消费规则不变。
- 取消保留已提交的分析与事实；记录完回执后终止运行，不假装已回滚业务事务。旧所有者回调不能覆盖新运行。
- 人工在中断期间补充指令时，下一轮同时得到已有事实和新输入；轨迹说明原回执已保存，不错误声称原工具未执行。
- 结果记录缺失、其他运行或调用键、工具意图不匹配，均不能推断已完成；不新增对其他未知外部操作的自动重试。

新增6项集成测试，`AgentInspectionServiceTest`现20项；使用真实迁移/Mapper/事务/运行恢复/API执行循环和本地固定来源，模拟回执丢失，无真实AI或业务环境调用。覆盖并发恢复仅补一份回执、API不重复执行、取消不重复分析、CLI两种证据到达顺序、无记录/跨运行/换调用键不误释放、意图不符拒绝、人工新输入与已执行事实并存。

完整回归 **282项、23类全部通过，失败/错误/跳过均为0**；controller/job及依赖离线编译通过。含5项既有本机已安装ZCode与模拟模型的验证，未使用真实模型账号。命令、测试名称与报告时点见 [测试汇总](测试汇总.txt)，6份变更源文件见 [源码摘要](源码摘要.sha256)。本轮没有新增依赖、迁移或运行配置。
