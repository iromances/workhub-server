1. **发布执行方**：用户选择“WorkHub 调用现有发布流程执行，人负责审核”。不能沿用旧草案的“只创建 MR，后续全部手动处理”。

5. **人的作用**：审核后才执行测试发布与生产上线；业务语义、证据或授权不足时与用户沟通，不把猜测自动实现。

用户进一步明确：

> AI 应该更高一层，主动巡检 WorkHub 提供的监测能力。
>
> 或者说在 WorkHub 工作台里我可以配置一个 AGENT 来做巡检的任务，或者给他分派其他任务，可以有很多个 AGENT。

据此产品主体明确为 **Agent 工作台**：用户创建多个 Agent，选择系统 AI、配置职责和工具范围，分派立即或周期任务。Agent 围绕任务主动规划、选择 WorkHub 工具、观察结果并决定后续行动；巡检与自主修复是任务应用之一，其他任务不强制走告警/问题/发布状态链。WorkHub 提供宿主、调度、持久化、权限及审核；Jenkins 执行获批发布。

“多个 Agent”指产品内可独立配置和使用的 Agent，不是要求当前开发会话委派子代理；默认不追加 Agent 自动创建同伴或互相派工的范围。上述职责/任务/运行的数据划分属于 v4 设计建议，用户的目标补充不冒写为完整技术规格已批准。
