## 1. Why：背景与问题

- 数字员工任务目前只能创建、调周期、开始/取消/重试/补充，**不能删除也不能修改任务规格**；无用任务只能留在列表里，规格写错只能废弃重建。
- 同日已按用户要求对两个"资料整理助手"做过 SQL 物理删除（见 `docs/notes.md` 2026-11-10 记录），证明删除诉求真实；直接 SQL 无权限/校验/审计，需要产品化。

## 2. What：目标与范围

### 本期目标

1. **任务修改**：`PUT /api/agent-tasks/{id}` 修改任务规格（目标/补充资料/验收要求/期望产物/完成目标/范围），版本乐观锁；校验与创建一致（范围 ⊆ Agent 授权、完成目标规则）；已有运行保留原规格快照，后续新运行用新规格。
2. **任务删除**：`DELETE /api/agent-tasks/{id}`（`expectedVersion` 查询参数）物理删除任务及其运行/事件/产物；删除前在同一事务写 `pm_agent_audit`（action=DELETE，记录规格摘要与删除行数）。

### 删除前置校验（不满足即 400/409，提示处理方式）

1. 周期任务须先暂停（`schedule_enabled=0`）。
2. 不存在未结束运行（状态须全为 COMPLETED/FAILED/CANCELLED/WAITING_INPUT；QUEUED/RUNNING/CANCELLING/WAITING_RESOURCE 拒绝）。
3. 运行不挂接过程数据：观测、问题、候选变更、代码工作区、构建测试、发布计划/交付、验证、巡检分配任一存在即拒绝（保留证据，停用替代）。

### 权限

- 修改：`agent:task:operate` + Agent 归属（与调整周期一致）。
- 删除：`agent:manage` + Agent 归属（与停用 Agent 一致）。

### 明确不做

1. 不删审计行；不删除运行挂接的过程数据（由前置校验阻止）。
2. 不做批量删除、不做运行单条删除。
3. 不改任务 `request_key` 与创建幂等语义。

## 3. Done：成功标准

| 编号 | 可观察的验收条件 | 核对方式 | 来源/确认人 |
| --- | --- | --- | --- |
| AC-01 | 修改任务规格成功后列表/详情返回新规格，版本+1，写审计；旧运行详情仍显示旧规格 | 服务测试 | 用户 |
| AC-02 | 修改校验与创建一致：范围超授权/完成目标非法/缺字段拒绝；版本冲突提示刷新 | 服务测试 | 用户 |
| AC-03 | 无未结束运行、无过程数据、周期已暂停的任务可删除；definition/task/run/event/artifact 级联清零，先写 DELETE 审计 | 服务测试 | 用户 |
| AC-04 | 周期未暂停、存在未结束运行、存在过程数据的任务删除被拒且数据不变，错误信息说明原因与替代操作 | 服务测试 | 用户 |
| AC-05 | 无 `agent:manage`/`agent:task:operate` 权限分别被 403/403 | 服务测试 | 用户 |
| AC-06 | 前端任务列表提供"编辑/删除"入口（编辑复用任务表单，删除二次确认），构建通过 | 前端构建 | 用户 |
