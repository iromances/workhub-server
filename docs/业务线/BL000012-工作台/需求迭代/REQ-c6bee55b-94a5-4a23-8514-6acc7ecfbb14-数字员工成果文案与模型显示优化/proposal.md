## 1. Why：背景与问题

- 当前问题及证据：数字员工「任务成果」弹窗存在两句说明性文案（运行概况区的「执行状态不代表业务健康或产物验收通过」、历史运行侧栏的「初次优先展示当前页最近完成的报告」），用户认为多余要求删除；同时员工列表「AI / 模型」列、运行信息详情与下载报告把供应商信息（接入名/通道类型/接入配置版本）与模型名组合展示，用户要求页面只显示模型名。注意：两句文案与「运行信息」折叠详情均产生于 2026-11-22 工作区未提交的结构化报告改造，HEAD（`210002f`）中仅有「本次 AI：…」行与「AI / 模型」列。
- 受影响用户/角色：数字员工使用者（`agent:view`）、任务操作人（`agent:task:operate`）。
- 不解决的后果：文案冗余影响阅读；供应商细节暴露在业务页面无必要。

## 2. What：目标与范围

### 本期目标

1. 删除「执行状态不代表业务健康或产物验收通过」页面文案，及下载报告元信息中「（不代表业务健康或验收通过）」后缀。
2. 删除「初次优先展示当前页最近完成的报告」页面文案。
3. 全系统检查后，页面显示只保留模型名；涉及位置：员工列表「AI / 模型」列、任务成果「运行信息」行、下载报告元信息行。

### 本期交付范围

1. `workhub-web/src/views/agent/AgentRunPanel.vue`：删运行概况免责 span、删报告后缀、运行信息行与报告元信息行改为仅模型名（无模型分别显示「未记录模型」/省略该行），清理 `.run-status-note` 样式。
2. `workhub-web/src/views/agent/AgentWorkbenchView.vue`：删历史提示 p 与 `.history-hint` 样式（列表补 `margin-top` 防塌陷）、「AI / 模型」列改「模型」列仅显示 `configuration.model`（空显示「使用接入默认模型」）、删除无引用的 `providerName()`。

### 明确不做

1. API 请求/响应中的 `providerConfigId` + `model` 字段与类型定义不变（用户明示服务端交互可保持）。
2. `AgentConfigDialog.vue` 配置表单仍选择 AI 接入 + 模型（录入而非展示）。
3. `AiConfigView.vue` 系统管理页仍以供应商为主体展示（接入配置管理的本身用途）。
4. 后端代码不变；`AgentInspectionService.java` 的 `interpretation` 是给模型读的工具返回 JSON 字段，非页面文案，不动。
5. 清单第 4 条为空，本期忽略。

### 约束与依赖

- 依赖的代码和文档：依赖工作区未提交的结构化报告改造（`AgentReportView`、`structuredAgentReport.ts` 等未跟踪文件），两目标文件的既有 WIP 随本次一并提交。
- 业务/合规约束：仓库安全规范（不安装依赖）；用户要求独立分支、合并前汇报。
- 既有系统/接口/数据约束：无 API、数据库变更。
- 外部依赖与前置条件：无。
