# WorkHub 业务线归档指引

上级：[仓库指引](../../AGENTS.md)。需求与材料由 WorkHub 仓库统一维护，知识库仅保留研发规范、模板与工作流。

## 正式目录

- 各业务线统一归档在 `docs/业务线/{业务线编码}-{业务线名称}/`；WorkHub 平台自身即业务线 `BL000012-工作台`：
  - 业务线现状：`现状.md`。
  - 研发进展：`迭代日志.md`。
  - 历史需求：`需求迭代/`，含 SDD（Proposal、Design、Tasks）、验证证据与已确认研发评估；研发评估按 `需求迭代/{项目名称}/{年份}/{审批编号}-{需求名称}/研发评估.md` 归档，WorkHub 平台需求的 SDD 按 `需求迭代/{需求编码}-{需求名称}/` 归档。
- 支付中台（原共享支付系统，`xxt-pay`、`intf-paychannel` 等跨业务线公共系统）无业务线编码，材料按同样结构归入 `docs/业务线/支付中台/`。
- 已确认自动评估索引：`docs/业务线/index.md`。
- 需求原件与附件以数据库为权威存储，AI 经 MCP `get_intake_detail` / `get_intake_attachment` 空中读取；仓库不做原始材料文件归档。
- 自动分析、澄清回复与过程调整保留系统历史，并归入仓库 `docs/notes.md`；不写入知识库 `notes.md`。
- 具体业务代码仍在经核实的业务线仓库维护；WorkHub 平台源码即本仓库。

## 归属与历史

- 建档前按编码和名称核对唯一正式目录，沿用既有需求编码、审批、历史版本和证据；不得在知识库重建副本。
- 跨 WorkHub 前后端的需求复用本目录，规格注明各仓库范围；不因迁移重置已确认状态。
- `历史版本/`、原始附件和快照按原字节保留；其中旧路径表示记录当时位置，可按 git 历史定位。历史指引快照不作为现行指令。
- Proposal、Design、Tasks 与 ADR 采用 [共用 SDD 流程](</Users/aslight/Documents/ObsidianMapping/Asset Obsidian Vault/schema/研发/SDD/流程.md>)，模板路径中的归档位置以本页为准。
