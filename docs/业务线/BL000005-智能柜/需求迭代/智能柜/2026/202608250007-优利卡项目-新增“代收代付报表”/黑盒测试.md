## 4. 缺陷与风险

| 编号 | 级别 | 类型 | 描述与证据 | 建议 |
| --- | --- | --- | --- | --- |
| R-01 | P0 | 部署/任务 | TEST 的 51、52、53 三个 XXL-Job 管理端各显示 86 个任务，均无 `collectionPaymentReportGenerateJob` / `collectionPaymentReportRewashJob`；2026-07 报表修改时间 2026-11-05 14:31:25，无法确认由正常调度生成 | 创建两个任务并绑定 ol-saps 执行器；正常任务建议 `0 0 0 1 * ?`（Asia/Shanghai）；补测生成、跳过、重洗、历史回填、并发锁 |
| R-02 | P1 | 功能 | 两笔提现的 `paymentMode` 均为 null，页面显示“—”，导出为空；V1.2 要求关联支付信息得到线上/线下 | 补齐提现支付方式关联；补测线上/线下及对账单付款方式 |
| R-03 | P1 | 数据口径 | 仅生成 2026-07，期初为 0；经销商 C175969ZER6P8 仅有 2.00 提现、无 7 月收入，期末 -2.00；2026-05/06/08/09/10 缺失但 2026-07 仍为 COMPLETE | 确认优利卡业务开始月份及首月期初初始化；如业务早于 7 月，回填历史月份并重算；评估首月负结余是否可接受 |
| R-04 | P1 | 口径待确认 | 直接展业订单 AP260701151538000001 无代理人，报表将首笔款/厂家科目归经销商 A7；V1.2 收入表写“缴费单对应申请单的代理人” | 产品确认直接展业订单的归属主体（经销商还是代理人），必要时调整并补用例 |
| R-05 | P1 | 版本可追溯性 | 部署页面实际请求 `/ol-saps/manage/collectionPaymentReport/...`，本地分支 api_list/控制器契约为 `/api/manage/...`；可能是网关重写，也可能是部署版本与本地 `0dad9aab` 不同，尚未确认 | 确认网关路由重写规则与 TEST 部署 commit/前端构建版本；在测试记录中固定制品版本 |
| R-06 | P1 | 设计/重算 | 代码契约：重洗“保留本月期初，不联动其他月份”；V1.2 要求“历史补录及跨月状态更新后应重算受影响月份和后续累计余额” | 构造至少 3 个月数据验证重洗；若确实不联动，修正重算逻辑或书面确认例外 |
| R-07 | P2 | 体验/数据 | 收入 830 条中 544 条为 0.00（65.5%），主要为提前买断账单第 4～12 期；V1.2 未要求剔除零金额行，但明细数量和页面噪音较大 | 确认是否隐藏零金额行，或增加期数/科目列便于识别 |
| R-08 | P2 | 体验 | 同一账单的经销商/厂家科目分别成两行，均显示同一账单号且无科目列；直接展业时两行主体相同，易被误认为重复 | 增加“科目/来源”列或在规则说明中标注；确认是否合并展示 |
| R-09 | P2 | 体验/默认值 | 页面默认最近 6 个已结束自然月（2026-05～2026-10），不是 V1.2 建议的“业务开始月份至当前月份”；首次打开即提示 5 个缺失月份 | 默认区间改为业务开始月份至当前月份，或由后端返回业务开始月份 |
| R-10 | P3 | 体验 | 接口异常时页面曾显示 `Request failed with status code 404` 技术文案 | 统一转换为业务可读提示 |
| R-11 | P3 | 导出格式 | xlsx 元信息表头的同一长文本重复写入每一列，首行阅读体验差 | 合并单元格或单独元信息区域；不影响数据正确性 |

## 6. 结论与下一步
