## 2. 用例设计

### 2.1 对公收款同步（SYN）

前置：交行测试环境可注入收款流水，XXL-Job 拉取任务已配置。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| SYN-01 | 注入一笔对公收款并触发同步任务 | 列表新增一条记录，交易流水、金额、付款/收款账号与户名、转账备注、交易时间、项目归属与注入一致 |
| SYN-02 | 同一银行流水号重复返回（重复拉取/重试） | 仅落一条记录，不重复核销（唯一键幂等） |
| SYN-03 | 连续两个周期同步 | 按时间游标增量拉取，不漏单、不重复 |
| SYN-04 | 指定历史时间窗口补拉 | 窗口内流水全部入库，游标正确推进 |
| SYN-05 | 接口超时/返回银行错误码 | 重试并告警，游标不推进，无脏数据入库 |
| SYN-06 | 单窗口超过单页数量 | 分页拉全，无丢笔 |

### 2.2 自动核销匹配（MATCH）

前置：各项目存在可核销的缴费单、客户账单、设备厂家对账单及带附言码的支付流水。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| MATCH-01 | 缴费单三要素一致（转账备注=附言码、付款户名=用户名称、金额=支付总金额） | 自动核销：收款状态“已入账”、入账方式“自动入账”、操作员 admin；入账明细生成（入账类型=缴费单、关联业务单号、入账金额）；缴费单按原核销规则结清 |
| MATCH-02 | 客户账单三要素一致 | 同 MATCH-01，入账类型=客户账单，账单结清 |
| MATCH-03 | 对账单三要素一致（备注包含对账单编号、付款户名=厂家名称、金额=应收总金额） | 同 MATCH-01，入账类型=对账单，对账单结清 |
| MATCH-04 | 附言码/备注不一致 | 不核销，挂账提示“付款转账备注无法匹配业务” |
| MATCH-05 | 金额不一致 | 挂账提示“付款金额不匹配” |
| MATCH-06 | 付款户名不一致 | 挂账提示“付款账户名称不匹配” |
| MATCH-07 | 转账备注为空 | 挂账提示“付款转账备注为空” |
| MATCH-08 | 无法归属项目的收款 | 挂账提示“未知付款” |
| MATCH-09 | 三要素命中多张候选业务单 | 挂账转人工，禁止自动核销（口径待确认，Q5） |
| MATCH-10 | 核销后核对业务单状态与【入账明细】 | 状态联动与明细记录一致，操作员 admin |
| MATCH-11 | 同一附言码第二笔收款到账 | 第二笔不重复核销，按挂账处理（口径待确认） |

### 2.5 手工入账（MAN）

| 用例 | 操作 | 预期 |

| MAN-01 | 未入账行点击【手工入账】 | 弹窗展示操作流程①发起→②待审核→③入账审核→④已入账，及该笔收款信息、挂账提示、可入账金额 |
