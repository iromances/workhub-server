## 6. Codex 接入配置模型能力

2026-09-23 根据 [Codex 模型能力动态加载需求](</Users/aslight/IDEAWorkspace/workhub-server/docs/requirements/workhub-server/REQ-9209b10e-c3f9-41ac-b2fe-79f9b2cdd442-Codex模型能力动态加载/design.md>)核验本地实现及自动化测试；尚未验证真实账号目录和已登录页面联调，未发布或重启应用。

接入配置 CLI 通道通过 `POST /api/manage/system/ai-provider/codex-models` 查询。后端以当前表单命令、工作目录运行 Codex app-server，通过 stdio 完成初始化并调用 model/list，聚合可见模型及各自推理强度；仅查询目录，不创建任务。接口须有 AI 配置新增、编辑或管理权限。后端本机与运行用户的 Codex 登录、配置决定目录内容；手动刷新只能绕过 WorkHub 的 60 秒缓存，不能承诺强制刷新 Codex 云端目录。单次协议查询限制 10 秒，成功和失败均回收进程。

前端打开含启用 CLI 通道的接入弹框时加载模型，强度随用户选择的模型联动。查询失败、旧模型缺失时保留历史值并提示；新建及改变环境、模型或强度后须加载有效目录再保存。模型和强度使用 Codex 原值保存并传给 CLI，历史全大写强度仅在旧值匹配及执行边界兼容；不将 ULTRA 映射为 xhigh。API 通道及场景编辑器继续沿用现有选项机制，字典和历史数据不迁移。

## 7. 需求录入保存与 AI 识别

2026-10-08 根据[需求规格与验证](</Users/aslight/IDEAWorkspace/workhub-server/docs/requirements/workhub-server/REQ-b6f5532c-e901-42f8-9d00-4ad0bd4f78cd-需求录入保存与AI识别解耦/tasks.md>)核验本地实现与自动化测试，未发布、重启应用或完成运行数据库及页面联调。

`POST /api/intake/upload` 在事务中保存原始需求、录入元信息和附件，提交后异步识别；接口不等待 AI 结果。保存自身的校验、附件存储或数据库提交失败仍报告失败。AI 执行异常、超时或任务提交被拒绝不删除已保存的内容；任务拒绝和后台异常通过独立事务写入 FAILED 与失败摘要，原事务 afterCommit 回调不传播任务拒绝。持续数据库故障时状态可能无法回写，日志提示按需求 ID 核查，已保存的内容不回滚。

状态继续使用 PENDING、RUNNING、SUCCEEDED、FAILED；`POST /api/intake/{id}/enrichment/retry` 在 `intake:ai:operate` 权限下仅重试 FAILED 记录，读取同一 ID 的原文和现有附件，不新建需求或绕过人工确认生成正式工作项。前端列表和详情提供失败重试，录入成功提示明确“需求已保存”。本期无数据库迁移、自动重试或进程重启后的任务恢复机制。

## 8. MCP 堡垒机共享连接

2026-10-09 根据[配置隔离修复与验证](</Users/aslight/IDEAWorkspace/workhub-server/docs/requirements/workhub-server/REQ-718a4a66-bdd6-492d-9fe5-c771ca94b2a3-堡垒机共享连接按配置隔离/tasks.md>)核验本地代码与 69 项相关自动化测试；新版应用的运行验证尚未完成。

资源 catalog 与数据库连接测试将所选堡垒机配置 ID 传入隧道管理器。共享槽以配置 ID 和 SSH 主机、端口、用户共同标识；不同配置即使使用同端点或凭据也分别持有主连接。引用同一配置的多个目标共享主连接，并按目标主机/端口复用转发。旧 catalog 与内联隧道允许缺少 ID，保留原端点共享语义，并与带 ID 的配置隔离。

堡垒机端点、凭据或启用状态更新后，仅在事务提交后失效该 ID 的连接；活跃租约结束后关闭旧连接，不影响另一配置。只改备注和事务回滚不失效。连接关闭归还租约，最后一次业务使用后空闲超过四小时回收；每 60 秒 SSH 心跳、最多三次无响应退出沿用既有参数，凭据变化或连接死亡由下次请求重建，不新增后台登录或数据库心跳。云端同用户并行会话限制与长期空闲效果须另行运行验证。
