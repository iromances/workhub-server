## 1. Why：背景与问题

目前取数交付需要在 DataGrip、独立 Excel 水印程序和 ZIP 加密操作之间切换。用户希望把文件处理能力收进 WorkHub，既能在取数需求中使用，也能让 AI 在收到指令后调用。

已核实的可复用能力：Demo 的 `WorkbookProtector` 是独立 Java API，核心不依赖 Swing 界面；支持普通视图、打印水印、透明文字及自定义属性，采用 Office Agile AES-256 打开密码。Demo 和 WorkHub 的 POI 均为 5.4.1。

需要补足的接入：菜单和权限、较大文件传输、后台处理任务、产物下载、密码访问、需求关联和 MCP 工具。现有上传限制为单文件 20 MB、本次交付文件约 35 MiB，不能直接沿用；现有附件服务使用整文件 byte[] 和数据库 BLOB，也不适合直接承载新的大文件处理链路。

## 2. What：目标与范围

### 本期目标与交付

1. 新增一级菜单“工具”，包含“Excel 水印与加密”和“ZIP 压缩与加密”两个页面，各页可查看处理记录。
2. Excel 页面保留 Demo 的参数与默认值：水印文字、透明度、提取人/审批编号的显示水印、隐藏水印、自定义属性六个独立选项，以及自动/手动打开密码。输出独立加密副本。
3. ZIP 页面支持上传一个或多个文件，生成 WinZip AES-256 ZIP、随机或手动 ZIP 密码、SHA-256 与校验文件。可以直接处理已有打开密码的 Excel，不要求解密 Excel。
4. Excel 页面可勾选“同时生成加密 ZIP”；Excel 密码和 ZIP 密码分别设置、分别展示，自动模式独立生成。
5. 在“数据提取/运维”需求的文件区提供“文件处理”入口，带入需求 ID、审批编号及选中的附件；也允许上传本次导出的文件。记录关联该需求，后续可从详情访问。
6. 向 AI 提供 MCP 工具：准备文件上传、创建 Excel 处理任务、创建 ZIP 任务、查询任务、领取结果和读取密码。AI 在用户指令下处理文件；支持关联需求和不关联需求的独立使用。
7. 大文件走工具专用流式上传/下载和后台队列。每次保留源文件指纹、产物指纹、操作人、来源入口、需求关联、参数摘要、开始/结束时间与验证结果。

### 已确认的调用方式

2026-10-29 用户选择：“在取数需求里提供处理入口，AI 导出文件后也可按指令调用”。因此本期不订阅“审批通过”事件自动处理，不新增自动审批或数据库取数引擎，不修改需求生命周期，不自动验收、完成或对外发送文件。审批编号用于业务关联和追踪，不将录入的审批状态文本视为自动执行授权。

### 本期边界

- Excel 工具沿用组合操作“水印 + 打开密码”；仅接受未加密普通 `.xlsx`。已有打开密码、数字签名、宏文件、已有背景或页眉页脚图片时明确提示原因，不覆盖、不自动移除原对象。
- 独立使用时审批编号可空，相关水印/属性选项禁用，不伪造审批号；提取人必填。关联需求时编号由后端读取，提交值冲突时报错。
- ZIP 生成不解析或执行内部文件，不提供解压任意外部 ZIP 的页面，不接受服务器任意路径或外部 URL。
- 文件内容保持原文，不新增业务脱敏或数据口径计算；数据库只读查询工具的既有脱敏与资源规则保持原职责。
- 不复制 Swing 界面、启动脚本或整个 Demo JAR 到应用运行链路；复用其核心源码和相关测试。

### 拟定默认值（随完整规格确认）

| 项目 | v1 建议 |
| --- | --- |
| Excel 输入 | 单文件最大 100 MiB；覆盖当前约 35 MiB 及 Demo 历史约 57 MiB 场景；核心解包上限继续为单条目 1 GiB、总计 2 GiB |
| ZIP 输入 | 1～20 个文件；单文件最大 100 MiB，总计最大 500 MiB；不接受同名条目覆盖 |
| 水印 | 默认“内部数据 · 禁止外传”、透明度 82%，沿用 50%～90%、最多 120 字符/4 行限制 |
| 身份选项 | 提取人显示默认关；其余五项默认开；审批编号为空时其三项禁用 |
| 密码 | Excel 自动生成 16 位四类字符；ZIP 自动生成 32 位大小写字母和数字；均可手动输入 8～128 位并确认，保留首尾空格 |
| 后台并发 | 1 个处理中任务、最多 8 个待处理任务；满队列明确失败，不阻塞普通 HTTP 请求 |
| 保留时间 | 未消费上传文件 24 小时；处理任务源副本、产物与密码密文成功/失败结束后 7 天清理；运行中任务不清理；审计元数据保留且不保存明文密码 |
| 文件位置 | WorkHub 既有本地存储根目录下的工具专用子目录；数据库保存索引和任务状态，不保存新的大文件 BLOB |

### 约束与依赖

- 不修改用户桌面源程序和源文件，不覆盖现有工作区改动，不安装桌面压缩软件或字体。
- ZIP 拟新增 `net.lingala.zip4j:zip4j:2.11.6`。官方文档支持 AES-256、流处理和 Unicode 文件名；本机 Maven 缓存未找到该依赖，下载须获得用户授权。来源：[zip4j 官方仓库](https://github.com/srikanth-lingala/zip4j)。
- 新增工具参数配置声明及专用文件密码加密主密钥；主密钥不提交代码，缺失时明确禁用任务创建。实现阶段不擅自修改真实环境配置。
- 部署机器需要能显示中文的已有字体；无法显示指定字符则任务失败并报告，不能输出方框水印或擅自安装字体。

## 3. Done：成功标准

| 编号 | 可观察的验收条件 | 核对方式 | 来源 |
| --- | --- | --- | --- |
| AC-01 | 有权限账号可在“工具”菜单进入两个页面，无权限时菜单隐藏且接口拒绝 | 前端操作和后端权限测试 | 用户菜单要求、既有权限体系 |
| AC-02 | Excel 可生成普通视图和每页打印水印、透明文字及自定义属性，六个选项互不影响 | 64 种组合及 OOXML/原生客户端检查 | Demo 能力 |
| AC-03 | Excel 打开密码为 AES-256；正确密码成功，错误/空密码失败；手动密码不被裁剪 | POI 加解密和参数测试 | Demo 能力 |
| AC-04 | 处理前后工作表、单元格类型/值/公式、长标识、共享字符串、样式及非水印部件一致 | 解密后规范化内容哈希与部件核验 | 取数交付完整性 |
| AC-05 | ZIP 为 AES-256，可含多个中文文件名；解压后逐文件 SHA-256 相同；错误/空密码失败 | ZIP 头检查、解压验证及独立客户端验证 | 既有 ZIP 交付方式 |
| AC-06 | 两工具可独立使用，Excel 可接续 ZIP；自动生成的两类密码不同，输出指纹和 `.sha256` 可下载 | 页面与 API 集成测试 | 用户复用要求 |
| AC-07 | 取数需求入口带入真实审批编号、附件和需求 ID；结果关联原需求，不自动改变需求状态 | 需求详情集成测试 | 用户本轮确认 |
| AC-08 | AI 可上传本地文件、提交异步任务、查询并下载原文产物；跨任务越权、过期票据和任意路径被拒绝 | MCP 到 HTTP 传输完整联调 | AI 独立调用要求 |
| AC-09 | 35 MiB 以上文件可经工具通道上传；旧附件上传语义不被放宽；超限与格式冲突明确失败 | 边界及大文件测试 | 已核实上传限制 |
| AC-10 | 失败不留下可下载半成品；重复 requestId 不重复生成；重启后未完成任务可识别为失败并重新发起 | 故障、幂等与重启测试 | 后台任务完整性 |
| AC-11 | 密码不出现在日志、普通任务详情、浏览器持久存储或 ZIP 内；仅授权主体单独读取，访问留痕 | 日志/权限/响应审查 | 文件处理职责 |
| AC-12 | 保留期限可见；到期文件和密码清理，元数据/指纹仍可查；源文件不变 | 清理和指纹测试 | 本规格默认值待确认 |
