## 1. 背景

当前 `AiConfigView.vue` 从 `aiModel`、`aiReasoningLevel` 字典获取 API 和 CLI 的共用选项，不能反映本机 Codex 当前模型能力。CLI 调用还复用了 HTTP 推理强度转换，缺少 `minimal`，并把 `ULTRA` 转成 `xhigh`。

本机 Codex CLI 版本为 `0.155.0-alpha.16`，已通过生成协议 Schema 确认 `model/list` 返回模型、支持的推理强度和默认强度。尚未实际启动 app-server 查询账号模型列表。

## 2. 目标与范围

1. 新建、编辑 AI 接入配置时，为启用的 Codex CLI 通道动态加载模型及其推理强度，支持刷新和失败重试。
2. 采用当前表单中的 CLI 可执行文件和工作目录，读取后端运行机器、系统用户和 Codex 配置所对应的模型目录。
3. 用户切换模型后，推理强度选项按模型联动；模型和强度编码从 Codex 查询、前端选择、配置保存到 CLI 调用全程使用 Codex 原值，显示名称单独处理。
4. 已保存的模型、强度即使未被查询结果包含，也保留并提示，不因打开弹框或刷新自动覆盖。
5. API 通道、AI 场景编辑器、速度模式维持现有行为；此次不实现其他供应商模型发现，不修改字典、不迁移历史配置。

约束：不安装依赖，不自行启动 WorkHub 应用；按既有 SDD 完整规格确认后实施。模型列表代表 Codex 当前提供的目录，不能承诺脱离账号、客户端缓存和网络条件的云端绝对最新状态。

## 3. 验收标准

| 编号 | 可观察的验收条件 | 核对方式 |

| AC-01 | 打开含启用 CLI 通道的接入弹框后，加载该命令、目录对应的 Codex 模型，完成分页并排除隐藏项 | 协议单测、前端验证 |
| AC-02 | 模型变化时只显示该模型支持的强度；原强度仍有效则保留，否则采用返回的默认强度；仅加载数据不改变编辑值 | 前端状态测试 |
| AC-03 | Codex 返回的模型和强度编码在查询响应、前端选项值、保存入库和 CLI 参数中保持一致，不转换大小写，不将 `ultra` 替换为 `xhigh`；历史大写强度兼容单独验证 | 查询、保存与 CLI 调用回归测试 |
| AC-04 | 查询失败、空目录、协议错误或超过 10 秒均有明确失败反馈；原值保留，可重试，无字典伪装成功 | 服务及前端测试 |

| AC-06 | 查询须有接入配置新增、编辑或管理权限；不会执行模型任务或写入接入配置，进程在成功和失败时均回收 | 权限及进程测试 |
| AC-07 | 既有值不在目录时显示提示并保留，可原样保存其他字段；新增或主动更改的模型/强度必须来自本次成功加载的有效组合 | 前端保存验证 |

## 4. v3 补充：移植到 asset / asset-portal

来源：2026-09-24 用户要求“把这套能力移植到asset项目里”。本次为同一能力的跨项目移植，沿用本需求编码和正式规格，保留 v2 的审批及验证记录，不另建一套规格。

目标仓库为 `/Users/aslight/IDEAWorkspace/asset` 与 `/Users/aslight/IDEAWorkspace/asset-portal`，当前分支均为 `codex/dev-20260822`。asset 是个人投资研究与交易辅助项目，不是 `asset-plateform` 消费分期业务线。

移植保留 v2 的功能范围：接入弹框动态查询 Codex 模型与强度、原值保存和执行、缓存/刷新/重试、历史值保留。API 通道、场景编辑器及速度模式保持现有行为；不改交易业务、不迁移数据库、不升级或安装依赖，不启动应用。

适配差异：

1. asset-portal 使用 Vue 2 / Element UI，改造现有 `system/aigateway/index.vue`，不复制 Vue 3 组件。
2. 使用 asset 的 `Result`、`AssetException`、会话认证和模块分层；不引入 WorkHub 的权限框架。
3. 按 asset 前端职责规则，旧大写强度的识别、兼容选项和模型组合校验放在后端；前端只呈现返回选项、管理交互及异步请求状态。
4. 新增或更改 CLI 环境、模型、强度后，后端保存也校验有效组合；环境与组合未变时允许保留原配置并保存其他字段，查询故障不自动换值。
