## 目标与范围

1. WorkHub 需求与验证进入 `docs/requirements/`，原始材料进入 `docs/requirement-sources/`，系统文档进入 `docs/system/`，过程记录进入 `docs/notes.md`。
2. asset 需求及产物进入其仓库 `docs/requirements/`，系统设计、MCP 契约和迭代日志进入 `docs/system/`。
3. 知识库保留研发规范、模板和工作流；修正入口和现行归档规则。投资研究等其他知识不属于迁移对象。
4. WorkHub 自动材料导出、分析追加、正式评估发布、打开方案目录及 MCP 路径说明使用项目文档根目录。知识库配置只负责读取规范和知识上下文。
5. 保留原始附件、来源 manifest、历史原件、既有未提交内容；历史来源路径可继续用于再次归档。

不安装软件或依赖，不执行数据库写入，不发布部署。前端沿用现有“打开开发方案文件夹”入口；新归档不再生成 Obsidian 链接。

## 验收

| 编号 | 可观察结果 | 验证 |
| --- | --- | --- |
| AC-01 | 两仓库文件迁移完整；附件、历史快照与 manifest 原字节一致 | 迁移清单 SHA-256、文件数与 manifest 校验 |
| AC-02 | 新归档、重评、澄清回复和确认发布只写项目 docs，知识库内容不变 | 隔离临时目录集成测试 |
| AC-03 | 旧 raw 路径映射到迁移后的来源；重复归档不重复追加，修订保留旧版本 | 历史路径、并发、幂等回归 |
| AC-04 | 未配置独立目录时从实际 WorkHub 仓库定位 docs；配置错误、知识库内写入、越界和符号链接被拒绝 | 路径与安全测试 |
| AC-05 | 知识库规范与项目文档可分别检索，历史和过程记录不作为当前事实 | 检索回归 |
| AC-06 | 打开方案目录与两种 MCP 入口返回项目文档路径 | 服务及 MCP 单测 |
