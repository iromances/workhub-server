## 1. Why：背景与问题

2026-10-09 通过运行中的 WorkHub MCP 只读核实：堡垒机配置 1（消费分期）和 2（物流平台）共用同一 SSH 主机、端口及用户，分别被 `amp-db-prod` 和 `db-prod` 引用。当前管理器仅以这三个端点字段标识共享连接，认证凭据版本不同时会淘汰同槽旧连接。

09:11:31 至 09:11:38 按“消费分期→物流平台→消费分期”经受控 MCP 执行 `SELECT 1`，每次切换均出现新 SSH 进程和控制 socket；09:12:04 至 09:12:08 连续访问消费分期则复用同一进程。查询均成功。现有进程已设置 60 秒 SSH 心跳，问题表现是跨配置连接替换。此次复现不代表已排除全部网络或云端空闲策略问题。

影响使用相关数据库的 MCP 诊断与定时监测，增加重复认证和连接等待；配置更新也可能使同端点的另一配置失效。

## 2. What：目标与范围

1. 已保存堡垒机配置按 ID 隔离连接；引用同一配置的多个目标仍共享主连接及复用目标转发。
2. 配置更新在事务提交后仅失效该配置的连接，活跃租约按原有语义完成后释放。
3. 在资源 catalog 和数据库连接测试内部调用链传递配置 ID，并兼容旧 catalog 与五参数隧道构造调用。
4. 自动化验证交替访问、同配置共享、定向失效、凭据变化、认证失败隔离及租约生命周期。

本期不修改生产凭据、云端会话策略或数据库结构，不增加数据库心跳任务。60 秒 SSH 心跳、4 小时业务空闲回收和失败请求抑制沿用现有语义。旧 catalog、内联服务器堡垒机等没有配置 ID 的调用保留原端点共享行为，且与带 ID 的连接隔离。

约束：遵守代码风格；保留工作区既有修改；使用已安装的工具与依赖；应用启动、重启须用户针对本次明确授权。正式产物只维护于本目录。
