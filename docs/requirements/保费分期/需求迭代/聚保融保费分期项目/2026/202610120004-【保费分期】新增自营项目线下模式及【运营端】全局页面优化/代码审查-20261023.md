## 3. 已确认问题

### R1 · [P2] 非实名企业编辑提交后修改未保存

**位置：** [AuthEnterpriseServiceImpl.java:357](http://10.10.116.21:10000/scf/scf-order/-/blob/0ea97c7eafd5d8e14116cb0ceefd1dd54366b06c/scf-order-service/src/main/java/com/thchengtay/order/service/impl/AuthEnterpriseServiceImpl.java#L357)，`commitNonRealName()`。

**触发步骤：**

1. 创建并提交一家具备完整资料的非实名企业。
2. 从渠道列表进入编辑，修改邮箱、地址或附件，保留“非实名认证”。
3. 直接点击“提交”；前端调用路径见 [EditDialog.vue:692](http://10.10.116.21:10000/scf/scf_channel_admin/-/blob/17aff6f26b39719d3bf1a2ddcdfb5e5071bbdcf2/src/views/customerManage/businessManage/components/EditDialog.vue#L692)。

**实际结果与原因：** 按统一社会信用代码查到已有企业后，不进入 `auth == null` 分支；`fillEnterpriseFields()` 和 `updateById()` 只在新建分支执行。已有企业仅关联渠道后返回成功，编辑内容没有落库。

**影响与验证：** 操作人员收到成功提示，但后续订单或合同仍取用旧资料。原方法隔离复现中，请求邮箱为 `new@example.invalid`，保存值仍为 `old@example.invalid`，本次更新次数为 `0`。

**修复方向：** 区分按 `authCode` 编辑企业和按证件号复用企业的关联操作；对允许编辑的企业保存本次资料，保留认证状态与归属校验。

**复审标准：** 编辑后直接提交，重新查询能取得新值；纯关联已有企业的操作不会意外覆盖共享资料。

### R2 · [P2] 新增企业保存草稿后无法继续编辑

**位置：** [AuthEnterpriseServiceImpl.java:301](http://10.10.116.21:10000/scf/scf-order/-/blob/0ea97c7eafd5d8e14116cb0ceefd1dd54366b06c/scf-order-service/src/main/java/com/thchengtay/order/service/impl/AuthEnterpriseServiceImpl.java#L301)，`save()` 删除原有渠道关联逻辑后直接返回。

**触发步骤：**

1. 渠道端新增企业，填写有效的统一社会信用代码。
2. 点击“保存”暂存草稿，成功后弹窗关闭。
3. 刷新企业列表尝试继续编辑，再尝试用同一信用代码新增。

**实际结果与原因：** 前端 [EditDialog.vue:669](http://10.10.116.21:10000/scf/scf_channel_admin/-/blob/17aff6f26b39719d3bf1a2ddcdfb5e5071bbdcf2/src/views/customerManage/businessManage/components/EditDialog.vue#L669) 仍调用草稿保存接口。需求分支的 `save()` 不再生成渠道关联，而列表 SQL 仍从 `crm_channel_enterprise` 关联查询并限制当前渠道，见 [ChannelEnterpriseMapper.xml:6](http://10.10.116.21:10000/scf/scf-order/-/blob/0ea97c7eafd5d8e14116cb0ceefd1dd54366b06c/scf-order-dao/src/main/java/com/thchengtay/order/mapper/crm/ChannelEnterpriseMapper.xml#L6)。因此草稿不在列表中；重新新增又会命中企业已存在检查。

**影响与验证：** “保存后稍后继续编辑”的路径中断。相同输入对比基线和目标方法，基线建立渠道关联，需求分支不建立关联。

**修复方向：** 补齐草稿的创建渠道归属、列表查询与继续编辑入口，明确区分草稿可见性和订单进件可选资格。

**复审标准：** 点击“保存”后，当前渠道仍能找到草稿并继续提交；未完成提交的企业不会因此获得不符合需求的进件资格。

### R3 · [P2] 组件名覆盖路由名导致标签导航失败

**位置：** [index.vue:120](http://10.10.116.21:10000/scf/insurance_admin/-/blob/f3fd9f6ee1818ee22a482e1723e3f6a4e9dbf0fb/src/layout/components/TagsView/index.vue#L120)，`addTags()`。

**触发步骤：**

1. 打开个人用户详情，产生已访问标签。
2. 打开其他页面后关闭当前标签，触发返回详情标签；或对详情标签执行“关闭其他”。

**实际结果与原因：** 路由注册名称为 `personalUserDetail`（[routers.js:67](http://10.10.116.21:10000/scf/insurance_admin/-/blob/f3fd9f6ee1818ee22a482e1723e3f6a4e9dbf0fb/src/router/routers.js#L67)），组件名为 `PersonalUserDetail`（[detail.vue:192](http://10.10.116.21:10000/scf/insurance_admin/-/blob/f3fd9f6ee1818ee22a482e1723e3f6a4e9dbf0fb/src/views/client/personalUser/detail.vue#L192)）。新增逻辑用组件名覆盖标签的 `name`，随后 [closeOthersTags():173](http://10.10.116.21:10000/scf/insurance_admin/-/blob/f3fd9f6ee1818ee22a482e1723e3f6a4e9dbf0fb/src/layout/components/TagsView/index.vue#L173) 和 [toLastView():189](http://10.10.116.21:10000/scf/insurance_admin/-/blob/f3fd9f6ee1818ee22a482e1723e3f6a4e9dbf0fb/src/layout/components/TagsView/index.vue#L189) 将完整标签对象传给 `router.push()`。

Vue Router 3.0.2 在对象具有 `name` 时优先按名称匹配，即使同时具有 `path`；该名称不存在时返回无匹配路由。依据：[框架匹配源码](https://github.com/vuejs/vue-router/blob/v3.0.2/src/create-matcher.js#L29-L36)。

**影响与验证：** 组件名和路由名不同的页面可能无法通过这些标签操作正常导航。原组件方法隔离复现中，传给导航的名称为未注册的 `PersonalUserDetail`。

**修复方向：** 保留真实路由 `name`，将 keep-alive 使用的组件名存入独立字段，并同步调整缓存增删逻辑。

**复审标准：** 覆盖路由名与组件名一致、不一致两类页面，检查标签切换、关闭当前、关闭其他、刷新，以及列表查询条件保留。

### R4 · [P2] 线下声明书未接入运营端附件列表

**位置：** [SelfOperatedOrderService.java:1103](http://10.10.116.21:10000/scf/scf-order/-/blob/0ea97c7eafd5d8e14116cb0ceefd1dd54366b06c/scf-order-service/src/main/java/com/thchengtay/order/service/application/v2/SelfOperatedOrderService.java#L1103)，`saveCompanyAttachment()`。

**触发步骤：**

1. 渠道创建线下订单，成功上传《授权委托暨业务合作声明书》。
2. 运营人员打开该订单的附件列表查看材料。

**实际结果与原因：** 新接口将文件保存到 `amp_attachment`，通过 `source_table=amp_application`、订单 ID 和类型 `246` 关联。运营端仍调用 `/api/contract/queryLoanAllAttachment`；该接口对自营订单分流至 `getContracts()`，见 [ApplicationContractController.java:148](http://10.10.116.21:10000/scf/scf-order/-/blob/0ea97c7eafd5d8e14116cb0ceefd1dd54366b06c/scf-order-controller/src/main/java/com/thchengtay/order/controller/ApplicationContractController.java#L148)。

[getContracts():1130](http://10.10.116.21:10000/scf/scf-order/-/blob/0ea97c7eafd5d8e14116cb0ceefd1dd54366b06c/scf-order-service/src/main/java/com/thchengtay/order/service/application/v2/SelfOperatedOrderService.java#L1130) 仅汇总客户、企业认证资料及签约流程文件，没有读取新增的订单级 `246` 附件；运营端也未调用新增的 `/company/attachment` 查询接口。

**影响与验证：** 声明书能上传并通过必传校验，但运营人员无法从既有订单附件入口查看。此项通过静态调用链确认，未做环境页面操作。

**修复方向：** 将订单级 `246` 附件接入运营端现有查询，保留名称、地址、类型及分组信息。

**复审标准：** 新增、替换声明书后，运营端对应订单能查看最新附件；图片和 PDF 均有可用的查看入口。

### R5 · [P2] 项目停用线下模式会隐藏历史订单附件

**位置：** [CompanyInfo.vue:237](http://10.10.116.21:10000/scf/scf_channel_admin/-/blob/17aff6f26b39719d3bf1a2ddcdfb5e5071bbdcf2/src/views/order/components/CompanyInfo.vue#L237)，`applyEnrollmentMode()`。

**触发步骤：**

1. 订单按模式 `2`（线下签约）完成进件并上传声明书。
2. 后续项目配置调整为只允许模式 `1`（线上签约）。
3. 在渠道端查看原线下订单的单位信息。

**实际结果与原因：** 函数用项目当前允许列表校验订单原模式；原模式不在列表中时，将组件的 `enrollmentMode` 清空。该逻辑也用于查看已有订单。声明书区域以 `enterprise.enrollmentMode === '2'` 为显示条件（[CompanyInfo.vue:91](http://10.10.116.21:10000/scf/scf_channel_admin/-/blob/17aff6f26b39719d3bf1a2ddcdfb5e5071bbdcf2/src/views/order/components/CompanyInfo.vue#L91)），因此历史附件被隐藏。

**影响与验证：** 项目未来进件范围的调整改变了历史资料可见性。原函数隔离复现输入为订单模式 `2`、当前允许列表 `['1']`，结果为显示模式空字符串、附件区域不可见。

**修复方向：** 查看历史订单时使用订单持久化的模式；项目可选范围限制用于新建或允许修改模式的流程。

**复审标准：** 项目改为仅线上后，历史线下订单仍展示原模式与声明书；新建订单只允许当前配置的模式。
