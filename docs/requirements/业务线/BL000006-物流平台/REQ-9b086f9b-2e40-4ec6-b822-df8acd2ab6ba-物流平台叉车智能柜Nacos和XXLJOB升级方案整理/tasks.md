## 2 核心验证锚点

| 对象 | 正向验证 | 反向或边界验证 |
| --- | --- | --- |
| 调度入口 | 官方 MethodJobHandler 正确接收合法参数，原业务调用保持一致 | 空参数、非法 JSON、无数据、旧方法返回 null、抛异常后再次触发，结果不被误报成功 |
| 失败返回与手工方法 | 原失败码/消息映射到中心；手工有参调用保持返回协议 | ol-saps 押金历史生成失败立即停止，不能因改 void 丢失返回码 |
| lease MQ | 参数 DTO 的筛选范围及原 retry 调用一致 | 空参数和错误参数按原约定；不能误变为全量重投 |
| IJobHandler 与自定义基类 | 所有实现与抽象签名一致、handler 注册完整 | 编译覆盖所有子类及测试，旧 execute(String) 不再作为调度实现 |
| Nacos | config 与 discovery 鉴权、共享配置、消费端调用正常 | 凭据错误、gRPC 不通、服务重启、配置刷新及断线重连 |
| 跨线调用 | 同注册域与显式 URL 两类调用分别验证 | 一方切换时另一方仍能调用；共享服务未迁时不能出现服务发现断层 |
| 调度与回滚 | 新中心注册、触发、日志及回调，按启停快照恢复 | 非空令牌不匹配、超时、原停用任务不被启用、新旧中心不同时触发 |
| 构建 | 依赖树及最终包各一份目标 core/client，public 新旧版本正确 | 旧显式版本覆盖、同坐标自定义 JAR、错误父 POM 与跳过的测试被识别 |

支付、结算、账单、短信和补偿入口的集成验证使用经确认的测试数据与环境；隔离测试通过不代替环境验证。测试开关导致跳过时，记录为未执行，不能写为通过。
