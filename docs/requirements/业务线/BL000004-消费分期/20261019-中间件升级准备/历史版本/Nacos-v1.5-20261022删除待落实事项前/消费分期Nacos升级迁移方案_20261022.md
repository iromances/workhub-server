# 消费分期 Nacos 升级迁移方案

版本：v1.5　修订日期：2026年10月22日

适用业务线：消费分期／asset-plateform。

## 一 系统现状与升级目标

| 对象 | 当前版本 | 目标版本 | 执行要求 |
| --- | --- | --- | --- |
| Nacos 服务端 | **1.3.2**； | **2.5.4**； | 单节点，使用独立新库，新实例部署；保留旧实例及旧库供回退 |
| Nacos 客户端 | **nacos-client 1.2.1** | **nacos-client 2.5.4** | 14 个应用服务 |
| MySQL | **8.0.28-231003** | **8.0.28-231003** | 不变 |
| JDK | **Oracle Java 1.8.0_361** | **Oracle Java 1.8.0_361** | 不变 |
| 业务 Spring Boot | **2.2.9.RELEASE** | **2.2.9.RELEASE** | 业务框架版本保持，通过兼容及安全回归 |
| 业务 Spring Cloud | **Hoxton.SR7** |  **Hoxton.SR7** | 不变 |
| 业务 Spring Cloud Alibaba | **2.2.1.RELEASE** | **2.2.1.RELEASE** | 不变 |

## 二 版本升级带来的主要变化

| 变化项 | 升级后的变化 | 消费分期需要处理的影响 |
| --- | --- | --- |
| Nacos 通信方式 | 2.x 客户端使用 gRPC 长连接进行配置及服务发现通信，新增客户端端口 9848，原 8848 仍需保留 | 放通两个端口，检查代理和端口映射；验证配置刷新、服务注册及断线重连。单节点部署方式不变 |
| Nacos 客户端兼容性 | 2.x 客户端不能连接 1.x 服务端 | 14 个后端升级依赖并连接新 Nacos；回退必须同时恢复旧应用包、旧配置和旧服务端，不能只改回旧地址 |
| Nacos 配置与数据库 | 跨大版本涉及存储结构和部署配置变化，不能将旧库原样交给新版本直接使用 | 本方案采用新实例、新库，按 2.5.4 建表，再迁移配置并核对 namespace、group、dataId；现有管理账号及权限按原状迁移。配置业务内容和服务名称保持。该方案属于新环境迁移，不是原实例直接覆盖升级 |

业务 Java 8、Spring Boot、Spring Cloud 和 Spring Cloud Alibaba 版本保持，升级 nacos-client 后验证依赖、启动、配置和服务发现兼容性。本次不开启应用鉴权，不新增账号密码或密钥。

## 三 升级步骤

### 步骤 1 准备新环境

1. 新建单节点 Nacos 2.5.4，按单机模式运行，连接独立新 MySQL 空库。用 2.5.4 自带 `mysql-schema.sql` 初始化表结构，完成旧数据迁移；导入完成前新 Nacos 保持停止，目标表保持为空。

### 步骤 2 改造各业务应用

1. **添加客户端依赖。**在各应用根 `pom.xml` 的 `<dependencies>` 中直接添加以下依赖，Alibaba BOM 均不修改，

   ```xml
   <dependency>
       <groupId>com.alibaba.nacos</groupId>
       <artifactId>nacos-client</artifactId>
       <version>2.5.4</version>
   </dependency>
   ```

2. **修改 Nacos IP 和端口。分别修改生产配置中的 `spring.cloud.nacos.config.server-addr` 和 `spring.cloud.nacos.discovery.server-addr`。若地址由启动参数或环境变量覆盖，同步修改实际生效值。`server-addr` 填主端口（默认 `8848`），不要填 gRPC 端口；默认还需放通客户端到新 Nacos 的 `9848`，非默认主端口时按主端口加 `1000` 核对 gRPC 连通性。保留 namespace ID、group、file-extension、prefix、shared-configs／extension-configs 和 refresh，不新增 username、password 或密钥。地址和端口落实前不完成最终发布配置冻结。

## 四 实施前待落实事项
| 编号 | 待落实事项 | 责任方 | 截止条件／缺失时处理 |
| --- | --- | --- | --- |
| D1 | amp-wolease 是否仍需在生产运行 | 业务负责人、应用研发 | 联合演练前确认并冻结发布实例范围 |
| D2 | 新 Nacos 单节点实例及新库的资源与部署位置；应用接入 IP／域名和端口暂未提供 | 运维、DBA、发布负责人 | 单节点方式已确定；环境搭建前落实主机、端口和数据库部署位置，确保新旧环境隔离并保留回退条件 |
| D3 | T41 漏洞名称／编号、对象、端口及复测标准；传输保护的密码算法验收口径 | 安全 | 开发整改前提供；切换前所有适用项有复测结论 |
| D4 | 上线日期、最终维护时段、回退决策人和任务补跑规则 | 发布负责人、业务负责人 | 排期时确定；约 2 小时窗口需容纳实测切换或回退，规则未落实不切换 |

生产切换前落实 D1—D4。各部门指定执行负责人，由发布负责人汇总产物位置、完成日期和验收结果。

其他业务线复用时，参考上述环境准备和应用改造内容，重新核实本业务线的版本、依赖、系统实例、配置和任务；不直接套用消费分期数量。

## 五 安全与日志配置

| 项目 | 要求 |
| --- | --- |
| 管理入口 | 保持现有账号及权限，限制管理网段；不新增应用鉴权、MFA 或口令策略改造 |
| 传输保护 | 管理入口 HTTPS TLS 1.2+；SDK HTTP／gRPC、数据库及代理后的跨主机链路使用 TLS 或受控 IPsec，保留证书／隧道与验证记录；密码算法验收口径见 D3 |
| 日志与审计 | 配置变更、管理操作及运行日志集中采集，至少保留 6 个自然月；落实脱敏、只读审计权限、备份、检索和恢复验证 |
