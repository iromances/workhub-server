# WorkHub 后端实施路线

## 1. 实施目标

后端第一阶段要交付一套可供前端接入的稳定 API 和数据模型，先完成台账闭环，再接外部来源和结构化增强能力。

## 2. 里程碑

### M1. 工程基线

- 初始化 Spring Boot 4 工程
- 接入 MyBatis、Druid、MySQL
- 接入统一异常处理、统一响应、基础日志
- 建立用户登录和 JWT 骨架

### M2. 核心领域

- 用户表
- 项目表
- 迭代表
- 版本表
- 工作项表
- 跟踪记录表
- 状态流转日志表
- 附件表

### M3. 主业务 API

- 登录接口
- 项目管理接口
- 迭代管理接口
- 版本管理接口
- 工作项列表、详情、创建、编辑接口
- 跟踪记录接口
- 状态流转接口

### M4. 收件与整理

- 企微回调接入
- 待整理箱入库
- 审批型结构化字段抽取
- 需求截图/附件上传接口
- 异步 enrichment 状态查询
- 待整理转正式工作项接口

### M5. 通知与稳定性

- 群机器人通知
- 到期提醒
- 幂等控制
- 日志补充
- 初始化脚本与部署说明

## 3. 开发顺序约束

1. 先建领域表和核心 API，再接企业微信和结构化增强。
2. 先实现截图/附件录入闭环，再做自动收件。
3. 先保证正式工作项流程稳定，再扩展通知和提醒。
4. 任何外部集成失败都不能影响核心台账可用性。

## 4. 验收基线

1. 用户可以登录并访问受保护接口。
2. 可以完整管理项目、迭代、版本、工作项。
3. 工作项可以写跟踪记录并做状态流转。
4. 企业微信回调内容可以落入待整理箱。
5. 结构化增强可以补齐审批型需求字段，且结果需人工确认后才能转正式工作项。
6. 状态变更和指派动作可以触发企微通知。
