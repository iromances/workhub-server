# WorkHub 后端实施路线

## 1. 实施目标

后端第一阶段要交付一套可供前端接入的稳定 API 和数据模型，先完成台账闭环，再接外部来源和结构化增强能力。

## 2. 里程碑

### M1. 工程基线

- 初始化 Spring Boot 4 工程
- 接入 MyBatis、Druid、MySQL
- 接入统一异常处理、统一响应、基础日志
- 建立用户登录和 JWT 骨架

### M2. 核心领域

- 用户表
- 项目表
- 迭代表
- 版本表
- 工作项表
- 跟踪记录表
- 状态流转日志表
- 附件表
- 支付渠道、商户、参数、敏感凭据、秘钥、项目绑定、多用途和关联商户关系表

### M3. 主业务 API

- 登录接口
- 项目管理接口
- 迭代管理接口
- 版本管理接口
- 工作项列表、详情、创建、编辑接口
- 跟踪记录接口
- 状态流转接口
- 支付渠道、商户、项目绑定、参数、敏感凭据、秘钥管理接口

### M4. 收件与整理

- 企微回调接入
- 待整理箱入库
- 审批型结构化字段抽取
- 需求截图/附件上传接口
- 异步 enrichment 状态查询
- 需求阶段动作接口
- 需求暂停、恢复和修改历史查询接口
- 需求待办录入、处理状态和处理结果维护接口
- 数据提取/运维类需求 SQL 草稿生成接口
- 系统配置接口
- 研发需求 GitLab 代码影响分析接口
- 研发需求 AI 澄清分析与逐项回复接口
- 研发涉及系统清单接口，包括业务线系统和全局中台系统
- 研发需求项目知识库需求迭代 Markdown 沉淀与辅助检索
- 研发工作项草稿确认创建接口
- 禅道同步预留接口

### M5. 通知与稳定性

- 群机器人通知
- 到期提醒
- 幂等控制
- 日志补充
- 初始化脚本与部署说明
- 可选 ELK 日志监控配置和 Kibana 错误统计说明
- MCP 只读安全通道，覆盖业务线资源定位、知识库/GitLab 摘要、需求管理读取、数据库只读查询和服务器状态/日志诊断
- 运维业务监测，先支持按业务线通过 MCP 只读数据库通道读取 XXL-JOB 运行报表快照，并在详情、手动采集和定时任务中定位失败 Job；MQ 消息监测入口预留
- 运维系统预警，先支持单独维护关注子系统并查询 WorkHub 本地错误事件表；ELK 接入方案后续确认，只作为本地事件数据来源，不改变查询接口
- 支付配置审计日志、敏感凭据维护和秘钥轮换留痕
- GitLab 仓库配置加密存储
- 研发拆解草稿与正式工作项创建留痕

## 3. 开发顺序约束

1. 先建领域表和核心 API，再接企业微信和结构化增强。
2. 先实现截图/附件录入闭环，再做自动收件。
3. 先保证正式工作项流程稳定，再扩展通知和提醒。
4. 任何外部集成失败都不能影响核心台账可用性。
5. 支付配置管理先交付静态配置与绑定闭环，再扩展真实支付网关校验与路由能力。
6. 研发需求先在澄清阶段由 AI 输出逐项待确认项和风险项，人工逐项回复或确认后再自动触发任务评估；任务评估先人工确认总预估工时和测试工时，AI/人工任务拆解作为辅助；需求和任务评估只关联业务线及对应系统，存在任务项时必须选择涉及系统，禁止 AI 跳过人工确认。
7. 禅道同步先保留接口和状态，真实写入需等禅道配置、字段映射和失败重试策略确认后再落地。

## 4. 验收基线

1. 用户可以登录并访问受保护接口。
2. 可以完整管理项目、迭代、版本、工作项。
3. 工作项可以写跟踪记录并做状态流转，暂停时记录暂停原因和暂停日期，并可恢复到暂停前状态。
4. 企业微信回调内容可以落入待整理箱。
5. 结构化增强可以补齐审批型需求字段，且结果需人工确认后才能进入需求阶段流转；需求详情可以暂停和恢复需求、查看修改历史，并维护多条待办、处理状态和处理结果。
6. 数据提取/运维类需求可以生成只读 SQL 草稿，但系统不连接业务库、不执行 SQL，执行前必须人工确认。
7. 研发需求可以按业务线读取 GitLab group 下全部仓库代码，先生成逐项澄清确认项和风险项，澄清完成后生成工作项草稿、改地点、工时和负责人建议；任务涉及系统必须来自业务线系统清单或全局中台系统清单，需求列表和详情可以从任务系统标签汇总出“这个需求改了哪些系统”。至少可人工确认总预估工时和测试工时推进到待排期；只有草稿已关联正式项目 ID 时才创建正式工作项。
8. 状态变更和指派动作可以触发企微通知。
9. 可以按项目、用途查询当前生效的支付商户绑定，并查看脱敏后的参数、敏感凭据、秘钥版本和关联商户关系信息。
10. AI 客户端可以通过主服务内嵌 HTTP MCP runtime 按业务线定位业务线系统清单、全局中台系统清单、GitLab group、知识库路径、数据库目标和服务器目标，按 intakeId 读取需求管理详情并按审批编号/需求名称搜索需求记录，并按业务线、环境、目标资源和权限 profile 执行受控只读数据库查询，以及白名单服务状态、白名单服务日志和白名单日志文件 tail，且所有调用可审计；MCP runtime 不暴露 GitLab Access Token、任意 SSH 命令。
11. 运维菜单下可以维护业务线 XXL-JOB 数据库名，列表默认查看 XXL-JOB Admin 报表快照统计，详情中按日期区间查看原始失败 Job 日志，默认最近一个月；定时任务会扫描失败 Job 并通过站内信预警；MQ 消息监测保留菜单入口，采集能力下一步接入。
12. 运维菜单下可以维护系统预警关注子系统，并按业务线、环境、子系统、级别和时间范围查询本地错误事件汇总与明细；关注子系统不复用项目或 XXL-JOB 配置。
