# SDD 工作流

本文件定义选用 SDD 流程后 AI 参与研发的阶段、产物与审查点。阶段可迭代，不是一次冻结的瀑布流程；变化应从正确的上游层级修订。

## 1. 六阶段工作流

| 阶段 | AI 主要工作 | 人的决策/审查点 | 书中典型产物 |
| --- | --- | --- | --- |
| 需求定义 | 整理背景、目标、范围、非范围、成功标准；追问缺失 | 确认业务意图、范围和完成条件 | `proposal.md` |
| 架构设计 | 基于已确认的需求与已核实的现状起草结构、职责、ADR、非功能约束 | 决定架构与风险取舍 | `design.md` |
| 接口契约 | 列出调用方/提供方、字段、状态、错误和兼容条件 | 确认对外承诺与兼容窗口 | OpenAPI、数据模型等 |
| 任务拆解 | 拆成可独立验收的交付单元，标明依赖和顺序 | 确认任务边界与验收口径 | `tasks.md` |
| 实现 | 逐任务修改代码与测试，对照规格自查 | 审查偏差与重要实现选择 | 代码、测试、迁移等 |
| 验证交付 | 从三层规格推导测试，记录真实结果和残余风险 | 接受或拒绝交付与剩余风险 | 测试、评审及交付证据 |

前一个阶段的输出须足以成为后一个阶段的输入。AI 可以在审查前迭代草案，但不得把“AI 已写完”当成“人已批准”。阶段性确认可合并进行，本目录不额外强制每阶段独立开 PR。

## 2. SDD 流程的需求产物

每个需求使用 `docs/业务线/{业务线编号}-{业务线名称}/{需求编号}-{需求名称}/SDD/`，与原有流程的 `研发方案.md` 和 `测试用例.md` 隔离。业务线与需求编号、名称从系统获取，唯一主目录和跨业务线关联遵守[通用约束](../通用约束.md)，不使用无编号占位目录：

| 产物 | 内容与作用 |
| --- | --- |
| `proposal.md` | 目标、背景、范围、非范围、成功标准、待确认问题；作为业务边界。 |
| `design.md` | 已核实的现状、结构和职责、数据/接口、非功能要求、风险、迁移及回滚；必要时链接 `contracts/` 和 ADR。 |
| `contracts/`、ADR | 复杂接口或重要决策的独立可评审材料；按需创建，不强制凑数。 |
| `tasks.md` | 可验证的交付物、依赖、顺序和验收条件，并追溯 Proposal 与 Design。 |
| `验证记录.md` | 计划与实际执行证据、失败/未执行项、剩余风险；是团队附加记录，不冒充原书主规格。 |

上述 SDD 文件是本流程的正式审查基线，不再强制映射进原有流程的 11 节 `研发方案.md`。有跨服务契约时，在接口的拥有者仓库维护权威定义，SDD `design.md` 给出引用、影响与兼容结论，避免多份冲突副本。

从模板生成需求文档时，规范链接和 ADR 模板链接应按产物的实际位置重新计算相对路径，或替换为真实产物链接；模板原位置可用的链接不能原样带入。尚未生成的可选产物不建立虚假链接，生成后检查所有本地链接是否可解析。

业务线的 `系统现状.md` 与需求目录并列，承载已生效且经过核实的当前事实；需求中的设计、验证和历史决策保留在 `SDD/` 中。系统现状不能用未实施的规格直接替换。

## 3. 阶段推进规则

1. **接收与核实：**确认系统业务线与需求的编号、名称、归属、唯一需求主目录、环境、分支、受影响系统及输入材料；先读取相关 `系统现状.md` 并核实证据，未核实的现状标为待确认。
2. **Proposal 审查：**目标、非范围、验收条件和关键待确认项经人确认后，才把它作为设计边界。
3. **Design/契约审查：**现状证据、职责边界、接口/数据、兼容、失败处理、非功能约束及重要 ADR 可审查。
4. **Tasks 与规格审查：**任务有依赖和可判定的验收；Proposal、Design、契约和 Tasks 达到本次变更所需的完整度，获有权人员确认后才能改代码。
5. **逐任务实现：**读取全局目标、已批准设计和当前任务；一次只实施获准范围，发现偏差先返回规格层。
6. **验证和交付：**逐项对照任务、设计契约和需求成功标准；回填真实测试结果，再由有权人员判断交付。已经生效且核实的事实更新到所属业务线 `系统现状.md`，注明核对时间和来源。

“规格 PR 先于代码 PR”是书中对新功能的建议，不是此处额外设立的唯一提交方式。小型缺陷修复可按实际影响采用较轻的规格表达，但不得绕过本流程的规格确认及通用授权要求。

## 4. 轻量化使用

探索性原型可先做只读分析，方向确定后再固化规格；存量系统先为本次变更范围补规格，不要求一次补写整个系统。紧急修复、一次性脚本或高不确定性研究可以按风险缩减辅助文件，但**不能减免通用安全、授权与规格确认要求**。适用范围不明时，向用户说明并请其决定。
