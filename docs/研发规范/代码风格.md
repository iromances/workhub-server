# 代码风格

适用于采用本规范的项目及其协作范围内的代码修改。编写前读取，交付前自查；

## 1. 基于事实，只写必要代码

- 先核对调用方、接口契约、参数与返回值约定、已有校验、框架行为及异常处理，再增加分支、校验、兜底或抽象；上下文不清楚时先定位核实，不用猜测性的判断或默认值掩盖不确定性。
- 已由可信入口、类型约束、数据库约束或明确契约保证的条件，不在内部调用链重复检查；省略前确认约束覆盖所有相关调用路径，不凭方法名或习惯推断。
- 不将应暴露的错误转换为成功、空集合、零值或其他默认值。异常沿用既有机制，只有当前层确需恢复、转换或补充必要上下文时才捕获；不添加无依据的宽泛捕获、重试、备用路径或兼容分支。
- 优先复用现有能力，不夹带无关重构，不为尚不存在的复用、扩展或兼容需求新增工具类、接口、配置或框架；精简不得降低可读性或改变业务语义。
- 保留有依据的外部输入校验、权限、业务状态、数据完整性、事务、并发和幂等保护。外部依赖失败按明确契约处理；重复执行不得静默制造重复数据或破坏记录。

## 2. 提前处理边界

- 在正常流程前完成当前函数职责内必要的参数校验、边界和退出条件处理；无需继续时按契约提前返回，非法参数或状态沿用既有异常机制，不伪装成功。
- 判断顺序须符合业务语义，不因提前退出跳过必要校验或操作。
- 依赖查询结果或中间状态的检查，在取得必要数据后、后续操作前执行；不为形式上的“全部前置”重复查询、改变必要顺序或增加已由上下文保证的检查。
- 正常逻辑按业务步骤顺序展开，避免多层嵌套，不将可提前完成的校验留到业务处理之后。

## 3. 工程边界与表达

- 工程结构、模块职责和已有约定以核实后的目标分支代码为准，结合项目指引实现，不将其他项目的模块或存储约定直接套用。
- 前端负责交互、呈现、输入收集、表单与页面状态、轻量展示格式化及操作编排；后端负责业务规则、计算、数据聚合、校验、状态、权限、持久化及外部交互。
- 命名、注释、数据类型与精度遵循目标项目约定；外部调用明确失败处理，不记录敏感配置，测试不默认依赖真实网络。

## 4. 交付前自查

- 新增校验、分支、兜底和抽象均有当前需求、真实调用路径或明确约束作为依据。
- 无重复校验，无默认值或异常捕获掩盖错误；必要的安全、业务和数据完整性保护仍完整。
- 边界与退出顺序正确，未跳过必要操作；正常流程清晰，行为、模块职责与数据精度符合项目约定。
