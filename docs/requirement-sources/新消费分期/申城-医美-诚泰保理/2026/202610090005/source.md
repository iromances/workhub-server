一 需求概述
本文档说明先行通支付平台支付网关及对外接口的产品目标、功能范围、业务流程和验收要求。通过统一接入入口，向业务系统提供代付申请、结果查询、账户流水、账户余额及银行回单查询能力，其中代付申请支持集团公司内部下拨和普通转账，配套接口支持状态跟踪和资金核对。
业务归属：先行通设备科技（上海）有限公司。主要使用方为接入支付平台的业务系统及其开发、运维人员；财务及业务运营人员通过接入系统使用查询结果和银行回单。
二 建设背景与目标
业务系统调用支付能力时，需要统一的接入规范、安全校验及结果处理方式。支付网关承接对外请求并完成接入校验，支付平台提供标准化业务接口，使接入方能够按照统一规则使用支付能力，减少重复对接工作。
本次目标是形成从代付发起到结果获取、资金核对及回单获取的完整使用流程，同时通过商户和应用识别、IP 白名单、签名校验及重复申请校验，控制接口访问和重复提交。
三 本次功能范围
功能 主要能力 业务用途
支付网关 统一入口及接入安全校验 规范接入和访问控制
代付申请 支持内部下拨及普通转账，重复申请提示 集团内部资金下拨及日常转账付款
代付结果查询 按商户订单号或支付流水查询 跟踪单笔代付状态
账户交易流水查询 按日期区间查询当日或历史流水 核对账户收支明细
代付账户余额查询 查询可用余额与冻结余额 了解代付账户资金情况
银行回单查询 查询代付订单对应的回单地址 获取交易凭证

范围说明：本次围绕支付网关和上述五项接口开展。批量代付、收款、退款、财务记账及新增业务操作页面不列入本版本范围；各渠道的具体支持能力以接入配置和联调确认为准。
四 业务流程
4.1 接入准备
平台为接入方分配商户标识和应用标识，完成密钥、证书及访问来源 IP 白名单配置。接入方按统一规范生成请求签名，通过 HTTPS 调用接口，使用 JSON 传递业务数据。测试环境与生产环境分别配置。
本次接入使用交通银行保理公司账号 310066580018800046419，前置机环境复用账号 310066771018800024309 的现有前置机环境。
4.2 代付主流程
1. 业务方根据集团公司内部下拨或普通转账场景，生成唯一商户订单号，填写金额、收款账户、代付类型及渠道要求的转账模式，提交单笔代付申请。
2. 支付网关校验请求完整性、商户及应用信息、应用状态、来源 IP、请求唯一性和签名。校验未通过时，拒绝请求并返回对应错误信息。
3. 支付平台校验商户订单号，受理有效代付申请并返回订单状态及相关流水信息。相同商户订单号重复提交时，提示重复申请，不返回首次受理结果；业务方需通过代付结果查询接口获取原订单状态。
4. 业务方通过代付结果查询接口主动查询后续状态，获取最终处理结果。代付最终结果以订单状态为准，不能仅依据接口调用成功判断付款成功。
5. 业务方按需要查询账户余额、交易流水和银行回单，完成资金核对及凭证获取。
五 功能说明
5.1 支付网关
提供统一对外访问入口，所有接口采用 HTTPS、POST 和 JSON。根据商户及应用信息识别接入方，校验应用状态、IP 白名单、数字签名和请求唯一标识，对不符合接入规则的请求返回明确错误信息。接入方按错误原因修正后重新调用。
5.2 单笔代付申请
代付申请支持集团公司内部下拨和普通转账两类业务场景，均通过单笔代付接口发起，并使用统一的重复申请校验和结果查询机制。重复提交时提示重复申请，原订单状态通过结果查询接口获取。
集团公司内部下拨：用于集团公司向所属成员单位下拨资金，按已配置的集团账户关系和渠道规则提交付款信息，满足集团内部资金下拨需求。
普通转账：用于向指定收款账户发起日常转账付款。业务方填写收款账户、金额及交易附言等信息，平台通过适用渠道处理转账。
提交时需提供唯一商户订单号、金额、收款账户、代付类型及账户属性。代付类型包括代付到银行账户和代付到渠道商户；两类业务场景的参数填写及可用渠道以接入配置和联调确认为准，渠道未指定时使用平台默认渠道。
申请返回订单状态及相关流水、金额和手续费等信息。交行渠道需按接口要求填写转账模式，其中下拨对应下拨（请款）；普通转账的参数按适用渠道规范填写。
5.3 代付结果查询
支持按商户订单号或支付流水查询单笔代付结果，二者至少填写一项；同时填写时按两个条件共同匹配。查询结果包括订单状态，并可包含渠道流水、金额、手续费、交易时间及处理信息。未查询到订单时返回失败及订单不存在提示。
5.4 账户交易流水查询
按开始日期和结束日期查询渠道账户交易流水，支持账户筛选及分页。平台根据日期范围处理当日或历史流水查询。返回交易时间、金额、收付款账户、交易后余额、摘要及渠道流水等可用信息，供业务方核对账户收支。
5.5 代付账户余额查询
查询代付账户的可用余额和冻结余额，并可返回渠道、币种及查询时间。业务方可据此了解账户资金情况；余额查询本身不发起付款，也不构成资金预留。
5.6 银行回单查询
按商户订单号或支付流水查询银行回单，二者至少填写一项。返回回单文件地址及相关流水信息。回单地址为空表示凭证尚未下载或回单不存在，接入方应展示相应提示；未匹配到订单时，接口文档约定返回字段为空的对象。

检查项 验收要求

代付与重复申请 分别验证集团公司内部下拨和普通转账，核对收款账户、金额和处理结果；同一商户订单号重复提交时，应提示重复申请，不返回首次受理结果。通过结果查询接口可获取原订单状态。

异常与接入 缺失必要业务参数、订单不存在及调用异常等场景提示明确；完成指定接入方和渠道的端到端联调。

# 2. 开发规范

## 2.1 通信地址

测试环境：https://test-xxtpay-gateway.thchengtay.com

生产环境：https://xxtpay-gateway.thchengtay.com

## 2.2 通信协议

由先行通支付平台提供接口地址，业务接入方调用。

采用 HTTPS 协议进行请求和响应的处理。所有接口均采用 POST 请求方式，接口响应返回 JSON 格式的数据。

接口未注明处均使用 UTF-8 编码。

## 2.3 通信安全

平台按接入方分配唯一商户标识 merchantNo 和应用标识 appId，接入方需在请求头中携带商户标识与应用标识，平台侧按应用维度校验应用状态与访问来源 IP 白名单。

为保证数据传输过程中的数据完整性和真实性，需要对数据进行数字签名，在接收签名数据之后进行签名校验，默认签名算法为 SHA256withRSA，摘要算法为 SHA-256。测试环境接入时，平台会为接入方分配唯一的平台商户标识 merchantNo、对应的商户密钥 secretKey，以及私钥证书和证书对应密码。签名使用私钥（.pfx），验签使用公钥（.pem）。生产环境由接入方生成密钥对，提供给平台方 2048 位的 PKCS12 格式的公钥（.pem）。

签名流程：

将完整的请求 body 中的数据进行排序。排序规则为字段名的字典序正序排序（a-z），然后转为 UTF-8 编码的字符串，将排序之后的字符串使用数字证书进行签名，将签名后得到的字节数组以 base64 编码方式得到的字符串值通过 signedMsg 在请求头中传递。

接入方的请求服务器需配置 IP 白名单，不在白名单中的服务器将被拒绝请求。

## 2.4 通信规范

除特殊约定外，所有接口的请求和响应的返回信息均以 JSON 字符串形式返回，HTTP 请求内容类型 `Content-Type = application/json`。

除特殊约定外，所有接口的 HTTP 请求头中均需包含以下字段：

| 字段名称 | 字段释义 | 字段格式 | 是否必须 | 备注 |
|----------|----------|----------|----------|------|
| merchantNo | 商户标识 | String | 是 | 平台分配 |
| appId | 应用标识 | String | 是 | 平台分配 |
| secretKey | 商户密钥 | String | 是 | 平台分配 |
| signedMsg | 签名值 | String | 是 | 请求体签名值 |
| timeStamp | 时间戳 | Long | 是 | 当前时间戳 |
| requestId | 请求唯一ID | String | 是 | 单次请求唯一 |

业务字段数据在请求 body 中以明文的 JSON 格式进行传递。详细业务数据字段参见[3. 业务相关接口](#3-业务相关接口)。

网关层校验未通过时，HTTP 请求状态码 status code 遵从行业技术规范，以下 code 有特殊含义：

| HTTP 状态码 | Body 中的 code | 释义 | 备注 |
|-------------|----------------|------|------|
| 401 | 000401 | 请求头不完整 | 请求头参数缺失 |
| 403 | 000403 | 服务器拒绝请求 | 请求 IP 非白名单 |
| 405 | 000405 | 请求方法不支持 | 请求 method 不是 post |
| 400 | 000600 | 请求 ID 已存在 | requestId 不唯一 |
| 400 | 000601 | 商户信息不存在 | merchantNo 和 secretKey 无对应商户 |
| 400 | 000602 | 签名验证失败 | signedMsg 验证失败 |
| … | 无 | 其他未说明状态码 | |

除特殊约定外，所有接口的返回 body 中均含有以下字段：

| 字段名称 | 字段释义 | 字段格式 | 是否必须 |
|----------|----------|----------|----------|
| code | 返回码 | String | 是 |
| message | 返回信息 | String | 是 |
| data | 具体业务数据，详见各个业务接口 | Object | 是 |

业务处理结果的 `code` 取值说明：

| code 值 | code 说明 | 备注 |
|---------|-----------|------|
| 200 | 请求成功 | 业务数据在 data 中返回 |
| 非 200 | 处理失败 | message 返回具体失败原因 |
