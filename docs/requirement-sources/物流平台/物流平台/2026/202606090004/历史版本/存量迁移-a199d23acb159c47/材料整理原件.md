1 需求背景与目标
1.1 需求背景
我方原通过通联支付进行收款，收款主体为“通汇诚泰商业保理（天津）有限公司”。根据监管要求，收款主体必须变更为“先行通数字科技有限公司”。
现有业务依赖两个核心支付能力：
代扣支付：存量用户已通过通联支付完成银行卡签约绑定，我方后台可直接调用通联快捷支付接口，从用户绑定的银行卡扣款。
主动支付：用户在微信/支付宝小程序内主动发起支付，原流程为在小程序内直接拉起微信/支付宝支付（通过通联返回的JSAPI/支付参数），现需改为跳转至通联收银台小程序完成支付，支付结束后返回我方小程序。
本次切换需将上述两个场景的收款主体均更换为“先行通数字科技有限公司”。 

1.2 需求目标
代扣接口主体切换：调用通联快捷支付接口（代扣）时，使用先行通的商户参数，存量用户协议号不变，支持从已绑卡扣款。
主动支付体验改造：微信、支付宝主动支付统一对接通联收银台小程序（参考文档4.3、4.4节），前端跳转至通联收银台页面，支付完成后返回我方页面。
辅助接口参数替换：退款、交易查询、对账文件下载等接口仅更换主体商户号，业务逻辑不变。
2 核心功能需求
2.1代扣支付（快捷支付）
2.1.1 现有流程
客户账单生成后我方系统触发自动扣款。
我方后台调用通联快捷支付接口，传入商户号、协议号（绑卡签约编号）、扣款金额等。
通联返回扣款结果，我方更新订单状态。
2.1.2 切换后变更点
请求中的商户号等替换为先行通的参数。先行通商户号为660451048165ZZ5
协议号原样传入（通联内部已完成共享协议号，确保可扣款）

2.2 主动支付（微信/支付宝）
2.2.1 现有流程
用户在小程序内点击支付 → 前端调用我方后端下单接口 → 后端调用通联接口获取JSAPI参数 → 前端在小程序内直接唤起微信/支付宝支付。
2.2.2 改造后流程
用户点击支付 → 前端调用我方后端下单 → 后端调用通联收银台统一下单接口（4.3/4.4节）→ 前端跳转至通联收银台小程序 → 用户在收银台完成支付 →用户点击“完成”或自动跳转回我方小程序指定页面 → 我方接收支付结果通知，更新订单。
