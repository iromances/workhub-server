# 回购写表逻辑梳理

## 一句话摘要

资产平台与嘉泰资产平台的回购都围绕账单、结算明细、对账单资源和对账单写数，但两套 SAPS 的落表顺序不同：资产平台通常先把资方/客户账单按回购结算，再生成 `statement_original_resource` 并实时出账；嘉泰资产平台先沉淀 `statement_charge_resource` 计费资源，再由 V2 对账单流程生成 `statement`、`statement_resource`、`statement_fee_detail`，最后回写计费资源和账单状态。

## 资产平台 SAPS

### 回购入口

资产平台存在三类主要回购入口：

1. 自动融资单回购：`FunderBillCompensationRepurchaseSchedule.repurchaseHandleSchedule` 调用 `CompensationRepurchaseBiz.repurchaseHandle(...)`。
2. 融资订单回购：`RepaymentPlanController` 提供商户回购、平台回购及各自试算接口，最终进入 `FunderBillSettleBizServiceImpl.buyBack(...)`。
3. 客户订单回购：`CustomerBillController` 提供客户订单回购及试算接口，最终进入 `CustomerBillSettlementBizServiceImpl.buyBack(...)` 和 `CustomerBillRepurchaseHandle.repurchase(...)`。

### 自动融资单回购识别

`CompensationRepurchaseBiz.repurchaseHandle(projectCode, financeApplicationCode, appointGraceDate)` 负责识别需要回购的融资单：

- 连续代偿触发：读取 `StatementConfig.needRepurchaseProjects`，通过 `repaymentPlanService.needRepurchasePlans(...)` 查找连续代偿达到阈值的融资单，默认阈值来自 `plan.settlement.minCompensationTimes`，默认值为 3。
- 客户逾期触发：读取项目配置 `needRepurchaseCustomerBillOverdueDays`，通过 `financingApplicationService.needRepurchaseFinancingApplications(...)` 找客户逾期超过配置天数的融资单。
- 连续代偿触发时会记录 `triggerBillNo`。后续 `RepurchaseHandleBiz` 在非强制模式下会把触发当期账单排除，只对剩余未结算账单走回购；触发当期通常保留为代偿口径。

识别完成后调用：

- `repurchaseHandleBiz.repurchaseHandle(financeApplicationNo, false, "[SCHEDULE]...", triggerBillNo, reason)`

### 自动融资单回购写表顺序

`RepurchaseHandleBiz.repurchaseHandle(...)` 是自动资方账单回购的核心执行链路：

1. 查询融资单未结算资方账单：`repaymentPlanService.listUnsettleBillByFinanceApplicationNo(...)`。
2. 如存在 `triggerBillNo` 且非强制回购，过滤触发当期账单。
3. 构造 `FunderBillTradeInOrBuyBackSettleApplyReq`：
   - `billStatusEnum = BillStatusEnum.BUY_BACK`
   - `funderBillNos = billNos`
   - `loadDbFlag = true`
   - `syncLoanAfterStatus = false`
4. 调用 `FunderBillSettleApplyBizImpl.funderSettleApply(...)` 执行资方账单结算写库。
5. 构造 `StatementResourceGenerateParam`，设置 `transaction = BUY_BACK`、`billNos`、`financingNo`、`financingApplication`、`isForceRepurchase`、`generateRemark`、`repurchaseReason` 等。
6. 调用 `StatementManage.generateStatementResource(...)` 生成回购对账单资源和实时对账单。
7. 调用 `loanAfterSyncBiz.syncFinancingLoanAfterStatus(..., BUYBACK)` 同步贷后状态；这是外部状态同步，不是本库核心写表。

### 自动融资单回购涉及表

资方账单结算由 `FunderBillSettleApplyBizImpl`、`FunderBillSingleSettleBizImpl` 和 `FunderBillPersistBizImpl` 共同完成，主要写表如下：

| 表 | 写数动作 | 关键字段/说明 |
| --- | --- | --- |
| `repayment_plan` | 更新 | 回购时 `bill_status = BUY_BACK`，资产平台枚举值为 `601`；同时更新 `paid_amount`、`unpaid_amount`、`settlement_status`、`settlement_time`。 |
| `repayment_plan_fee_detail` | 更新 | 按科目更新 `total_amount`、`paid_amount`、`unpaid_amount` 等。 |
| `repayment_plan_pay_detail` | 新增 | 生成回购支付流水，`settlement_mode = BUY_BACK`、`payment_mode = OFFLINE`、`pay_amount`、`settlement_time`、`account_time`、`reverse = false`。 |
| `repayment_plan_pay_subject_detail` | 新增 | 生成支付流水对应科目明细，记录 `subject_no`、`subject_name`、`paid_amount`、结算账户等。 |
| `repayment_plan_history` | 新增 | 保存回购后的账单历史快照。 |
| `repayment_plan_fee_detail_history` | 新增 | 保存回购后的账单科目历史快照。 |
| `customer_order` | 可能更新 | `FunderBillPersistBizImpl` 支持按 `orderNo` 更新客户订单；自动融资单回购通常不传 `orderNo`，一般不触发。 |

对账单资源由 `StatementManage` 分发到场景资源生成器，再由 `StatementGenerator` 写表：

| 表 | 写数动作 | 关键字段/说明 |
| --- | --- | --- |
| `statement_original_resource` | 新增 | 保存原始对账单资源，包含 `statement_type`、`scene_code/name`、`in_out`、`capital_project_code`、`resource_serial_no`、`application_no`、`financing_no`、`bill_no`、`subject_no/name`、`amount`、`statement_date`、`settlement_date`、`generate_remark` 等。 |
| `statement` | 新增 | 实时出账时生成对账单主表。 |
| `statement_resource` | 新增 | 实时出账时生成对账单资源明细。 |
| `statement_fee_detail` | 新增 | 实时出账时按科目汇总生成对账单费用明细。 |

### 融资订单手工回购写表顺序

`FunderBillSettleBizServiceImpl.buyBack(...)` 处理融资订单回购，包括商户回购和平台回购：

1. 锁客户账单和商户账单。
2. 结算前先查询融资单所有未结算资方账单与科目明细，供后续出对账单使用。
3. 调用 `repurchaseBizService.redoBillForRepurchase(...)` 重做子账单，持久化重做结果。
4. 调用 `customerBillSettlementBizService.t1BuyBackSettlement(...)` 结算资方账单和资方子账单。
5. 按回购方选择对账单场景：
   - 平台回购：`BILL_FINANCING_PLATFORM_REPURCHASE`
   - 商户回购：`BILL_FINANCING_FINANCING_ORDER_REPURCHASE`
6. 调用 `statementManage.generateStatementResource(...)` 生成对账单资源。
7. 调用 `applicationOrderService.changeCreditor(applicationNos, PLATFORM)`，把相关客户订单债权人切到平台。

该链路除自动融资单回购涉及的父账单表外，还会涉及子账单结算表：

| 表 | 写数动作 | 关键字段/说明 |
| --- | --- | --- |
| `repayment_plan_sub` | 更新/可能重做 | 子账单重做与回购结算会更新子账单金额和结算状态。 |
| `repayment_plan_fee_detail_sub` | 更新/可能重做 | 子账单科目重做与结算会更新科目金额。 |
| `repayment_plan_pay_detail_sub` | 新增 | 生成子账单回购支付流水。 |
| `repayment_plan_pay_subject_detail_sub` | 新增 | 生成子账单回购支付科目明细。 |
| `repayment_plan` | 更新 | 父资方账单同步结算，金额和结算状态随子账单核销结果更新。 |
| `repayment_plan_fee_detail` | 更新 | 父资方账单科目金额同步更新。 |
| `repayment_plan_pay_detail` | 新增 | 从子账单回购结算合并生成父账单支付流水。 |
| `repayment_plan_pay_subject_detail` | 新增 | 从子账单回购结算合并生成父账单科目支付明细。 |
| `statement_original_resource`、`statement`、`statement_resource`、`statement_fee_detail` | 新增 | 根据平台回购或商户融资订单回购场景生成。 |

平台回购场景 `BillFinancingPlatformRepurchaseResourceGen` 还有两个特殊动作：

- 对未核销的平台服务费单据调用 `statementService.cancelStatement(..., "融资单回购作废")`，并把未核销服务费作为负向 `statement_original_resource` 重新写入。
- 对平台给资方的回购对账单，可能通过 `statementSettlementBiz.verification(...)` 自动核销；强制回购时会额外校验余额。

### 客户订单回购写表顺序

`CustomerBillRepurchaseHandle.repurchase(applicationOrder, isForceRepurchase)` 处理客户订单回购：

1. 校验客户订单融资状态必须为 `FINANCED`。
2. 查询客户订单未结算子账单：`repaymentPlanSubService.listUnsettleBillByApplicationNo(...)`。
3. 锁客户账单和商户账单，并校验是否存在处理中的支付流水。
4. 结算前查询融资单未结算父账单和父账单科目明细，供后续出对账单使用。
5. 调用 `repurchaseBizService.redoBillForRepurchase(...)` 重做子账单，持久化重做结果。
6. 调用 `customerBillSettlementBizService.t1settlement(...)` 结算父/子账单。
7. 设置场景 `BILL_FINANCING_CUSTOMER_ORDER_REPURCHASE`，调用 `statementManage.generateStatementResource(...)` 生成对账单资源。
8. 调用 `applicationOrderService.changeCreditor(applicationNo, PLATFORM)`，把客户订单债权人切到平台。

客户订单回购对账单资源生成器 `BillFinancingCustomerOrderRepurchaseResourceGen` 的特征：

- 非试算时从 `repayment_plan_pay_detail_sub`、`repayment_plan_pay_subject_detail_sub` 读取已冲销科目，作为对账单资源科目来源。
- 额外添加减免融资服务费、渠道服务费、运营服务费、保证金等负向科目。
- `generateAfter` 当前只执行实时出账；余额结算逻辑因 2026-03-06 易宝账户体系停用已注释。

## 嘉泰资产平台 SAPS

### 回购入口

嘉泰侧主要有两个入口：

1. 普通定时回购：`BuyBackStatementGenerateSchedule.buyBackStatementGenerateSchedule` 调用 `statementGenerateBizService.execute(..., StatementTypeEnum.BUYBACK)`。
2. 强制回购：`CapitalProviderController` 暴露 `/api/mandatory/buyback`，调用 `StatementBizServiceImpl.mandatoryBuyBack(...)`。

另外 `MandatoryBuybackBizServiceImpl.analyze(...)` 会按 `mandatory_buyback_config` 配置分析强制回购候选资产：

- 线上资产和换货资产分别按代扣率、代偿率等规则筛选。
- 分析结果批量写入 `Mandatory_buyback_analyze`。
- 有候选申请单时构造 `MandatoryBuybackRequest`，继续调用 `mandatoryBuyBack(...)`。

### 强制回购调度到生成流程

`StatementBizServiceImpl.mandatoryBuyBack(...)` 的核心动作：

1. 校验申请单号、强制回购类型等参数。
2. 调用 `repaymentPlanService.checkBuybackStatement(applicationNos)` 防止重复出回购单。
3. 调用 `repaymentPlanService.checkBuybackBill(applicationNos)` 校验是否存在可回购账单。
4. 构造 `StatementGenerateScheduleDto`：
   - `applicationNos`
   - `force = true`
   - `executeDate = LocalDate.now()`
   - `mandatoryType`
5. 按申请单首期账单 `projectNo` 分组，调用 `V2StatementGenerateService.generateStatement(params, BUYBACK)`。

### 回购处理器写表顺序

`BuyBackStatementProcesser` 是嘉泰 V2 回购对账单处理器。主流程继承自 `V2AbstractStatementGenerateProcesser.generateStatement(...)`：

1. `fetchDataSource(...)` 选择数据源。
2. `generate(...)` 生成对账单主表、资源明细和费用明细。
3. `updateBillAndBillFeeDetails(...)` 更新账单和账单科目结算状态。
4. `generatePlatFormFee(...)` 生成平台服务费计费资源。
5. `afterGenerateStatement(...)` 回写计费资源出账标记。

普通回购和强制回购的数据源差异：

- 普通回购：`meetConditionApplications(...)` 按项目 `buyBackRule` 找满足连续 N 期、累计 M 次等规则的申请单。
- 强制回购：直接使用传入的 `applicationNos`。

### 嘉泰回购涉及表

| 表 | 写数动作 | 关键字段/说明 |
| --- | --- | --- |
| `Mandatory_buyback_analyze` | 新增 | 强制回购分析结果，记录项目、申请单、代扣/代偿分析等候选结果。表名大小写以实体 `@TableName("Mandatory_buyback_analyze")` 为准。 |
| `statement_charge_resource` | 新增 | `BuyBackStatementProcesser.saveChargeResource(...)` 先写计费资源，`charge_type = BUY_BACK` 或 `FUNDER_FEE`，`settlement_mode = BUY_BACK`，`generate_bill_flag = false`。 |
| `statement` | 新增 | `V2AbstractStatementGenerateProcesser.generate(...)` 生成对账单主表；强制回购对账单号前缀会加 `F`，备注为“强制回购”或强制类型对应说明。 |
| `statement_resource` | 新增 | 保存对账单资源明细。 |
| `statement_fee_detail` | 新增 | 按科目汇总生成费用明细，初始 `paid_amount = 0`，`unpaid_amount = total_amount`。 |
| `bill_fee_detail` | 更新/可能新增 | 回购后非平台服务费科目更新为已结算；日计息项目会先把旧科目明细 `cancel = true`、备注“付息模式回购作废”，再新增重算后的科目明细。 |
| `repayment_plan` | 更新/可能新增 | 回购后 `bill_status = BUY_BACK_W`、`settlement_status = SETTLED`、`settlement_time = now`；日计息项目会先把旧账单 `cancel = true`、备注“付息模式回购作废”，再新增重算后的账单。 |
| `statement_charge_resource` | 更新 | `afterGenerateStatement(...)` 将本次已出账资源回写 `generate_bill_flag = true`，并回填 `statement_no`。 |

### 日计息项目特殊处理

嘉泰侧日计息项目在回购前会调用 `generateDayCalcBill(...)` 重算账单：

1. 查询未结算账单和科目。
2. 将原 `bill_fee_detail` 标记 `cancel = true`，备注“付息模式回购作废”。
3. 将原 `repayment_plan` 标记 `cancel = true`，备注“付息模式回购作废”。
4. 新增重算后的 `bill_fee_detail` 和 `repayment_plan`，重算当期资方服务费、担保费和账单金额。

这意味着日计息项目回购时，账单表和科目表既有“作废旧数据”的更新，也有“新增重算数据”的插入。

### 嘉泰回购状态口径

嘉泰 `BillStatusEnum` 中回购相关枚举为：

- `BUY_BACK_W(600, "待回购")`
- `BUY_BACK(601, "已回购")`

`BuyBackStatementProcesser.updateBillAndBillFeeDetails(...)` 在生成回购对账单后，将 `repayment_plan.bill_status` 更新为 `BUY_BACK_W`，即待回购；不是直接改为已回购。历史注释中出现的旧状态值不应作为准绳，实际应以枚举和当前代码为准。

## 两套系统的主要差异

| 维度 | 资产平台 SAPS | 嘉泰资产平台 SAPS |
| --- | --- | --- |
| 回购触发 | 自动代偿/逾期识别，手工融资订单/客户订单回购 | 定时普通回购，API/分析任务触发强制回购 |
| 先写什么 | 先结算资方/客户账单和支付明细 | 先写 `statement_charge_resource` 计费资源 |
| 对账单资源表 | `statement_original_resource` | `statement_charge_resource` 先沉淀，后生成 `statement_resource` |
| 账单状态 | 资方账单回购后直接 `BUY_BACK = 601` | 出回购对账单后先 `BUY_BACK_W = 600` |
| 子账单 | 融资订单/客户订单回购会重做和结算 `repayment_plan_sub` 等子账单表 | 本次代码链路主要围绕 `repayment_plan`、`bill_fee_detail` 和对账单表 |
| 日计息重算 | 本次未看到同类统一逻辑 | 日计息项目会作废旧账单/科目并新增重算账单/科目 |
