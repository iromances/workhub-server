# 代收代付对账单需求与系统功能

## 一句话摘要

代收代付对账单是资产平台相关资金链路中的一类资方对账单，当前在 SAPS 中以 `statement_type = 10012` 落表到 `funder_statement` 和 `funder_statement_resource`，支持对账单查询、明细查询、自动付款、付款结果查询和页面重新付款。

## 当前理解

### 需求口径

- 业务对象：代收代付对账单。
- 对账单类型：`StatementTypeEnum.DSDF_FEE = 10012`，描述为“代收代付”。
- 数据来源：资方对账单通知 `THJTFunderStatementNoticeDto`，当 `bizType = 10012` 时进入代收代付专用保存逻辑。
- 系统行为：代收代付通知进入后，系统不继续向合作方推送普通资方对账单通知，而是本地保存对账单并把通知记录视为已推送。
- 初始状态：对账单保存后为未结算、未核销，金额字段按通知总金额和明细费用从分转元写入。

### 系统功能

- 对账单列表查询：`GET /statement/dsdf/query`。
- 对账单列表导出：`GET /statement/dsdf/query/export`。
- 对账单明细查询：`GET /statement/dsdf/detail`。
- 对账单明细导出：`GET /statement/dsdf/detail/export`。
- 收款方列表：`GET /statement/dsdf/payeeList`。
- 页面重新付款：`POST /statement/dsdf/rePay`。
- 自动付款调度：`dsdfPaySchedule`。
- 付款结果查询调度：`dsdfRemitQuerySchedule`。

## 实现口径

### 对账单接收和保存

- 入口：`FunderStatementBizServiceImpl.syncReceive`。
- 判断条件：`request.bizType == StatementTypeEnum.DSDF_FEE.getValue()`。
- 处理步骤：
  - 调用 `prepareData(request)`，根据通知中的 `partnerScheduleNo` 查 `repayment_plan.funder_bill_no`，并查询相关放款单、账单费用等上下文。
  - 调用 `saveDsDfFunderStatement(request, funderStatementParams)` 保存对账单头和明细。
  - 将 `funder_statement_notice.push_flag` 置为 `true`。

### 明细保存

- 明细表：`funder_statement_resource`。
- 每个通知明细通过 `partnerScheduleNo` 匹配 `repayment_plan.funder_bill_no`；匹配不到会抛 `BILL_NOT_MATCH`。
- 关键字段：
  - `statement_no = request.cnNo`
  - `application_no = repayDetail.applicationNo`
  - `period = repayDetail.period`
  - `pid = repayDetail.partnerScheduleNo`
  - `bill_no = repaymentPlan.billNo`
  - `source_serial_no = repayDetail.sourceSerialNo`
- 金额字段：
  - `principal`
  - `repay_service_fee`
  - `payment_fee`
  - `principal_payment_fee`
  - `repay_service_payment_fee`
- 金额处理：通知中的整型金额按分转元保存；`principalPaymentFee` 和 `repayServicePaymentFee` 当前也走转元方法。

### 对账单头保存

- 主表：`funder_statement`。
- 关键字段：
  - `statement_no = request.cnNo`
  - `statement_type = 10012`
  - `cooperation_code / cooperation_name` 来自匹配到的放款单。
  - `project_no / project_name` 来自匹配到的放款单。
  - `principal / repay_service_fee / payment_fee` 来自明细累计。
  - `total_amount / unpaid_amount / red_amount` 来自通知金额分转元。
  - `status = UNSETTLEMENT`
  - `verification_status = UNCHECK`
  - `last_pay_date / last_grace_date = request.settlementDate`
  - `settle_account_code / settle_account_name` 来自通知。

### 列表查询

- SQL 固定查询 `funder_statement.statement_type = 10012`，并排除删除、取消记录。
- 页面展示中的项目名和付款方当前是 SQL 写死：
  - 项目名：`即科医美通汇诚泰保理（再保理）`
  - 付款方：`通汇诚泰商业保理（天津）有限公司`
- 收款方：`funder_statement.settle_account_name`。
- 代收代付科目金额：`dsdfAmount = total_amount`。
- 支付手续费：`sum(funder_statement_resource.payment_fee)`。
- 付款时间：成功付款订单 `customer_order.complete_time`。
- 如果 `payment_status` 不是成功，服务层会隐藏列表中的 `operator`。

### 明细查询

- SQL 从 `funder_statement_resource` 查询，关联：
  - `funder_statement.statement_no`
  - `customer_transaction.goods_id = funder_statement_resource.bill_no`
  - `customer_order.order_no = customer_transaction.order_no`
  - `customer_order.status = 4`
- 服务层会把一条资源拆成科目行：
  - 本金行：`principal > 0`，结算金额取 `principal`，手续费取 `principalPaymentFee`。
  - 服务费行：`repayServiceFee > 0`，结算金额取 `repayServiceFee`，手续费取 `repayServicePaymentFee`。
- 明细展示会把结算账户追加为 `结算账户（代收代付）`。

### 自动付款

- 调度入口：`DsdfPaySchedule`。
- 业务方法：`FunderStatementBizServiceImpl.dsdfPayExcute`。
- 查询条件：
  - `statement_type = 10012`
  - `last_pay_date <= executeDate`
  - `payment_status = 1`
  - 可按 `statementNo` 指定单张对账单。
- 查询到的对账单逐个调用 `statementBizService.rePay`。

### 页面重新付款

- 页面接口：`POST /statement/dsdf/rePay`。
- 业务方法：`StatementBizServiceImpl.rePay`。
- 当前限制：
  - 使用 Redis 锁 `RP + statementNo` 防止短时间重复处理。
  - 对账单不存在或 `status = SETTLED` 时拒绝付款。
  - 代码没有限制必须是付款失败状态才能重新付款。
- 付款行为：
  - 新建 `customer_order`，`biz_serial_no = statementNo`。
  - 新建 `customer_transaction`。
  - 调用 `paymentApiService.singleRemit` 发起单笔代付。
  - 收款账户来自 `statement.settleAccountCode` 对应的 `StatementConfig`。
  - 金额为 `statement.totalAmount * 100`。
  - 渠道固定为 `BCM`。
  - 回调地址为 `/statement/remit/callback`。

### 付款结果查询

- 调度入口：`DsdfRemitQuerySchedule`。
- 业务方法：`FunderStatementBizServiceImpl.dsdfRemitQuery`。
- 查询条件：`payment_status = 2` 且 `statement_type = 10012`。
- 付款成功：
  - 三方返回 `trxStat = 4`。
  - `customer_order.status = SUCCESS`。
  - 对账单更新为已结算、付款成功、已核销。
  - `paid_amount = total_amount`，`unpaid_amount = 0`。
  - 向嘉泰推送 `/saps/api/soa/settle`。
- 付款失败：
  - 三方返回 `trxStat = 3`。
  - `customer_order.status = FAILED`。
  - 对账单更新为未结算、付款失败，并记录失败原因。

## 边界和风险

- 页面重新付款当前只校验“不是已结算”，没有强制要求 `payment_status = FAILED`。如果页面在“付款处理中”状态也开放按钮，可能创建新的付款订单。
- `rePay` 的 Redis 加锁 key 是 `RP + statementNo`，但 finally 删除的是 `statementNo`，需要后续确认是否存在锁释放不一致问题。
- 列表 SQL 中项目名和付款方是固定文本，后续若代收代付扩展到其他项目或付款主体，需要重新确认页面查询口径。
- 明细查询只关联成功订单 `customer_order.status = 4`，未成功付款时可能查不到付款相关明细展示字段。
