# WorkHub 系统架构与设计

## 1. 技术栈

- Java 25
- Spring Boot 4.0.x
- MyBatis Spring Boot Starter 4.0.x
- Druid Spring Boot 4 Starter 1.2.28
- MySQL 8
- JWT
- BCrypt
- Maven

外部集成：

- 企业微信自建应用回调
- 企业微信群机器人 webhook
- AI 模型 HTTP API
- 本地 Codex CLI
- GitLab 仓库只读拉取
- 本地项目知识库需求迭代 Markdown 写入与摘要检索
- 支付渠道网关配置管理
- 可选 ELK 日志监控，通过 ECS JSON 文件日志、Filebeat、Elasticsearch 和 Kibana 实现，不参与核心业务写入链路

## 3. 仓库结构

本节记录当前模块结构、模块职责边界和业务域归档方式。

本仓库采用 Maven 多模块项目结构，根 `pom.xml` 作为聚合工程，按职责拆分为 model、support、dao、service、controller、job、mcp-server、bootstrap 等模块。

| 模块或目录 | Maven module | 主要职责 |
|---|---:|---|
| `workhub-model/` | 是 | 请求、响应、实体和值对象等前后端和层间契约模型。 |
| `workhub-support/` | 是 | 配置属性模型和跨模块支撑对象。 |
| `workhub-dao/` | 是 | MyBatis 数据访问接口和数据库访问映射。 |
| `workhub-service/` | 是 | 业务动作、业务编排、集成服务与 JWT 令牌服务。 |
| `workhub-controller/` | 是 | HTTP 接口、统一响应和异常处理。 |
| `workhub-job/` | 是 | 定时任务和后台调度入口。 |
| `workhub-mcp-server/` | 是 | 面向 AI 客户端的只读运维 MCP 工具实现和安全通道。 |
| `workhub-bootstrap/` | 是 | Spring Boot 启动入口、运行时配置和资源组装。 |
| `workhub-bootstrap/src/main/resources/db/schema/mysql/` | 否 | Flyway 数据库脚本唯一自动扫描目录；`V1` 至 `V20` 是历史数字版本，后续统一使用 `VYYYYMMDD_HHMMSS__brief_desc.sql` 时间戳版本。 |
| `docs/` | 否 | 事实文档、规则与约定、模板和历史执行记录。 |

工程实现基线：

- Spring Boot + MyBatis 注解/分层模式。
- 业务域示例：认证放在 `auth`，项目放在 `project`，迭代放在 `sprint`，版本放在 `release`，工作项放在 `workitem`，需求管理放在 `intake`，支付配置放在 `payment`，运维监测放在 `ops`。

## 4. MCP 只读通道

MCP 只读通道用于在 AI 客户端、受控运维资源和 WorkHub 需求管理数据之间建立安全代理层。当前统一使用 Streamable HTTP MCP transport：

- HTTP runtime：内嵌在 `workhub-server` 主服务中，通过 `/api/mcp/runtime` 接收 MCP JSON-RPC 请求，使用独立 Bearer Token 鉴权，支持 `2025-11-25/2025-06-18/2025-03-26` 协议协商，并兼容 Codex 当前包含的 `2026-07-28` 预发布协议标识；通知返回 HTTP 202，当前不提供服务端 SSE 流，GET 返回 405。runtime 直接读取主库中已启用的 MCP 资源配置，配置变更后下一次调用生效。

当前 MCP runtime 只暴露受控只读工具，`docs/事实/MCP能力清单.md` 维护完整能力清单：

- `list_mcp_targets`：返回业务线、业务线系统清单、全局中台系统清单、环境、数据库目标、服务器目标、知识库配置摘要和 GitLab 配置摘要。
- `get_business_line_context`：按业务线名称或编码返回已启用的多环境访问入口、GitLab group、代码缓存路径 `data/git-cache/{gitlabGroupName}`、知识库路径规则、数据库目标和服务器目标。
- `get_knowledge_context`：读取 MCP 项目配置中的 `projectVaultPath` 知识库根地址，并按业务线返回 raw/wiki 根目录和需求归档路径结构；当前不读取知识库文件正文。
- `sync_gitlab_group_repositories`：按业务线触发 GitLab group 及子组仓库同步到本地受控缓存，工具结果不返回 GitLab Access Token。
- `search_intakes`：按审批编号和/或需求名称搜索需求管理记录，返回匹配摘要。
- `get_intake_detail`：按 intakeId 读取单条需求管理详情。
- `get_requirement_test_context`：按需求聚合业务线、分支、涉及系统、指定环境已启用访问入口和环境资源测试上下文。
- `get_business_line_test_context`：按业务线、环境和系统聚合测试上下文；`accessEndpoints` 返回运营端、客户端、网关或其他入口，并提供网关地址与路径前缀组合后的 `effectiveUrl`。
- `run_readonly_query`：按目标和 profile 执行受控只读 SQL；结果、SQL 回显和审计 SQL 在 MCP 服务端统一脱敏。
- `get_service_status`：按服务器目标、profile 和服务名读取服务状态；配置服务白名单时只允许读取白名单服务，服务白名单为空表示不限制服务名。
- `read_service_logs`：按服务器目标、profile 读取服务日志或日志文件 tail；日志路径白名单配置一个或多个绝对日志目录，允许按具体服务传入该目录下不同的日志文件；路径校验防止目录越界和 shell 注入，对应白名单为空表示不限制该维度。
- `search_service_logs`：在白名单内的单个普通日志或 ZIP 历史日志中执行固定字符串检索；命中数受 profile 限制，检索关键词不写入审计，不开放正则、通配符、解压写盘或任意 shell。
- `DATABASE` 和 `SERVER` 资源可通过 `publicResource` 标记为公共资源；公共资源不要求业务线绑定，并自动出现在各业务线上下文中。`featureTags` 用于返回“禅道、合同系统、支付”等用途特征，帮助 AI 选择目标。
- 非公共资源继续通过 `businessLineCodes` 绑定业务线，并可通过业务线下的系统列表 `systemNames` 绑定一个或多个系统；`systemNames` 为空表示默认覆盖所绑定业务线下所有系统；兼容字段 `systemName` 表示首个系统。

资源选择遵循：

```text
businessLineCodes + environmentCode + targetKey + profileKey
```

非公共 MCP 资源与业务线是多对多绑定关系。`mcp_resource_config.business_line_code` 仅保留首个业务线用于兼容和排序，实际查询业务线可访问的 DB/server 目标时以 `mcp_resource_business_line` 绑定表为准。公共资源的 `business_line_code` 为空字符串且不写绑定表，由 `public_resource=1` 明确识别。

堡垒机由 `mcp_bastion_config` 统一维护，凭据使用 MCP 主密钥加密保存且不通过管理接口回显。数据库目标开启堡垒机连接时通过 `mcp_resource_config.bastion_id` 关联一台已启用堡垒机，Catalog 在服务端解析关联配置并继续输出既有 `sshTunnel` 结构；服务器目标的堡垒机连接配置本次保持原逻辑。历史数据库目标内嵌的堡垒机配置由 Flyway `V20260720_153544` 逐条迁移并建立关联。

堡垒机新增/编辑表单支持连接测试。后端使用本机 `ssh -N` 建立无远端命令的 SSH 会话，以临时 Control Socket 建立成功作为握手及认证成功依据，结束后立即销毁进程和 Socket；密码认证通过 `sshpass` 环境变量传递密码，命令参数和响应均不包含密码。编辑态密码留空时只在服务端内存中解密并复用已保存密码。测试结果只暴露成功状态、耗时和分类后的安全错误，不返回原始 SSH 输出，并写系统操作审计。

数据库目标新增/编辑表单也支持测试当前未保存配置。后端根据 `sshBastionEnabled` 自动选择连接方式：关闭时直接通过 JDBC 连接目标，开启时解析所选 `bastionId`，先建立带 Control Socket 的本地端口转发，再通过本地转发端口连接数据库；连接建立后仅执行 `SELECT 1`。编辑态数据库密码留空时只在服务端内存中复用已保存密码。SSH 和 JDBC 均设置 8 秒超时，结果按堡垒机、数据库两个失败阶段分类，不返回凭据、JDBC URL 或原始底层错误，并写系统操作审计。

服务器目标新增/编辑表单支持测试当前未保存配置。关闭堡垒机时，后端直接以目标服务器的 SSH 用户和密码/私钥建立 `ssh -N` 会话；开启堡垒机时，先使用表单内的堡垒机配置建立本地端口转发，再通过该转发端口验证目标服务器 SSH。两段连接均以临时 Control Socket 作为握手及认证成功依据，8 秒超时，不执行远端命令；编辑态两套密码留空时分别在服务端内存中复用已保存密码。结果按堡垒机、服务器两个失败阶段分类，不返回凭据或原始 SSH 输出，并写系统操作审计。

MCP 安全边界另见 `docs/规则与约定/研发要求与约定.md`。

### 统一 AI 网关运行时

- 系统内部真实模型调用统一进入 `AiGatewayClient`；默认按 useCase 解析配置，受信任的内部请求可覆盖 Provider、模型、推理、速度、超时和 Schema，但不能覆盖密钥；本期不提供任意 Prompt 的公共 HTTP 执行接口。
- 最终调用参数优先级为“请求覆盖 → 场景覆盖 → Provider 默认”；最终值缺失时 fail-closed。
- 网关按 `channel_type + api_protocol` 分流：`CLI` 进入 `CodexCliClient`，`OPENAI_RESPONSES` 进入 Responses 客户端，`OPENROUTER/OPENAI_COMPATIBLE/CUSTOM` 进入 Chat Completions 客户端；未知协议显式失败。
- Responses 请求使用 `/responses`、`store=false`、`reasoning.effort`、可选 `service_tier=priority` 和 `text.format.json_schema`；Chat Completions 使用 `/chat/completions`、`reasoning_effort`、可选 `service_tier=priority` 和 `response_format.json_schema`。
- Provider API Key 只在服务端短暂解密并放入 `Authorization` 请求头，不进入业务请求对象、命令行、响应或日志；外部 HTTP 错误只返回状态码和安全错误摘要。
- `AiUseCaseDefinitions` 固化场景安全能力。`intake.structured.extract`、`intake.sql-draft.generate` 允许 API/CLI 和显式图片输入；`intake.clarification.analyze`、`intake.development.analyze`、`intake.development.adjust` 依赖本地仓库，只允许 CLI，管理员不能通过改库把它们切换到 API。
- 数据库配置和受控内部覆盖是 Provider、模型、推理强度、速度、超时和提示词的运行时来源；场景不存在、停用、最终参数缺失、Provider 停用或能力不匹配时 fail-closed，不回退到 application 默认供应商，也不跨供应商静默降级。
- API 客户端分别落实连接、响应读取和总调用超时；Schema 只允许安全的 classpath JSON 相对路径。
- API 图片输入只读取业务调用显式传入的图片路径，单文件限制 10MB，编码为 data URL；CLI 的非仓库场景使用空临时工作目录，仓库场景只接收业务明确传入的工作目录和附加目录。
- 供应商连接探针使用独立场景 `system.provider.smoke`，直接复用目标 API 协议适配器，只发送固定无业务数据提示词和最小 Schema；仅精确单字段 `{"status":"OK"}` 判为成功，响应不返回原始供应商正文和密钥，并记录操作审计。
- AI 接入配置支持使用当前未保存单通道表单执行连通测试：API 复用 Responses/Chat 适配器，CLI 复用禁用插件、禁用本地工具的 Codex 结构化调用；存量脱敏 Key 仅按同 ID、同通道在服务端内存补回，测试不写 Provider 表。页面在弹窗左下角常驻展示当前 API/CLI 页签结果，前端请求时限按通道总调用超时放宽。

## 7. 安全方案

- 本地账号密码登录
- 密码 BCrypt 存储
- 登录成功返回 JWT、角色编码和权限点
- JWT 请求由过滤器加载数据库账号状态和权限点作为 Spring Security authorities
- 账号支持启用/停用、连续 5 次登录失败锁定 15 分钟、后端生成一次性初始密码和重置密码
- 权限首版采用 RBAC，包含账号、角色、权限点、用户角色、角色权限、登录日志和操作日志
- 前端按权限点过滤菜单、路由和按钮；后端对账号、角色、系统配置、AI 配置、项目、需求、工作项、运维、MCP 和支付配置等接口使用权限点强校验，无权限返回 `403`
- 权限点按菜单 `*:view` 和按钮动作拆分；历史 `*:manage` 权限保留为兼容授权，新增细粒度按钮权限通过 Flyway `V3__refine_menu_button_permissions.sql` 初始化和迁移。
- 首版不做业务线、环境、本人数据等数据层面的行级限制，业务列表和统计沿用现有查询口径
- 网关能力未引入
- 支付敏感参数、敏感凭据和秘钥数据包含密文、脱敏值、指纹和版本摘要
- AI Provider API Key 使用独立主密钥执行 AES-GCM 加密，管理接口只返回脱敏值；运行时明文仅在服务进程内短暂解析并通过子进程环境变量传递
