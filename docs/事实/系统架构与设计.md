# WorkHub 系统架构与设计

## 1. 技术栈

- Java 25
- Spring Boot 4.0.x
- MyBatis Spring Boot Starter 4.0.x
- Druid Spring Boot 4 Starter 1.2.28
- MySQL 8
- JWT
- BCrypt
- Maven

外部集成：

- 企业微信自建应用回调
- 企业微信群机器人 webhook
- AI 模型 HTTP API
- 本地 Codex CLI

- 可选 ELK 日志监控，通过 ECS JSON 文件日志、Filebeat、Elasticsearch 和 Kibana 实现，不参与核心业务写入链路

## 3. 仓库结构

本节记录当前模块结构、模块职责边界和业务域归档方式。

本仓库采用 Maven 多模块项目结构，根 `pom.xml` 作为聚合工程，按职责拆分为 model、support、dao、service、controller、job、mcp-server、bootstrap 等模块。

| 模块或目录 | Maven module | 主要职责 |
|---|---:|---|
| `workhub-model/` | 是 | 请求、响应、实体和值对象等前后端和层间契约模型。 |
| `workhub-support/` | 是 | 配置属性模型和跨模块支撑对象。 |
| `workhub-dao/` | 是 | MyBatis 数据访问接口和数据库访问映射。 |
| `workhub-service/` | 是 | 业务动作、业务编排、集成服务与 JWT 令牌服务。 |
| `workhub-controller/` | 是 | HTTP 接口、统一响应和异常处理。 |
| `workhub-job/` | 是 | 定时任务和后台调度入口。 |
| `workhub-mcp-server/` | 是 | 面向 AI 客户端的只读运维 MCP 工具实现和安全通道。 |
| `workhub-bootstrap/` | 是 | Spring Boot 启动入口、运行时配置和资源组装。 |
| `workhub-bootstrap/src/main/resources/db/schema/mysql/` | 否 | Flyway 数据库脚本统一目录；`V1__init.sql` 是当前完整建库基线，后续变更从 `V2__*.sql` 递增。 |
| `docs/` | 否 | 事实文档、规则与约定、模板和历史执行记录。 |

工程实现基线：

- Spring Boot + MyBatis 注解/分层模式。
- 业务域示例：认证放在 `auth`，项目放在 `project`，迭代放在 `sprint`，版本放在 `release`，工作项放在 `workitem`，需求管理放在 `intake`，支付配置放在 `payment`，运维监测放在 `ops`。

## 4. MCP 只读通道

MCP 只读通道用于在 AI 客户端、受控运维资源和 WorkHub 需求管理数据之间建立安全代理层。当前统一使用 HTTP transport：

- HTTP runtime：内嵌在 `workhub-server` 主服务中，通过 `/api/mcp/runtime` 接收 MCP JSON-RPC 请求，直接读取主库中已启用的 MCP 资源配置，配置变更后下一次调用生效。

当前 MCP runtime 只暴露受控只读工具，`docs/事实/MCP能力清单.md` 维护完整能力清单：

- `list_mcp_targets`：返回业务线、业务线系统清单、全局中台系统清单、环境、数据库目标、服务器目标、知识库配置摘要和 GitLab 配置摘要。
- `get_business_line_context`：按业务线名称或编码返回 GitLab group、代码缓存路径 `data/git-cache/{gitlabGroupName}`、知识库路径规则、数据库目标和服务器目标。
- `get_knowledge_context`：读取 MCP 项目配置中的 `projectVaultPath` 知识库根地址，并按业务线返回 raw/wiki 根目录和需求归档路径结构；当前不读取知识库文件正文。
- `sync_gitlab_group_repositories`：按业务线触发 GitLab group 及子组仓库同步到本地受控缓存，工具结果不返回 GitLab Access Token。
- `search_intakes`：按审批编号和/或需求名称搜索需求管理记录，返回匹配摘要。
- `get_intake_detail`：按 intakeId 读取单条需求管理详情。
- `run_readonly_query`：按目标和 profile 执行受控只读 SQL。
- `get_service_status`：按服务器目标、profile 和服务名读取服务状态；配置服务白名单时只允许读取白名单服务，服务白名单为空表示不限制服务名。
- `read_service_logs`：按服务器目标、profile 读取服务日志或日志文件 tail；配置服务白名单或日志路径白名单时只允许读取白名单范围，对应白名单为空表示不限制该维度。
- `SERVER` 资源通过业务线下的系统列表 `systemNames` 支持同一服务器目标承载一个或多个微服务系统；`systemNames` 为空表示默认覆盖所绑定业务线下所有系统；兼容字段 `systemName` 表示首个系统。

资源选择遵循：

```text
businessLineCodes + environmentCode + targetKey + profileKey
```

MCP 资源与业务线是多对多绑定关系。`mcp_resource_config.business_line_code` 仅保留首个业务线用于兼容和排序，实际查询业务线可访问的 DB/server 目标时以 `mcp_resource_business_line` 绑定表为准。

MCP 安全边界另见 `docs/规则与约定/研发要求与约定.md`。

## 7. 安全方案

- 本地账号密码登录
- 密码 BCrypt 存储
- 登录成功返回 JWT、角色编码和权限点
- JWT 请求由过滤器加载数据库账号状态和权限点作为 Spring Security authorities
- 账号支持启用/停用、连续 5 次登录失败锁定 15 分钟、后端生成一次性初始密码和重置密码
- 权限首版采用 RBAC，包含账号、角色、权限点、用户角色、角色权限、登录日志和操作日志
- 前端按权限点过滤菜单、路由和按钮；后端对账号、角色、系统配置、项目、需求、工作项、运维、MCP 和支付配置等接口使用权限点强校验，无权限返回 `403`
- 权限点按菜单 `*:view` 和按钮动作拆分；历史 `*:manage` 权限保留为兼容授权，新增细粒度按钮权限通过 Flyway `V3__refine_menu_button_permissions.sql` 初始化和迁移。
- 首版不做业务线、环境、本人数据等数据层面的行级限制，业务列表和统计沿用现有查询口径
- 网关能力未引入
- 支付敏感参数、敏感凭据和秘钥数据包含密文、脱敏值、指纹和版本摘要
