# WorkHub Controller 接口说明

本文档按 controller 层梳理当前暴露给前端、外部系统和 AI/MCP runtime 的 HTTP 接口。接口表统一包含 `系统路径`，用于标注前端功能入口或调用来源；非前端页面直接触发的接口标为 `后台/系统调用`、`外部回调` 或 `通用附件`。

## 1. 通用说明

| 项目 | 说明 |
|---|---|
| 基础路径 | 业务接口统一以 `/api` 开头。 |
| 鉴权 | 除登录、健康检查和企业微信回调等明确匿名接口外，默认需要登录态或 JWT。 |
| 返回格式 | 以项目统一响应结构返回；分页接口通常返回 `items/total/page/pageSize`。 |
| 敏感字段 | 系统配置、支付凭据、MCP 资源密码和 GitLab Token 不回显明文，只返回脱敏值或是否已配置。 |
| 系统路径 | 采用 `一级菜单-页面/弹窗-动作` 格式；多个入口用顿号分隔。 |
| 文档维护 | 新增、移除或改变接口语义时，同步更新本文档。 |

## 2. 认证接口

控制器：`AuthController`

| 方法 | 路径 | 系统路径 | 用途 | 请求/参数 | 关键说明 |
|---|---|---|---|---|---|
| `POST` | `/api/auth/login` | 登录页-登录 | 用户名密码登录 | 请求体：`LoginRequest` | 返回 JWT 和当前用户信息。 |
| `GET` | `/api/auth/me` | 全局-恢复登录态 | 获取当前登录用户资料 | 需要 JWT | 用于前端恢复登录态和用户信息。 |

## 3. 系统接口

| 方法 | 路径 | 系统路径 | 用途 | 请求/参数 | 关键说明 |
|---|---|---|---|---|---|

| `DELETE` | `/api/system/developers/{id}` | 系统管理-研发人员-删除 | 删除研发人员资源 | 路径参数：`id` | 删除系统维护的研发人员资源。 |

## 4. MCP 运维通道接口

控制器：`McpResourceController`

| 方法 | 路径 | 系统路径 | 用途 | 请求/参数 | 关键说明 |
|---|---|---|---|---|---|
| `GET` | `/api/mcp/resources` | 系统管理-MCP资源配置 | 查询 MCP 只读运维资源配置 | 查询参数：`resourceType`、`businessLineCode`、`environmentCode`、`keyword`、`enabledOnly` | `resourceType` 支持 `DATABASE/SERVER`；返回目标、绑定业务线、白名单、profile 和启用状态；敏感值不回显。 |
| `POST` | `/api/mcp/resources` | 系统管理-MCP资源配置-新增 | 新增 MCP 资源配置 | 请求体：`McpResourceSaveRequest` | 支持一个资源绑定多个 `businessLineCodes`；新增数据库目标和服务器目标时 `targetKey`、`name` 可不传，由后端按业务线、环境、资源类型、主机和端口自动生成；数据库资源必须配置账号密码；服务器资源必须配置账号和密码或私钥；服务器所属系统为空表示覆盖所选业务线下所有系统；服务白名单和日志路径白名单为空表示对应维度不限制；密码入库前加密。 |
| `PUT` | `/api/mcp/resources/{id}` | 系统管理-MCP资源配置-编辑 | 更新 MCP 资源配置 | 请求体：`McpResourceSaveRequest` | 编辑时密码字段留空表示不修改已有加密密码。 |
| `DELETE` | `/api/mcp/resources/{id}` | 系统管理-MCP资源配置-删除 | 删除 MCP 资源配置 | 路径参数：`id` | 删除本地资源配置。 |
| `GET` | `/api/mcp/catalog` | 后台/AI MCP通道-资源目录 | 生成 MCP Server 可读取的 catalog JSON | 无 | 包含 `businessLines/environments/databaseTargets/serverTargets/knowledge/gitlab`；GitLab 摘要不返回 Access Token。 |
| `POST` | `/api/mcp/runtime` | 后台/AI MCP通道-工具调用 | 内嵌 HTTP MCP runtime | MCP JSON-RPC 请求 | 支持 `initialize`、`tools/list`、`tools/call`；工具直接读取当前已启用 MCP 资源配置。 |
| `GET` | `/api/mcp/audits` | 系统管理-MCP审计日志 | 读取 MCP runtime 审计日志 | 查询参数：`limit`，默认 `100`，最大 `500` | 日志路径来自 `WORKHUB_MCP_AUDIT_LOG`，未配置时使用 `logs/mcp-audit.jsonl`。 |

### 4.1 MCP runtime 工具边界

| 工具 | 用途 | 安全边界 |
|---|---|---|
| `list_mcp_targets` | 列出可用业务线、环境和资源目标 | 只返回已启用、可访问的配置摘要。 |
| `get_business_line_context` | 获取业务线上下文 | 返回业务线、系统清单和必要配置摘要，不返回密钥。 |
| `get_knowledge_context` | 获取知识库上下文 | 读取 MCP 项目配置中的 `projectVaultPath` 并返回知识库根地址、业务线 raw/wiki 根目录和归档路径结构；不读取知识库文件正文。 |
| `sync_gitlab_group_repositories` | 同步业务线 GitLab group 仓库 | 只拉取或刷新到 WorkHub 受控本地缓存；不返回 GitLab Access Token，不提交、不推送、不修改远端。 |
| `run_readonly_query` | 执行只读 SQL | 只允许只读、单语句、有边界查询；禁止写入、DDL、导出和高风险函数。 |
| `get_service_status` | 读取服务状态 | 配置服务白名单时只能读取白名单服务；白名单为空表示不限制服务名。 |
| `read_service_logs` | 读取服务日志 | 配置服务白名单或日志路径白名单时只能读取白名单范围；对应白名单为空表示不限制该维度；不提供任意 shell。 |

| `PUT` | `/api/ops/monitors/{id}` | 运维监测-监测配置-编辑 | 更新运维监测配置 | 请求体：监测配置保存请求 | 更新本地监测配置。 |
| `DELETE` | `/api/ops/monitors/{id}` | 运维监测-监测配置-删除 | 删除运维监测配置 | 路径参数：`id` | 删除本地监测配置。 |
| `POST` | `/api/ops/monitors/{id}/check` | 运维监测-监测配置-手动采集 | 手动触发一次真实采集 | 路径参数：`id` | `XXL_JOB` 通过 MCP 只读数据库通道读取调度库，只读不触发任务、不修改配置。 |
| `GET` | `/api/ops/monitors/xxl-job/dashboard` | 运维监测-XXL-JOB看板 | 查询 XXL-JOB 本地监测看板 | 查询参数：`businessLineCode`、`environmentCode`、`enabledOnly` | 首页不实时读取远端调度库，只返回本地配置字段和上次采集结果。 |
| `GET` | `/api/ops/monitors/xxl-job/executors` | 运维监测-XXL-JOB配置-关注执行器选择 | 查询可关注执行器下拉选项 | 查询参数：`businessLineCode`、`environmentCode`、`xxlJobDatabaseName` | 读取 `xxl_job_group`，返回 `appName/title`；不修改 XXL-JOB 配置。 |
| `GET` | `/api/ops/monitors/{id}/xxl-job/detail` | 运维监测-XXL-JOB详情-兼容旧页 | 查询单条 XXL-JOB 监测详情兼容接口 | 查询参数：`startDate`、`endDate` | 保留兼容旧前端；新页面不再使用。 |
| `GET` | `/api/ops/monitors/{id}/xxl-job/logs` | 运维监测-XXL-JOB日志 | 查询原始执行日志 | 查询参数：`startDate`、`endDate`、`page`、`pageSize`、`author`、`executorAppName`、`logStatus` | 只读 `xxl_job_log` 明细和分页总数；`logStatus` 支持 `ALL/FAILED`。 |
| `GET` | `/api/ops/system-alerts` | 运维监测-系统预警看板 | 查询系统预警本地错误事件看板 | 查询参数：`businessLineCode`、`environmentCode`、`serviceName`、`level`、`startTime`、`endTime`、`page`、`pageSize` | 当前只查询本地 `ops_system_alert_event`，默认最近 1 小时 `ERROR` 事件。 |
| `GET` | `/api/ops/system-alerts/subsystems` | 运维监测-系统预警-关注子系统 | 查询系统预警关注子系统清单 | 查询参数：`businessLineCode`、`environmentCode`、`enabledOnly`、`keyword` | 独立于项目涉及系统和 XXL-JOB 执行器配置。 |
| `POST` | `/api/ops/system-alerts/subsystems` | 运维监测-系统预警-关注子系统-新增 | 新增系统预警关注子系统 | 请求体：关注子系统保存请求 | 用于配置本地系统预警关注范围。 |
| `PUT` | `/api/ops/system-alerts/subsystems/{id}` | 运维监测-系统预警-关注子系统-编辑 | 更新系统预警关注子系统 | 请求体：关注子系统保存请求 | 更新启用状态、名称或说明。 |
| `DELETE` | `/api/ops/system-alerts/subsystems/{id}` | 运维监测-系统预警-关注子系统-删除 | 删除系统预警关注子系统 | 路径参数：`id` | 删除本地关注配置。 |

## 7. 项目接口

控制器：`ProjectController`

| 方法 | 路径 | 系统路径 | 用途 | 请求/参数 | 关键说明 |
|---|---|---|---|---|---|
| `GET` | `/api/projects` | 项目管理-项目列表 | 查询项目列表 | 查询参数：`status`、`keyword`、`businessLine`、`page`、`pageSize` | 未传分页参数时返回全量；`businessLine` 优先按业务线编码筛选，兼容历史名称；`keyword` 支持项目编码/名称和业务线。 |
| `GET` | `/api/projects/{id}` | 项目管理-项目列表-查看详情 | 查询项目详情 | 路径参数：`id` | 返回项目详情。 |
| `POST` | `/api/projects` | 项目管理-项目列表-新建 | 新建项目 | 请求体：`ProjectSaveRequest` | 必填 `code/name/type/businessLineCode/ownerUserName/status`；`businessLine` 名称入参兼容。 |
| `PUT` | `/api/projects/{id}` | 项目管理-项目列表-编辑 | 更新项目 | 请求体：`ProjectSaveRequest` | 规则同新建。 |
| `DELETE` | `/api/projects/{id}` | 项目管理-项目列表-删除 | 删除项目 | 路径参数：`id` | 已被工作项、迭代、版本、支付绑定或研发评估引用时拒绝删除。 |
| `GET` | `/api/projects/business-lines` | 项目管理-业务线 | 查询业务线列表 | 查询参数：`keyword`、`page`、`pageSize` | 未传分页参数时返回全量；返回 `businessLineCode`、名称、GitLab 组名、说明和启用状态。 |
| `POST` | `/api/projects/business-lines` | 项目管理-业务线-新增 | 新增业务线 | 请求体：`BusinessLineSaveRequest` | `businessLineName` 必填；后端自动生成唯一 `businessLineCode`；可维护 `gitlabGroupName/description/enabled`。 |
| `PUT` | `/api/projects/business-lines/{id}` | 项目管理-业务线-编辑 | 更新业务线 | 请求体：`BusinessLineSaveRequest` | 更新业务线主数据；业务线编码保持不变。 |
| `DELETE` | `/api/projects/business-lines/{id}` | 项目管理-业务线-删除 | 删除业务线 | 路径参数：`id` | 已被项目、成员或涉及系统引用时拒绝删除。 |
| `POST` | `/api/projects/business-lines/{id}/involved-systems/sync-git` | 项目管理-业务线-同步涉及系统 | 从 GitLab 同步业务线涉及系统 | 路径参数：`id` | 读取 GitLab group 及子组可访问仓库，只新增缺失系统，不覆盖手工维护项。 |
| `GET` | `/api/projects/involved-systems` | 项目管理-涉及系统 | 查询研发涉及系统清单 | 查询参数：`systemScope`、`businessLine`、`enabledOnly`、`keyword` | `systemScope` 支持 `BUSINESS_LINE/MIDDLE_PLATFORM`；`businessLine` 优先传业务线编码，兼容名称。 |
| `GET` | `/api/projects/involved-systems/selectable` | 需求管理-查看详情-任务评估-系统标签选择 | 查询某业务线可选涉及系统 | 查询参数：`businessLine` 必填 | `businessLine` 优先传业务线编码；返回当前业务线启用系统和全局启用中台系统。 |
| `POST` | `/api/projects/involved-systems` | 项目管理-涉及系统-新增 | 新增研发涉及系统 | 请求体：`systemScope`、`businessLineCode`、`systemName`、`description`、`enabled`、`sortOrder` | 业务线系统必须传 `businessLineCode`，兼容 `businessLine` 名称；中台系统忽略业务线。 |
| `PUT` | `/api/projects/involved-systems/{id}` | 项目管理-涉及系统-编辑 | 更新研发涉及系统 | 请求体：涉及系统保存请求 | 系统名称已被研发任务使用时不能改名，可通过 `enabled=false` 停用。 |
| `DELETE` | `/api/projects/involved-systems/{id}` | 项目管理-涉及系统-删除 | 删除研发涉及系统 | 路径参数：`id` | 已被研发任务使用时拒绝删除，需改为停用。 |

### 11.3 需求阶段动作接口

| 方法 | 路径 | 系统路径 | 用途 | 请求/参数 | 关键说明 |

| `CONFIRM_RELEASE` | 上线确认 | `待上线` -> `已完成` | 记录实际上线日期。 |
| `CLOSE_REQUIREMENT` | 关闭需求 | 未到 `已完成/终止关闭` 的需求 -> `终止关闭` | 必须填写 `closeReason`，可填写 `occurredAt` 作为关闭日期。 |

| `POST` | `/api/payment/merchants/{merchantId}/secrets/file` | 支付配置-商户账号与密钥-查看详情-秘钥版本-上传文件 | 上传文件新增秘钥版本 | `multipart/form-data`；字段：`secretName`、`secretType`、`fileValueType`、`file`、`activateNow`、`validFrom`、`validTo`、`remark` | `fileValueType` 必须为 `TEXT/BINARY`；后端不按扩展名或 MIME 自动推断。 |
| `GET` | `/api/payment/bindings` | 支付配置-商户账号与密钥-查看详情-项目用途绑定 | 查询业务支付绑定列表 | 查询参数：`projectId`、`businessLine`、`merchantId`、`purposeCode`、`status` | `businessLine` 优先传业务线编码，兼容名称；商户详情绑定区块按 `merchantId` 调用；`projectId` 为空表示业务线通用绑定。 |
| `POST` | `/api/payment/bindings` | 支付配置-商户账号与密钥-编辑-新增绑定 | 新建业务支付绑定 | 请求体：`PaymentProjectBindingSaveRequest` | 从编辑商户弹窗发起时固定传当前商户 `merchantId`；业务线按编码保存并展示主数据名称；支持多用途和关联商户。 |
| `PUT` | `/api/payment/bindings/{id}` | 支付配置-商户账号与密钥-查看详情-项目用途绑定-编辑 | 更新业务支付绑定 | 请求体：`PaymentProjectBindingSaveRequest` | 规则同新增。 |
| `GET` | `/api/payment/projects/{projectId}/bindings/resolve` | 后台/支付绑定解析 | 解析项目用途应使用的生效商户绑定 | 查询参数：`purposeCode` | 优先项目专属绑定，找不到时按项目所属业务线编码回退通用绑定。 |
| `GET` | `/api/payment/purposes` | 支付配置-用途下拉 | 查询系统内置支付用途字典 | 无 | 返回 `BIND_CARD/WITHHOLD/REFUND/TRANSFER/WITHHOLD_SPLIT_SETTLEMENT` 等用途和历史用途映射。 |
