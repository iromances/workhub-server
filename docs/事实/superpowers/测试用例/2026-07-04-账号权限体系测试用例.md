# 账号权限体系测试用例

## 1. 需求信息

- 需求名称：WorkHub 账号权限体系
- 研发方案文件：`docs/superpowers/specs/2026-07-04-account-permission-system-design.md`
- 测试用例文件路径：`docs/事实/superpowers/测试用例/2026-07-04-账号权限体系测试用例.md`
- 涉及系统：`workhub-server`、`../workhub-web`
- 涉及模块：认证、系统管理、账号管理、角色管理、权限校验、审计日志
- 编写时间：2026-07-04
- 编写人或代理：Codex

## 2. 测试范围

- 本次需求核心场景：
  - 数据库账号登录，替代硬编码管理员。
  - 角色、权限和用户授权配置。
  - 前端菜单、路由和按钮按权限控制。
  - 后端接口按权限点强校验。
  - 后端一次性初始密码和修改本人密码。
  - 登录日志和关键操作审计。
- 本次需求边界场景：
  - 用户拥有多个角色。
  - 角色停用。
  - 内置角色禁止删除。
  - 最后一个超级管理员保护。
- 本次需求异常场景：
  - 密码错误、账号停用、账号锁定。
  - 无 token、过期 token、无权限接口访问。
  - 权限配置为空或权限编码不存在。
  - 审计字段包含敏感字段时必须脱敏。
- 不纳入自动化测试的范围及原因：
  - 真实生产账号和真实生产权限配置不纳入自动化，避免污染生产授权。
  - 企业微信 SSO、LDAP、OAuth2 不属于首版范围。
  - 字段级权限和授权审批流不属于首版范围。

## 3. 测试环境

- 后端环境：本地或测试环境 `workhub-server`。
- 前端环境：本地或测试环境 `../workhub-web`。
- 数据库环境：测试 MySQL，执行账号权限体系 Flyway 脚本。
- 外部依赖：不涉及外部身份源；MCP 只读资源可使用测试配置。
- 测试数据准备方式：
  - 初始化 `admin` 超级管理员。
  - 准备 `normal_user`、`ops_user`、`pm_user` 等测试账号。
  - 准备不同权限组合的角色和权限点。

## 6. 未覆盖风险

- 未覆盖场景：真实生产权限初始化、生产账号密码策略和生产角色授权准确性。
- 未覆盖原因：生产权限不能在自动化测试中随意创建、删除或授权。
- 可能影响：若生产授权数据配置错误，可能导致用户看不到菜单、看不到按钮或误获高权限。
- 后续补充计划：上线前在测试环境完成权限矩阵验收；生产发布后先由超级管理员核对内置角色和关键账号授权，再开放普通用户使用。
