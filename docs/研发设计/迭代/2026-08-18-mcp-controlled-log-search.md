# MCP 受控日志检索设计

## 1. 背景与目标

生产问题排查需要在已配置 SERVER 资源的普通日志和 ZIP 历史日志中按业务标识定位记录。现有 `read_service_logs` 只能读取日志尾部，无法有效检索较早时间的记录。

本次新增 `search_service_logs`，支持对单个白名单日志文件执行固定字符串检索，同时继续保持 MCP 服务器通道只读、命令闭集和输出有界。

## 2. 范围

- 普通文本日志使用 `grep -F` 检索。
- `.zip` 历史日志使用 `zipgrep` 检索，不解压写入远端文件系统；由于 GNU `zipgrep` 内部固定调用 `egrep`，ZIP 关键词必须不含正则元字符，从输入约束上保证字面量语义。
- 每次调用只允许一个明确的绝对文件路径，不支持目录、通配符、正则表达式或多文件批量扫描。
- `maxMatches` 默认取 SERVER profile 的 `maxOutputLines`，且不能超过该值。
- 沿用日志目录白名单、SSH/堡垒机、超时、输出截断与审计机制。

## 3. 安全设计

- 命令由 `CommandPolicyGuard` 以参数列表构造，不经过 shell。
- 日志路径规范化后必须位于 SERVER 资源配置的允许目录中，并继续拒绝目录越界和特殊字符。
- 关键词最大 256 字符，拒绝控制字符；ZIP 检索额外拒绝以 `-` 开头或包含正则元字符的关键词，避免 `zipgrep` 脚本将其解释为选项或表达式；对账单号、追踪码等普通业务标识保持字面量匹配。
- MCP 审计保留工具、目标、文件、退出码和耗时，但将检索关键词替换为 `[REDACTED]`。
- 不提供解压、下载、写文件或任意 SSH 命令能力。

## 4. 接口

工具：`search_service_logs`

必填参数：`targetKey`、`profileKey`、`logPath`、`keyword`。

可选参数：`maxMatches`。

返回现有诊断命令统一结构：目标、profile、命令 key、退出码和受限输出。退出码 `1` 表示没有匹配内容，不视为远程执行异常。

## 5. 影响范围

- `workhub-mcp-server` 命令策略、服务器诊断服务和工具注册表。
- MCP 能力与安全边界、架构说明、业务运维分析方法和控制器接口说明。
- 不涉及数据库结构、页面、业务系统代码或生产服务器写操作。

## 6. 验证方案

- 单元测试覆盖普通日志、ZIP 日志、命中数上限、路径越界、控制字符和审计脱敏。
- 执行 `workhub-mcp-server` 模块测试与编译。
- 服务更新后，分别对嘉泰设备租赁 SAPS 及四个 gateway 日志目录调用工具核对目标对账单。
