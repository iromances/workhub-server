# 系统预警“删除&过滤”测试用例

## 1. 自动化覆盖计划

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| SA-CLEAN-001 | 消息关键词为空或超过 200 字 | 拒绝创建任务，不执行删除和规则变更 |
| SA-CLEAN-002 | 提交包含完整查询条件 | 任务持久化业务线、环境、服务、级别、分类和时间快照 |
| SA-CLEAN-003 | 提交后执行较长任务 | 接口快速返回任务 ID，删除在后台执行 |
| SA-CLEAN-004 | 匹配数量超过单批大小 | 每批最多 500 条，持续处理到固定最大事件 ID |
| SA-CLEAN-005 | 已有相同启用忽略规则 | 复用规则，不重复创建规则或关键词 |
| SA-CLEAN-006 | 没有相同规则 | 新建启用的 `IGNORE/MESSAGE/ANY` 规则 |
| SA-CLEAN-007 | 事件存在关联通知 | 先按业务线、环境、源事件 ID 精确删除通知，再删除事件 |
| SA-CLEAN-008 | 相同源事件 ID 位于其他环境 | 不删除其他环境通知 |
| SA-CLEAN-009 | 某批执行失败 | 任务标记失败，保留累计数量、游标和失败原因 |
| SA-CLEAN-010 | 线程池拒绝任务 | 任务标记失败，不长期停留在 PENDING |
| SA-CLEAN-011 | 同一任务被重复执行 | 只有一次状态抢占成功，不重复执行批次 |
| SA-CLEAN-012 | 查询自己的任务状态 | 返回进度、规则 ID、删除数量和时间字段 |
| SA-CLEAN-013 | 无权查询他人任务 | 普通用户被拒绝，管理权限可以查询 |
| SA-CLEAN-014 | 前端关键词为空 | “删除&过滤”禁用，不能提交 |
| SA-CLEAN-015 | 前端确认弹框 | 展示预估数量、筛选范围、全局规则和 ELK 不删除提示 |
| SA-CLEAN-016 | 前端任务成功 | 停止轮询、提示实际数量并刷新当前查询 |
| SA-CLEAN-017 | 前端任务失败 | 停止轮询、显示失败原因和已完成数量、恢复按钮 |
| SA-CLEAN-018 | 取消确认 | 不创建任务 |
| SA-CLEAN-019 | 已有任务运行时再次提交 | 按钮保持可用，创建独立任务并分别轮询 |
| SA-CLEAN-020 | 两个任务删除范围重叠 | 按实际受影响行数累计，均可结束且不重复创建规则 |

## 2. 计划执行命令

```bash
mvn -q -pl workhub-service,workhub-controller -am -Dtest=SystemAlertCleanupTaskServiceTest,SystemAlertCleanupTaskExecutorTest,SystemAlertControllerTest -Dsurefire.failIfNoSpecifiedTests=false test
mvn -q -DskipTests compile
./node_modules/.bin/vue-tsc --noEmit
npm run build
git diff --check
```

前端命令在同级 `workhub-web` 仓库执行。不连接生产数据库，不启动或重启应用。

## 3. 手工验证计划

- 输入关键词并查询，确认“删除&过滤”与“删除”同级且不依赖列表勾选。
- 核对确认弹框的历史删除范围和全局过滤提示。
- 提交小范围任务，观察处理中、成功提示和列表刷新。
- 模拟后端失败，确认错误提示、已完成数量和按钮恢复。
- 在过滤规则页核对新规则；核对 ELK 原始日志未被删除。
