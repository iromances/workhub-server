# 系统预警业务线关注范围测试用例

## 1. 自动化覆盖计划

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| SA-SCOPE-001 | 新增 `ALL` 且服务列表为空 | 保存成功 |
| SA-SCOPE-002 | 新增 `SELECTED` 且没有启用服务 | 校验失败 |
| SA-SCOPE-003 | 相同业务线和环境重复新增 | 返回重复配置错误 |
| SA-SCOPE-004 | `ALL` 生成 ELK 查询 | 不包含服务过滤，包含环境、级别和时间条件 |
| SA-SCOPE-005 | `SELECTED` 生成 ELK 查询 | 包含服务名 `terms` 过滤 |
| SA-SCOPE-006 | 整条业务线返回多个服务日志 | 按实际服务名入库并分别汇总通知 |
| SA-SCOPE-007 | 重复读取相同 ELK 事件 | 事件只新增一次 |
| SA-SCOPE-008 | 修改模式、索引或服务 | 清除范围同步游标 |
| SA-SCOPE-009 | 旧配置数据迁移 | 范围为 `SELECTED`，子系统与索引完整保留 |
| SA-SCOPE-010 | 页面切换关注模式 | 动态显示服务编辑区且校验一致 |

## 2. 计划执行命令

```bash
mvn -q -pl workhub-service,workhub-controller -am test
mvn -q -DskipTests compile
npm run build
```

前端构建命令在 `workhub-web` 执行。Flyway 脚本同时通过 SQL 审查和后端构建资源检查验证；不连接未经用户明确指定的持久环境数据库。

## 3. 手工验证计划

- 进入“运维监测 -> 系统预警 -> 关注业务线”。
- 新增 `ALL` 范围，确认不需要添加子系统。
- 新增或修改为 `SELECTED`，确认至少一个启用子系统。
- 验证列表、编辑、删除确认、加载失败和保存失败提示。
- 在联调 ELK 环境验证全部服务、指定服务、过滤规则、慢 SQL 和通知行为。
