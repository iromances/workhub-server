# 嘉泰消费分期资方服务费场景与实际还款台账口径

## 1. 文档目的

本文梳理嘉泰消费分期生产环境现行项目中，资方服务费在以下业务场景中的处理方式，并明确其对“实际还款台账”的影响：

1. 放款及头收；
2. 每期正常还款；
3. 提前结清；
4. 退费及七天无理由退费；
5. 回购。

本文重点回答三个问题：

- 客户是否实际支付资方服务费；
- 金额是否进入账单 `total_amount`；
- 是否生成资方服务费对账单计费数据。

本文只分析嘉泰资方侧，不分析消费分期业务侧。

## 3. 核心字段与概念

### 3.1 资方服务费科目

资方服务费的账单科目为：

```text
P0003：资方服务费
```

### 3.2 账单金额字段

| 字段 | 含义 |
| --- | --- |
| `bill_fee_detail.total_amount` | 当前账单实际应付金额，参与账单合计 |
| `bill_fee_detail.paid_amount` | 当前账单科目的已付或本次结算金额 |
| `bill_fee_detail.original_amount` | 原始资方服务费，主要用于记录头收或原始计费金额 |
| `bill_fee_detail.cost_amount` | 已发生或应轧差的成本金额，鹿优选等项目用于负数冲减 |

必须注意：`original_amount` 不等于客户本次实际支付金额。

### 3.3 资方服务费对账单计费数据

本文所称“资方服务费对账单计费数据”，特指：

```text
statement_charge_resource.charge_type = 8000
```

退费、七天无理由、线下还款和回购对账单虽然也可能包含 `P0003`，但其 `charge_type` 分别属于退费、线下或回购类型，不能与 `8000`混为一谈。

### 3.4 结算方式

| 值 | 含义 |
| ---: | --- |
| 100 | 正常还款 |
| 201 | 提前结清 |
| 400 | 退费 |
| 401 | 七天无理由退费 |
| 500 | 代偿 |
| 600 | 回购 |

## 4. 当前项目和产品口径

### 4.1 即科医美

| 项目/产品 | 付息模式 | 处理特征 |
| --- | --- | --- |
| `JT_XXT-PRJ-JK-E` / `JT_PRD-JK-E001` | 商户全额贴息 | 放款环节贴息头收；退费可生成负数P0003 |
| `JT_XXT-PRJ-JK-E` / `JT_PRD-JK-E002` | 客户付息 | 普通付息模板，不属于本文重点贴息产品 |

`JT_PRD-JK-E001`被明确加入 `discount_interest`贴息产品配置，并使用 `discountSettleBillTemplateService`。

### 4.2 鹿优选/沃橙

| 项目/产品 | 付息模式 | 处理特征 |
| --- | --- | --- |
| `JT_XXT-PRJ-LYX-A` / `JT_PRD-LYX-A001` | 当前校验策略为客户付息 | 资方服务费项目级头收，使用T5计费模板 |
| `JT_XXT-PRJ-LYX-A` / `JT_PRD-LYX-A002` | 当前校验策略为客户付息 | 资方服务费项目级头收，使用T5计费模板 |

虽然订单模式为客户付息，嘉泰同步还款计划时会把每期 `repayServiceFee`调整为0，并把原始服务费放入 `originalServiceFee`。因此客户每期不再支付P0003，资方服务费通过放款建账时的头收计费处理。

### 4.3 自牧云创/量化派

| 项目/产品 | 付息模式 | 处理特征 |
| --- | --- | --- |
| `JT_XXT-PRJ-ZMY-A` / `JT_XXT-PRJ-ZMY-A001` | 当前校验策略为客户付息 | 日计费，主要为线下还款 |
| `JT_XXT-PRJ-ZMY-A` / `JT_XXT-PRJ-ZMY-A002` | 当前校验策略为客户付息 | 日计费，线上P0003生成8000计费数据 |

量化派资方服务费按照实际资金占用天数计算，不属于放款头收项目。

## 6. 分场景处理说明

### 6.1 放款时是否轧差头收

#### 6.1.1 即科E001贴息

结论：存在放款头收/轧差，但不生成8000资方服务费计费数据。

处理方式：

- 商户贴息金额参与放款金额拆分；
- 向商户实际支付金额按“本金减贴息金额”计算；
- P0003的原始金额保留在 `original_amount`；
- P0003不是客户后续每期应支付金额；
- 该环节不产生 `charge_type=8000`数据。

即科的“头收”是放款资金拆分口径，不能在实际还款台账中当作客户期还。

#### 6.1.2 鹿优选/沃橙

结论：存在放款建账时的资方服务费头收计费。

处理方式：

- 嘉泰同步还款计划时，将每期 `repayServiceFee`改为0；
- 原始服务费保存到 `originalServiceFee`；
- 产品配置 `calcServiceFee=true`；
- 账单生成时按整单 `loan_order.service_fee`生成一条正数8000计费数据；
- 后续正常期还不再重复生成资方服务费计费数据。

这里的“头收”是放款成功后建账时一次性计费。当前放款金额校验仍按全额本金向商户支付，因此不能简单理解为从放款本金支付指令中直接扣除P0003。

#### 6.1.3 量化派

结论：不头收。

量化派没有放款建账时生成整单P0003的配置，服务费在正常还款、提前结清、退费或回购时按实际占用天数确认。

### 6.2 每期正常还款

#### 6.2.1 即科E001贴息

- 客户不支付P0003；
- P0003的 `total_amount`和实际支付均为0；
- `original_amount`仅记录放款头收原始金额；
- 不生成8000计费数据。

#### 6.2.2 鹿优选/沃橙

- 客户每期不支付P0003；
- 正常还款不重复生成8000计费数据；
- 放款建账时已经生成过整单正数8000数据。

#### 6.2.3 量化派

- 客户支付按还款计划或实际天数计算的P0003；
- A001线下还款：P0001和P0003进入线下还款对账单，不生成8000；
- A002线上还款：P0003生成8000计费数据；
- A002线下还款：P0003进入线下还款对账单，不生成8000。

### 6.3 提前结清

#### 6.3.1 即科E001贴息

- 客户不支付P0003；
- 未起息账单将P0003的 `total_amount`、`paid_amount`和`unpaid_amount`置为0；
- `original_amount`仍可能保留正数；
- 不生成负数P0003；
- 不生成8000计费数据。

因此，即科提前结清账单中保留的 `original_amount`不能作为本次实际还款金额。

#### 6.3.2 鹿优选/沃橙

- 已起息部分不重复收取P0003；
- 对未起息部分生成 `-cost_amount` 的负数P0003计费数据；
- 负数数据的 `charge_type=8000`；
- 负数用于冲减放款时已经头收、但尚未发生的资方服务费；
- 负数不写入 `bill_fee_detail.total_amount`，因此不影响提前结清还款账单的 `total_amount`。

鹿优选提前结清与正常还款的客户支付口径相同，客户都不支付P0003；但资方服务费对账单口径不同，提前结清会产生未起息费用的负数轧差。

#### 6.3.3 量化派

提前结清资方服务费计算公式：

```text
P0003 = 剩余未还本金 × 资方年服务费率 ÷ 360 × 实际占用天数
```

其中：

- 第一期不计算起息当天；
- 后续期计算起息当天；
- 实际天数小于0时按0处理；
- 重算后的正数P0003进入提前结清账单 `total_amount`；
- 未起息时实际天数为0，P0003为0，不生成负数；
- A002线上提前结清会生成8000计费数据；
- A001线下进入线下还款对账单。

### 6.4 退费和七天无理由退费

#### 6.4.1 即科E001贴息

普通退费：

- 未起息账单：`P0003 = -original_amount`；
- 已起息账单：不退资方服务费，P0003不生成负数。

七天无理由退费：

- 不区分是否已经起息；
- P0003按 `-original_amount`全额冲回。

即科负数P0003的特点：

- 负数写入 `bill_fee_detail.total_amount`和`paid_amount`；
- 负数参与退费账单 `total_amount`汇总；
- 形成的是退费或七天无理由计费数据，`charge_type`分别为4000、4001；
- 不形成8000资方服务费计费数据。

计算关系可以理解为：

```text
退费账单total = 本金 + 负数资方服务费 + 其他负数退回费用
```

#### 6.4.2 鹿优选/沃橙

普通退费：

- 已起息费用不冲回；
- 未起息部分按负数P0003冲减。

七天无理由退费：

- 头收的资方服务费全部按负数冲回。

鹿优选负数P0003的特点：

- 负数写入 `statement_charge_resource`；
- `charge_type=8000`；
- 负数影响资方服务费对账单合计；
- 负数不进入退费账单 `bill_fee_detail.total_amount`；
- 实际还款三表查询不能直接获取该负数。

#### 6.4.3 量化派

普通退费：

- 已起息时按实际占用天数重算正数P0003；
- 正数P0003进入退费账单 `total_amount`。

未起息退费或七天无理由退费：

- P0003清零；
- 不生成负数P0003；
- 不生成8000资方服务费计费数据。

量化派退费场景中如存在P0003计费数据，其类型属于退费/七天无理由，不属于8000。

### 6.5 回购

#### 6.5.1 即科E001贴息

- 当前V2回购逻辑明确跳过贴息产品P0003；
- 回购只处理本金；
- 不重新生成资方服务费；
- 不冲回历史头收资方服务费；
- 不生成负数P0003；
- 不生成8000计费数据。

#### 6.5.2 鹿优选/沃橙

- 当期只生成本金回购数据；
- 后续未起息账期的P0003按 `-cost_amount`生成负数；
- 负数P0003的 `charge_type=8000`；
- 负数影响资方服务费对账单，不进入回购账单 `total_amount`；
- 未来账期账单中的非本金科目被清零。

#### 6.5.3 量化派

- 按回购日实际占用天数重算正数P0003；
- 正数P0003和本金一起进入回购金额；
- P0003属于回购对账单数据，不属于8000；
- 后续未发生费用清零。

## 7. 负数P0003的最终结论

在本文三个项目范围内，需要区分两个数据层面。

### 7.1 实际还款三表数据源

实际还款台账当前使用：

- `repayment_plan`；
- `bill_fee_detail`；
- `loan_order`。

在这三个表的当前有效账单科目中，主要只有即科E001贴息退费和七天无理由退费会出现负数P0003。

### 7.2 资方服务费计费数据

鹿优选提前结清、退费、七天无理由退费和回购也会产生负数P0003，但这些负数存在于：

```text
statement_charge_resource
charge_type = 8000
```

它们不属于客户实际还款金额，也不在当前三表实际还款查询范围内。

量化派在本文场景中不会生成负数P0003。

## 8. 当前实际还款台账的既有处理

### 8.1 当前调用链

```text
GET /jiatai-amp-saps/manage/report/paytable/page
  -> PayTableReportController.pageIndex()
  -> RepaymentReportService.page()
  -> RepaymentPlanPaySubjectDetailMapper.pageQueryThreeTable()
```

下载同样使用 `pageQueryThreeTable`，然后调用相同的字典和金额后处理逻辑。

### 8.2 负数按0展示

当前 `RepaymentReportService.dictAndEnumConvert`对P0003执行以下处理：

```text
1. 退费/七天无理由场景下，如果payAmount恰好为0.00，先用originalServiceFee替换；
2. 如果最终payAmount小于0，则强制改成0.00。
```

因此：

- 即科数据库中可能存在负数P0003；
- 页面和Excel下载均把负数展示为0；
- 现有台账不会展示即科真实的资方服务费冲回金额。

这不是旧SQL本身完成的处理，而是查询结果返回前的Java Service后处理。当前生产 `master`仍保留该逻辑。

### 8.3 当前三表查询的贴息取值风险

`pageQueryThreeTable`当前存在如下逻辑：

```sql
WHEN interest_subsidy_mode = 1
 AND bill_status NOT IN (400, 401)
 AND subject_no = 'P0003'
THEN original_amount
```

这会使即科贴息订单在正常还款、提前结清、回购等非退费场景中，把头收的 `original_amount`展示成当前事件的实际还款。

但真实业务是：

- 正常还款：客户不支付该P0003；
- 提前结清：未起息P0003实际为0，不生成负数；
- 回购：当前V2明确跳过P0003。

因此，如果台账定义为“客户实际支付流水”，直接使用 `original_amount`会把历史头收金额误算为本次实际还款。

## 9. 实际还款台账建议口径

建议把不同性质的金额拆开，不使用一个“实还金额”字段同时承载客户付款、历史头收和资方对账单轧差。

### 9.1 客户实际还款金额

优先使用本次结算生成的支付科目明细：

```text
repayment_plan_pay_subject_detail.paid_amount
```

如果继续使用最终账单三表查询，则至少应确保：

- 即科正常还款P0003为0；
- 即科提前结清P0003为0；
- 即科回购P0003为0；
- 即科退费负数是否展示，需要由产品口径明确决定。

### 9.2 原始/头收资方服务费

单独展示：

```text
bill_fee_detail.original_amount
```

建议字段名称为“原始资方服务费”或“放款头收资方服务费”，不得计入本次客户实际还款合计。

### 9.3 资方服务费冲回金额

建议单独增加“资方服务费冲回金额”字段：

- 即科：来源于负数 `bill_fee_detail.paid_amount`或`total_amount`的绝对值；
- 鹿优选：来源于 `statement_charge_resource`中 `charge_type=8000`且 `fee_amount<0`的数据；
- 量化派：通常为0。

如果台账只定义为客户实际付款，可以继续把负数实还展示为0，但不能完全丢弃冲回信息，至少应在独立字段或独立对账单台账中保留。

### 9.4 建议的数据分层

| 金额类型 | 推荐来源 | 是否计入客户实还合计 |
| --- | --- | ---: |
| 客户实际支付P0003 | 支付科目明细 `paid_amount` | 是 |
| 放款头收P0003 | `original_amount`或放款计费数据 | 否 |
| 即科退费P0003冲回 | 负数账单科目金额 | 否，建议单独展示 |
| 鹿优选头收费用冲回 | 负数8000计费数据 | 否，属于资方对账单调整 |
| 量化派日计费P0003 | 事件重算后的正数P0003 | 是 |

## 10. 推荐验收用例

至少覆盖以下场景：

1. 即科E001贴息正常还款：客户实还P0003为0，原始服务费单独展示；
2. 即科E001未起息提前结清：P0003不出现负数，客户实还P0003为0；
3. 即科E001已起息提前结清：客户实还P0003仍为0；
4. 即科E001未起息普通退费：数据库P0003为负数；
5. 即科E001已起息普通退费：P0003不冲回；
6. 即科E001七天无理由退费：P0003按原始金额全额取负；
7. 即科E001回购：回购单只包含本金，不包含P0003；
8. 鹿优选放款建账：产生正数8000计费数据，客户账单P0003为0；
9. 鹿优选正常还款：不重复生成P0003计费数据；
10. 鹿优选未起息提前结清：产生负数8000，但账单P0003 total为0；
11. 鹿优选七天无理由：全部未发生头收费用产生负数8000；
12. 鹿优选回购：未来账期产生负数8000，回购单仅按项目规则承载本金；
13. 量化派A001正常线下还款：P0003进入线下还款单；
14. 量化派A002正常线上还款：P0003生成正数8000；
15. 量化派提前结清：P0003按实际天数重算，未起息为0；
16. 量化派七天无理由：P0003清零且不产生负数；
17. 量化派回购：正数P0003进入回购金额，不生成8000；
18. 页面与Excel下载对负数P0003的展示结果一致。

## 12. 最终结论

1. 即科E001是当前明确配置的贴息产品，P0003在放款时头收；正常还款、提前结清和回购时客户均不再支付P0003。
2. 即科未起息普通退费和七天无理由会在账单科目中生成负数P0003，并计入退费账单 `total_amount`。
3. 鹿优选/沃橙的P0003在放款建账时一次性形成正数8000；提前结清、退费、七天无理由和回购时，未发生部分通过负数8000冲减，不进入客户还款账单合计。
4. 量化派不头收，P0003按实际占用天数在还款或结算事件中确认；未起息和七天无理由时清零，不生成负数。
5. 在实际还款当前三表数据源中，负数P0003主要只有即科退费场景；鹿优选的负数位于资方服务费计费数据中。
6. 现有实际还款台账页面和下载会把负数P0003强制展示为0，同时非退费贴息场景又可能把 `original_amount`当作本次实还，需在后续需求中明确“客户实还、原始头收、资方冲回”三个独立口径。
